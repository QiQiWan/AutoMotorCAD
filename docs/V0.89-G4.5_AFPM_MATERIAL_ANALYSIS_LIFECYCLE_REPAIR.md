# V0.89-G4.5 AFPM / Material / Analysis / Lifecycle Repair

## Scope and evidence

This iteration addresses the supplied screenshots plus the packaged system and task logs. The logs show native AFPM validation taking about 14 seconds before reporting intersections between `Stator` and `StatorAir`, slot regions and magnet regions. They also show analysis-definition requests ranging from seconds to tens of seconds, and material-library writes occurring where a design-material assignment was expected.

## Root causes and repairs

1. **Project shell geometry.** Three redundant context/guidance rows competed with the four-stage navigation and inherited minimum-height/overflow rules. The default desktop shell is now one 56 px row containing project identity and Design / Validate / Results / Decide. Context, focus and journey explanations remain in the DOM for diagnostics but are hidden in the normal workflow.
2. **AFPM projection.** The previous Studio illustration overlaid stator teeth/windings and rotor magnets on one opaque plane. The replacement renders separate stator and rotor axial faces. It is a design-intent projection; native Motor-CAD geometry remains authoritative.
3. **Material assignment.** Opening the library picker called the generic close routine, which erased the picker callback before a material was chosen. The picker now preserves its design-draft transaction and returns the selected material to the current component. Material views rerender on the global language-change event.
4. **Default AFPM native check.** The guided starter serialized every displayed default as an explicit override. Motor-CAD therefore rebuilt winding/geometry even when the user changed nothing. Browser and server now drop values equal to template defaults; the native check receives only true design changes. An invalid registered native template still fails closed.
5. **Analysis index latency.** Bootstrap previously expanded the project graph, materialized revision history and decoded large analysis snapshots before separately querying the latest motor revisions. The hot path now uses a project summary, bounded latest-revision queries and deferred snapshots. It reports index, motor-window and total bootstrap timing.
6. **Motor-configuration lifecycle.** Unreferenced configurations can now be deleted. Any revision referenced by analysis, task, case or result lineage is rejected with explicit blockers, preserving engineering traceability.
7. **Stale frontend assets.** The product version remains `0.89.9`; HTML, JS and CSS responses are explicitly non-cacheable so upgrades cannot mix an old navigation/material client with the new backend.

## Validation

- G4.5 plus G4.1–G4.4 targeted regressions and inherited workflow compatibility: 71/71 passed.
- All production JavaScript files passed `node --check`.
- The Python package passed `compileall`.
- Licensed Windows Motor-CAD 2026R1 live qualification remains pending. The repair removes unintended default rewrites; it does not bypass native geometry validation or claim that an externally modified template is valid.
