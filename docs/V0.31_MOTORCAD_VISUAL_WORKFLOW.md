# MotorCAD Studio V0.31：Motor-CAD 设计理念分析与优化方案

## 1. 结论摘要

本轮审计得到的核心判断是：当前系统已经拥有较完整的工程对象和真实求解证据，主要瓶颈集中在信息架构、参数上下文和结果表达。

V0.30 具备 Design Revision、Scenario、Run Configuration、Task、Case、Worker、原生几何检查、绕组证据和 FEA Evidence。上述能力分布在默认设计页、修改版本弹窗、运行摘要、监控和结果页中，工程师需要先理解系统内部对象，才能找到某项具体能力。Motor-CAD 的优势集中在“当前视图就是当前任务上下文”：径向界面只处理径向尺寸，绕组界面只处理相槽与导体，计算界面只处理求解条件，结果界面同时提供整体关系和局部细节。

因此，本轮优化采用四条主线：

1. 视图与参数一一绑定；
2. 绕组成为与几何同级的设计对象；
3. 工作流持续显示工程状态；
4. 结果先呈现整体关系，再进入数值细节，并始终显示数据权威等级。

## 2. 对当前系统的审计

| 领域 | V0.30 已有能力 | 主要断点 | V0.31 处理 |
|---|---|---|---|
| 设计对象 | Design + 不可变 Revision，模板默认值与显式覆盖 | 默认页只有一个示意图；高级能力藏在“修改版本” | 七个一等设计视图直接进入设计页 |
| 参数 | Registry、候选 Motor-CAD 变量、依赖图、可行基线 | 平铺参数缺少空间维度；看图和改值来回切换 | 服务端返回 view → parameter_ids 契约 |
| 绕组 | 三项可编辑参数、整数门禁、原生 winding pattern artifact | 形式、相槽、方向、槽内定义没有连续可视上下文 | 绕组排布与槽内定义双视图 |
| 工作流 | 四步工程流程与五种 UI 状态 | 顶部流程、项目主导航和二级导航重复；状态只在局部出现 | 单一持续状态条，显示完成/当前/阻塞/运行 |
| 结果 | 标量、曲线、maps/fields/vectors、FEA Evidence | FEA 控件和证据分散；热结果缺少整体路径 | 原生 FEA 控制台 + 热拓扑总览 |
| 权威性 | Task-time Execution Lease 和原生 Case Evidence | Studio 示意图与原生结果的视觉边界不够稳定 | 每个视图固定显示用途、来源和权威说明 |

## 3. 从 Motor-CAD 截图提取的关键设计原则

### 3.1 选项卡代表工程视角

截图中的 Radial、Axial、3D、Winding Pattern、Definition、Materials、Calculation、Temperatures、Output Data 等选项卡承担了三层职责：

- 限定当前问题空间；
- 只暴露该空间相关参数；
- 参数改变后立即反馈到同一画布。

可借鉴的核心是领域分层。传统 Windows 工具栏样式、密集表格和固定像素布局不适合作为 Web 端目标；Web 端应保留清晰的任务边界，并提高可读性、响应式能力和证据提示。

V0.31 将设计页组织为：

| 视图 | 主要参数 | 画布反馈 | 进入下一步的条件 |
|---|---|---|---|
| 径向截面 | 槽极、定子内外径、气隙、齿宽、槽深、槽口、磁体 | 定转子、槽、绕组占用、磁体、尺寸标注 | 几何静态检查通过 |
| 轴向截面 | 叠长、内外径、气隙、磁体厚度 | 机壳、定子叠片、转子、磁体、轴、轴承、端绕组关系 | 装配关系完整；原生几何待 Case 验证 |
| 绕组排布 | 槽极、匝数、并联支路、槽满率 | 相别、进出方向、线圈连接和整数关系 | 槽/相/支路约束通过 |
| 槽内定义 | 槽口、齿宽、槽深、匝数、槽满率 | 槽衬、分隔、导体占用和槽楔关系 | 已结构化字段通过；原生专有字段有证据 |
| 材料 | Revision 材料覆盖、冷却介质 | 组件—材料—来源—状态表 | 材料映射在 Revision 中冻结 |
| 原生证据 | 模型检查、绕组、FEA artifact | L0–L4 权威阶梯和 artifact 列表 | 与当前 Revision / Case 指纹一致 |
| 版本对比 | 当前值、上一可行值、模板默认值 | 变化量和来源 | 变化可解释且可追溯 |

### 3.2 参数编辑采用上下文收敛

服务端新增 `design_views`，浏览器无需根据参数命名猜测视图归属。每个视图只接收当前模板真实存在的参数；缺失字段不会以空表单冒充支持。

```json
{
  "id": "winding",
  "label": "绕组排布",
  "parameter_ids": [
    "slot_count",
    "pole_count",
    "turns_per_coil",
    "parallel_paths",
    "slot_fill_factor"
  ],
  "available": true
}
```

画布选中参数、右侧参数列表选中状态和编辑弹窗中的字段高亮共享同一个 parameter id。保存继续创建新的不可变 Revision，保留现有追溯模型。

## 4. 绕组优化方案

### 4.1 当前缺口

此前结构化可编辑字段只有：

- `turns_per_coil`；
- `parallel_paths`；
- `slot_fill_factor`。

相数来自模板 MTT / profile，整数门禁可计算 `slots_per_phase_path`，原生 Case 能导出 `winding_pattern.txt`。这些事实已经足以建立可靠的第一阶段绕组工作区，但还不足以开放线径、铜径、并绕根数、槽衬、分隔和真实绕组因数编辑。

### 4.2 V0.31 结构

`winding_design` 同时返回结构化事实和证据边界：

| 类型 | 字段 | 当前用途 | 权威来源 |
|---|---|---|---|
| 可编辑 | 匝数、并联支路、槽满率 | Revision 参数与即时预检查 | Studio Registry + Revision |
| 模板元数据 | 相数、Motor-CAD winding code、definition code | 相槽关系与门禁 | MTT / template profile |
| 推导 | 槽/相/支路 | 整数可行性 | Studio 静态检查 |
| 视觉估计 | 线圈节距 | 帮助理解连接关系 | 当前槽极关系；标记 `visual_only` |
| 待原生回读 | 线径、铜径、并绕根数、槽衬、分隔、导体间距、绕组因数 | 暂不开放编辑 | 未来 Motor-CAD Winding Definition / Output |

槽内圆点数量只随槽满率改变，用来表达占用密度；界面明确说明圆点不代表真实线径和导体根数。

### 4.3 后续原生映射

V0.32 应按以下顺序扩展：

1. 在 Worker Execution Lease 内读取 Winding Definition 参数和运行时回读值；
2. 在参数注册表中为每个字段定义 Motor-CAD candidate、单位、范围和版本；
3. 将运行时回读写入 `model_validation.json` 和 Case artifact；
4. 只有读写回环、单位换算和保存后回读均通过时，才将字段由 `native_only` 提升为可编辑；
5. 使用原生 winding pattern 生成 coil go/return slot 表、相序和线圈组；Studio 的示意路径继续保留为解释层。

## 5. 工作流优化方案

### 5.1 状态模型

工作流保留四个用户阶段：

1. 设计电机；
2. 设置分析；
3. 计算模型；
4. 分析结果。

每个阶段统一使用五种状态：

| 状态 | 视觉 | 用户含义 | 主操作 |
|---|---|---|---|
| done | 绿色勾选 | 当前步骤证据已冻结 | 可返回查看 |
| current | 蓝色实心 | 当前最合理的工作位置 | 执行本阶段动作 |
| pending | 灰色轮廓 | 上游尚未完成 | 查看依赖 |
| blocked | 红色 | 存在明确阻断项 | 定位字段并修复 |
| running | 蓝色脉冲 | Worker / Motor-CAD 正在执行 | 查看进度和证据 |

V0.31 在工程模式隐藏重复的项目主导航和二级导航，将“项目概览”“数据资产”下沉为辅助入口。引导、专家和开发者模式继续保留各自的信息密度。

### 5.2 状态来源

状态条复用 `/api/projects/{project_id}/ui-guidance` 的 READY、NEEDS_CHECK、BLOCKED、RUNNING、COMPLETED，不建立第二套状态机。页面路由只决定 active，工程证据决定 current/done/blocked/running，避免“导航高亮”和“项目真实进度”互相覆盖。

### 5.3 建议的下一步增强

- 每个阶段显示最近一次关键证据的时间、指纹和来源；
- 阻塞阶段直接显示最多三个根因，并提供跳转到字段/工况/运行环境；
- 运行中显示 Case 数、队列、资源租约和预计完成范围；
- 完成后将主操作切换为“分析最新结果”，并保留“基于此版本继续迭代”。

## 6. 结果拓扑与有限元云图

### 6.1 整体拓扑

Motor-CAD 热网络图的高价值在于把节点温度、损耗源和传热路径放在同一张可解释图中。V0.31 的热结果先显示整体热路径，再显示详细温度和损耗结果。

系统定义两种严格区分的来源：

- Case 含 `thermal_network` / `thermal_circuit` 结构表：显示原生节点、连接和边值；
- 只有标量温度与损耗：显示“工程热路径摘要”，连接使用虚线，并说明该图不等于完整 Motor-CAD 热网络。

V0.33 应增加原生热网络导出适配器，至少保留 node id、label、component、temperature、capacitance、edge source/target、resistance、power flow、unit、solver step 和 artifact hash。

### 6.2 FEA 云图

V0.31 只在 Case 结果含原生 `nodes + elements + values` 时绘制云图，并提供：

- 场变量选择；
- 自动范围与 2–98% 分位色标；
- 图例、外框、网格开关；
- 存在原生 vector artifact 时的矢量开关；
- 节点数、单元数、原始数值范围和单位；
- 明确的 Native FEA Evidence 来源说明。

当原生数据缺失或格式无法解析时，界面保持证据空态。颜色分布不会由标量插值、随机值或模板示意生成。

V0.34 建议增加等值线、时间步回放、手动色标、区域显隐、探针、差值云图和导出 PNG/SVG/CSV；所有操作需保留原始范围和 Case/Step 标识。

## 7. 权威等级

| 等级 | 含义 | 允许用途 |
|---|---|---|
| L0 | Studio 参数化示意 | 解释结构与交互定位 |
| L1 | Studio 静态约束 | 提前发现确定性非法关系 |
| L2 | Motor-CAD 原生模型检查 | 确认目标版本可建模/可生成绕组 |
| L3 | Motor-CAD 求解结果 | 数值分析与工程判断 |
| L4 | 原生 artifact + 哈希 + Case 追溯 | 结果验证、报告和数据生产 |

任何视觉组件都应显示自身等级，并保留通向更高等级证据的入口。

## 8. 分期路线与验收指标

| 阶段 | 范围 | 关键验收 |
|---|---|---|
| V0.31 | 七视图、绕组/槽内解释层、状态条、热拓扑、FEA 控制台 | 视图—参数契约可测试；缺证据不绘制伪结果 |
| V0.32 | 原生 Winding Definition 读写回环 | 线径/绝缘/分隔字段保存后回读一致；原生 coil table 可追溯 |
| V0.33 | 原生热网络导出 | 节点、热阻、功率流与 Motor-CAD 同 Case 一致 |
| V0.34 | 高级 FEA 交互 | Step 回放、探针、等值线与导出保持原始范围和单位 |
| V0.35 | 跨版本/跨工况比较与优化 | 设计变化、结果变化和约束变化可同屏解释 |

建议跟踪以下产品指标：

- 从进入项目到找到目标设计参数的中位点击数；
- 从 Design Revision 到首次可提交计算的时间；
- 因槽绕组整数关系导致的 Motor-CAD 启动后失败率；
- 使用原生证据视图完成结果验证的 Case 占比；
- FEA 空态、解析成功、RAW_ONLY 和结构化场的比例；
- 用户从结果返回设计并创建下一 Revision 的完成率；
- 每类阻塞问题的修复时长和重复发生率。
