# V0.89-E — UI Soak / Recovery / Fault Injection Qualification

Release target: **MotorCAD Studio 0.89.5 / Schema 45**

## Purpose

V0.89-E closes the reliability gap between single-pass workflow correctness and long-running engineer use. It qualifies the live Studio browser/control plane under repeated navigation, reload, project re-entry, editor transactions and deliberate recovery faults, while preserving the existing V0.88-F Native and V0.87-F-C 100/500 Case production-hardening contracts.

The authority is `UISoakRecoveryFaultQualificationV1` (`contract_version = 0.89-E`). Formal qualification is additive and fail-closed. It cannot replace V0.89-D real Windows Golden Journey evidence or the formal Native 100/500 Case soak.

## Formal authority chain

Formal PASS requires one evidence chain in the same Studio runtime database:

1. `WindowsMotorCADProductionQualificationV2` / V0.88-F — licensed Windows + Motor-CAD 2026R1 Native matrix and observed fault evidence.
2. `WindowsNativeGoldenJourneyQualificationV1` / V0.89-D — live Chromium SPM/IPM/AFPM Golden Journeys, bound to V0.88-F by immutable `run_id + content_hash`.
3. `ProductionSoakQualificationV1` / V0.87-F-C — formal Native `SOAK_100` and `SOAK_500` Case campaigns plus restart/reopen and Runtime Lifecycle evidence.
4. `UISoakRecoveryFaultQualificationV1` / V0.89-E — live full-shell `UI_SOAK_100` and `UI_SOAK_500`, 12/12 UI recovery faults, inherited Native-fault evidence, release gates and immutable trace package.

A V0.89-D run may only donate inherited Native fault evidence when its frozen V0.88-F predecessor content hash still matches the current V0.88-F acceptance row. Evidence substitution after qualification therefore fails closed.

## UI Soak tiers

| Tier | Required cycles | Minimum telemetry samples | JS heap growth gate* | DOM growth gate | HMI registry growth gate |
|---|---:|---:|---:|---:|---:|
| UI_SOAK_100 | 100 | 10 | <=512 MB | <=2500 nodes | <=64 controls |
| UI_SOAK_500 | 500 | 25 | <=768 MB | <=4000 nodes | <=64 controls |

`*` JS heap is enforced when Chromium exposes `performance.memory`; absence of that optional metric does not fabricate a value.

Each cycle traverses the real production shell and current engineering lineage. The harness repeatedly enters Project overview, Design Revision, Analysis Configuration and ResultBundle when those objects exist; it reloads the browser periodically and leaves/re-enters the project through the project manager. The run records DOM nodes, optional JS heap, active dialogs, HMI action-registry size, route/context state, page exceptions, console errors and HTTP 5xx responses.

The following counters must remain zero for each formal tier:

- failed cycles;
- duplicate writes;
- engineering-context leaks;
- unsaved-data loss;
- orphan dialogs;
- page errors;
- unexpected console errors;
- unexpected HTTP 5xx;
- failed route rollback;
- unhandled Promise rejections.

`MCSEngineeringContextV3` must remain on the qualified project lineage after navigation/reload, the dialog layer must finish clean, and HMI action registration may not grow without bound.

## UI recovery/fault matrix

Formal Windows qualification requires **12/12 PASS**:

1. `DIRTY_NAVIGATION_GUARD` — an edited Project field blocks navigation and retains input.
2. `ROUTE_COMMIT_ROLLBACK` — injected route-commit failure rolls back to the last stable route.
3. `SAVE_RESPONSE_LOSS_REPLAY` — replaying the same Design commit key returns the same immutable Revision.
4. `DOUBLE_CLICK_SINGLE_FLIGHT` — two same-turn save clicks result in one Project write.
5. `HTTP_409_CONFLICT_RECOVERY` — stale Draft version produces visible conflict and a clean refresh/recovery path.
6. `HTTP_500_RETRY_RECOVERY` — one injected 500 is observed; the subsequent health request succeeds.
7. `NETWORK_OFFLINE_RECOVERY` — temporary Chromium offline state fails visibly and the recovered browser regains API reachability.
8. `BROWSER_RELOAD_CONTEXT_RESTORE` — reload restores only backend-validated Project context.
9. `MODAL_INTERRUPT_CLEANUP` — cancel/close removes the dialog and its blocking layer.
10. `ACTIVE_TASK_REFRESH_SURVIVAL` — a qualified V0.89-D Task monitor survives browser refresh without creating a duplicate Task.
11. `RESULT_REOPEN_AFTER_RELOAD` — the exact V0.89-D ResultBundle reopens after refresh.
12. `WORKER_RECYCLE_SURVIVAL` — the real Worker recycle UI action is confirmed, exactly one recycle POST is emitted, and Studio remains operable.

Local Chromium qualification intentionally excludes items 10–11 because they require a real task/result lineage. Local mode therefore qualifies the 10 pure UI/control-plane recovery scenarios plus the full 100/500 UI cycle tiers. It never creates formal Windows/Motor-CAD production status.

## Inherited Native faults

V0.89-E does not re-label browser simulations as Motor-CAD failures. The following faults are inherited from the formal V0.88-F evidence chain and validated by immutable predecessor hash:

- `EXECUTABLE_MISSING_OR_UNSUPPORTED`;
- `LICENSE_UNAVAILABLE`;
- `WORKER_CRASH`;
- `BROWSER_REFRESH_ACTIVE_TASK`;
- `STUDIO_RESTART_REOPEN`.

Formal V0.89-E fails if any required V0.88-F row is absent, non-PASS, lacks portable evidence SHA, or the predecessor content hash no longer matches the V0.89-D frozen reference.

## Evidence package

The live runner writes:

- `tiers/ui_soak_100.json`;
- `tiers/ui_soak_500.json`;
- `telemetry/*_samples.json`;
- `faults/*.json` for all recovery probes;
- `final_ui.png`;
- `playwright_trace.zip`;
- `evidence_manifest.json`;
- `v089e_import_payload.json`;
- `v089e_qualification_result.json`.

Every tier/fault row contains a portable path, SHA-256 and byte size. The final manifest is independently hashed on import. Missing files, path escape, file-size mismatch, SHA mismatch or run-ID mutation blocks qualification.

## Windows one-click execution

`run_windows_production_qualification.ps1` is now the top-level 0.89.5 qualification runner. It uses one `MOTORCAD_STUDIO_DATA_DIR` and separate state/artifact namespaces so all predecessor rows are queryable from the same authority database. The sequence is:

1. current release regression + wheel-neutral import;
2. V0.88-F formal Native qualification and fault evidence;
3. V0.89-D SPM/IPM/AFPM live Golden Journeys;
4. V0.87-F-C Native 100/500 Case soak with graceful shutdown/restart evidence;
5. V0.89-E UI 100/500 cycles and fault matrix;
6. immutable evidence import and final fail-closed summary.

If V0.88-F requires manual observed fault evidence, the runner exits with the existing resume instruction. Resume uses the same evidence root/data authority and continues the remaining D/Native Soak/E layers without silently changing lineage.

## Local diagnostic boundary

A local invocation can exercise the live harness:

```bash
motorcad-studio-ui-soak --base-url http://127.0.0.1:8000 --artifact-dir acceptance_evidence/v089e-local
```

`--cycle-override` is diagnostic only. A shortened cycle count cannot satisfy the 100/500 tier contract.

The current release build environment is Linux and its managed Chromium policy blocks direct navigation to the local Studio URL (`ERR_BLOCKED_BY_ADMINISTRATOR`). Contract/unit/component browser regression is executable here; formal live full-shell evidence must therefore be produced on the target Windows workstation. No formal Windows pass is claimed in the distributed package.
