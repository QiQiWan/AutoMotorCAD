# MotorCAD Studio V0.21 后续架构优化路线图

## 1. 当前阶段判断

V0.21 已经完成领域对象的第一轮收敛：Design、Scenario、Solver Profile、Output Profile 分别版本化，并在 Task 前冻结不可变 Run Configuration。这个变化解决了“设计本体、运行工况、求解设置、输出定义和执行记录混在同一 Task 中”的核心语义问题。

下一阶段的主要风险已经转移到实现层：前端路由仍包裹旧 Tab/global state 生命周期，Motor-CAD 仍主要作为单次求解调用而非受监管运行时，数据库仍使用兼容式补表策略，测试也缺少真实浏览器和 Windows Motor-CAD 合同验证。

## 2. V0.22 — Frontend Core（最高优先级）

### 2.1 目标

把 V0.20/V0.21 的“URL 路由化”升级为“页面生命周期路由化”。

目标结构：

```text
Router
  ↓
Route Resolver
  ↓
Project / Asset Context Resolver
  ↓
Page Controller
  ├─ load(signal)
  ├─ render(model)
  ├─ bind()
  └─ dispose()
```

每次路由变化都终止旧页面未完成请求，禁止旧页面异步结果覆盖新页面。

### 2.2 需要清理的遗留结构

当前 V0.21 仍存在：

```text
main.py                 1651 lines
task_manager.py         1271 lines
solvers/motorcad.py     1480 lines
domain.py                565 lines
setTimeout               ~50 occurrences
previousShowTab           7 references
```

前端 `operator-flow.js / router.js / workflow.js / v021.js` 仍对旧页面行为进行多层包装。V0.22 应逐步移除 `previousShowTab`、页面级 monkey patch 和依赖延迟时间的恢复逻辑。

### 2.3 建议模块

```text
/static/core/router.js
/static/core/store.js
/static/core/api.js
/static/core/i18n.js
/static/pages/project-overview.js
/static/pages/design-revision.js
/static/pages/simulation-setup.js
/static/pages/task-detail.js
/static/pages/task-monitor.js
/static/pages/result-case.js
/static/components/dialog.js
/static/components/model-schematic.js
```

### 2.4 验收

- 任意深链接刷新后恢复同一工程对象；
- Back/Forward 不丢 Project / Revision / Task 上下文；
- 连续快速切换页面时旧请求全部 abort；
- 页面代码不再通过 `setTimeout` 等待另一个页面“先渲染完”；
- 新页面不增加新的全局 `window.*` 业务状态；
- 所有用户文案使用 key-based i18n，不依赖 DOM 文本替换。

## 3. V0.23 — Motor-CAD Runtime + Validation Evidence（最高优先级）

### 3.1 Session Supervisor

将 Motor-CAD 从“被函数启动的外部进程”提升为可观测资源：

```text
MotorCAD Session
├─ session_id
├─ pid
├─ rpc_port / url
├─ Motor-CAD version
├─ template/model
├─ owner case
├─ state
├─ heartbeat
├─ RSS memory
├─ jobs_completed
└─ last_native_error
```

Supervisor 负责：冷启动、租约、释放、异常关闭、进程回收、内存阈值回收和可选 warm pool。

PyMotorCAD 的 `MotorCAD` 对象已经提供 `open_new_instance`、`reuse_parallel_instances`、`keep_instance_open` 等实例生命周期参数，因此 Studio 可以在其上建立明确的 Session Policy，而不依赖进程扫描猜测所有权。

### 3.2 Validation Evidence

把当前瞬时 Gate 升级为可持久化证据：

```text
L0 Static Constraints
L1 Native Build + Parameter Readback
L2 Solver Smoke
L3 Full Solve
L4 Result Quality
```

Evidence 必须绑定：

```text
Run Configuration hash
Motor-CAD version
PyMotorCAD version
Template/MOT hash
Automation mapping version
Automation units
Material database hash
Native messages
Parameter readback
Native snapshot
Result quality summary
```

Motor-CAD 官方自动化文档要求参数自动化时关注 Scripting 页面、弹窗状态、消息历史和 Automation Parameter 默认单位。Studio 应将这些运行上下文写入 Evidence，使 PASS 能够回答“在哪个版本、哪份模型、哪组单位和哪份材料数据上通过”。

### 3.3 验收

- Case 失败时能唯一定位 owning Motor-CAD Session；
- 进程退出、RPC 断开和 Studio 主进程异常后不会遗留无所有者实例；
- 同一 Run Configuration 的 Validation Evidence 可复查且带内容哈希；
- Native PASS 发生任何配置指纹变化后立即失效；
- 一个 Case 的 Motor-CAD 消息不会混入另一个 Case。

## 4. V0.24 — Engineering Workbench

### 4.1 Parameter Dependency Graph

参数编辑器从输入表单升级为工程关系图：

```text
slot_count
  ↓
slot_pitch
  ↓
tooth / slot width
  ↓
winding pattern
  ↓
conductors per slot
  ↓
slot fill
  ↓
winding factor / feasibility
```

每个规则定义：输入参数、派生量、硬约束/软约束、Motor-CAD 证据映射、修复候选。

### 4.2 Issue → Field → Fix

根因卡片直接映射到对应输入项，例如：

```text
Slot fill = 1.41 > 1.00
→ 绕组 / 每槽导体数
→ 导体尺寸
→ 槽面积
→ 推荐恢复上一可行版本 / 调整候选
```

提供“定位参数”“与上一可行 Revision 对比”“恢复模板基线”“修改后重检”，减少用户进入日志中心的频率。

### 4.3 双模型视图

```text
[Studio 快速参数示意] [最近一次 Motor-CAD Native Snapshot]
```

快速示意负责即时反馈；Native Snapshot 只在真实 Native Validation 后更新，并标注 Evidence ID 和时间，避免让近似 SVG 被误认为真实 Motor-CAD 几何。

## 5. V0.25 — Reliability Engineering

### 5.1 数据库 Migration

将当前兼容式 schema 初始化替换为：

```text
backup
→ detect schema version
→ ordered migration
→ integrity check
→ service ready
```

数据库升级失败时阻断工程服务，并提供可恢复备份，禁止在查询阶段临时补表。

### 5.2 浏览器 E2E

至少自动执行：

```text
Project
→ Template
→ Design Rev
→ Scenario Rev
→ Solver/Output Profile
→ Run Configuration
→ Native Validation
→ Submit
→ Monitor
→ Result
→ Refresh / Back / Forward
```

并覆盖非法槽数、材料覆盖、旧 Design 自然迁移和 Run Configuration Replay。

### 5.3 Windows + Motor-CAD Contract Test

建立真实工作站测试矩阵：

```text
Motor-CAD 版本 × 模板 × Analysis × Studio build
```

故障注入覆盖 RPC timeout、Motor-CAD crash、license unavailable、BrokenPipe、Worker kill、DB lock、disk full、stale task 和进程残留。

## 6. V0.26 — Engineering Decision + AI Data

结果中心升级为工程决策工作台：

```text
             Rev.5    Rev.6    Rev.7
Torque       PASS     PASS     —
Efficiency   94.8%    95.1%    —
Loss         182 W    171 W    —
Slot fill    0.82     0.89     1.14 FAIL
Native       PASS     PASS     FAIL
```

支持设为基准、设为候选、创建下一 Revision、加入 DOE、加入 Dataset。

Data Factory 应进一步保存 Validation Evidence ID、材料数据库 hash、automation mapping version、求解器版本、输入/输出 schema 和质量门禁，保证 AI 数据训练时能够筛掉“求解状态成功但工程证据不足”的样本。

## 7. 领域模型还可继续扩展的三个点

### Experiment Definition Revision

V0.21 已把 DOE/优化定义完整冻结进 Run Configuration，因此历史执行可以复现。若后续操作员频繁复用同一 DOE/NSGA-II 方案，再将 Experiment Definition 升级为第五类版本化资产，避免现在就过度增加对象数量。

### Output Profile selection mode

显式区分：

```text
selection_mode = explicit
selection_mode = template_recommended
```

同时冻结 output registry/catalog hash。这样“空列表代表推荐输出”的隐式规则不会随未来模板目录变化而产生歧义。

### Material Provenance

当前材料已经属于 Design-domain 并进入 Run Configuration override lineage。下一步还需要记录：材料数据库文件 checksum、数据库版本、材料名称/ID、BH 曲线、损耗曲线、热物性来源和绑定证据。对于后续代理模型/多物理场训练，这是比材料显示名称更重要的可复现信息。
