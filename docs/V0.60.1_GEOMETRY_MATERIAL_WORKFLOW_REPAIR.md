# V0.60.1 几何、绕组、材料与工作流稳定性修复

日期：2026-08-17  
适用版本：MotorCAD Studio V0.60.1

## 1. 修复范围与设计原则

本次稳定性修复聚焦电机设计工作区的七个直接问题，并同步处理这些问题暴露出的状态管理、布局约束和材料数据治理缺陷。修复保持 V0.60.1 版本号与数据库 schema 19，不引入破坏现有项目数据的迁移。

核心原则：

- 几何预览必须表达与当前拓扑一致的装配关系，示意图允许为可读性放大尺寸，但必须显式说明。
- 用户主动选择的设计视图属于前端会话状态，后台异步刷新不得覆盖该选择。
- 页面刷新/重新加载函数只接受明确的路由上下文，DOM Event 不得被误传为业务上下文。
- 布局以实际设计区域宽度为约束，不依赖浏览器窗口宽度猜测组件可用空间。
- Motor-CAD 材料数据库以工作站上的实际 `.mdb` 为权威来源，并保存来源路径、文件 SHA-256 和 Motor-CAD 版本。
- 导入的 Motor-CAD 材料保持来源快照；编辑时创建 Studio 管理副本，避免扫描或重新导入覆盖用户修改。
- 工程师在完成一个设计步骤后，界面直接给出下一步入口。

## 2. 轴向装配剖面修复

### 原因

原 `v031.js` 的轴向视图使用通用 SVG：定子、转子、磁体和绕组之间的相对位置与径向磁通 BPM/SPM 的真实纵向装配关系不一致，并且径向磁通与轴向磁通模板共用同一套示意图。该实现容易让工程师将预览理解为物理结构。

### 修复

- 新增 `radialMachineAxialView()`，用于径向磁通电机的纵向装配剖面。
- 上下两侧同时显示定子、径向气隙、磁体与转子，保持关于转轴中心线的拓扑对称。
- 显示左右端绕组、中心轴和轴承。
- 气隙和磁体厚度为可读性放大，并在图内声明。
- 新增 `axialFluxAxialView()`，对轴向磁通模板使用转子盘—磁体—轴向气隙—定子盘的堆叠表达。
- `axialView()` 根据 `template.is_axial` 分派对应视图。
- 后端与编辑器标签同步改为“纵向装配剖面”或“轴向堆叠剖面”，减少“轴向截面”对径向磁通电机的语义歧义。

涉及文件：

- `motorcad_studio/static/v031.js`
- `motorcad_studio/static/v024.js`
- `motorcad_studio/model_workbench.py`
- `motorcad_studio/engineering_precheck.py`

## 3. 绕组排布遮挡与重叠修复

### 原因

V0.59 的后置 CSS 把绕组内部布局强制成 `minmax(520px, 1fr) 260px`，在 1500 px 以下仍保持 `420px + 250px`。该组件外层同时存在设计参数侧栏，因此浏览器窗口较宽时，中央设计区域仍可能很窄。旧断点根据 viewport 判断，无法感知中央设计区域的实际宽度，最终出现绕组内容被参数栏覆盖。

### 修复

- 对 `.studio-v059 .winding-layout-v031` 取消硬编码第二列，主布局使用 `minmax(0,1fr)`。
- 所有内部子项强制 `min-width:0; max-width:100%`，避免 table/SVG 撑破 grid。
- 绕组槽表使用自身滚动容器，不再侵入右侧参数栏。
- 增加 design-viewer container query：1040 px 以下压缩摘要区，820 px 以下将设计主体和参数栏纵向堆叠。
- 保留窄屏可读性，桌面端优先完整展示绕组图和槽表。

涉及文件：`motorcad_studio/static/styles.css`

## 4. Motor-CAD 材料数据库模块

### 公开资料结论

Motor-CAD 官方资料公开了 `.mdb` 的文本/INI 存储形式、固体/流体字段含义、钢材 B-H 与损耗数据、磁体退磁曲线和材料导入/导出操作。官方资料没有提供一个可以保证与任意本机 Motor-CAD 安装版本、用户修改状态完全一致的“完整默认材料库清单”。同时，Motor-CAD 会在本机维护所选数据库，材料改动会写回所选 `.mdb`。

因此本系统将本机实际数据库作为材料真值来源，公开文档用于解释字段和格式。

### 新增后端

新增 `motorcad_studio/material_library.py`：

- 解析标准 Motor-CAD `.mdb` INI 文本。
- 支持 `General`、`Magnet`、`Steel`、`Fluid`。
- 原样保留所有 `Key=Value` 字段，未知字段也不会丢失。
- 提取钢材 B-H 曲线、频率/磁密/损耗点。
- 提取磁体多温度退磁曲线。
- 提取流体温度相关热导率、比热、密度和运动黏度数组。
- 自动发现 `MOTORCAD_STUDIO_SOLIDS_DB`、`MOTORCAD_STUDIO_FLUIDS_DB`、`MOTORCAD_DEFAULTS_FILE`、`Defaults.INI` 及受限范围内的 Motor-CAD 用户目录。
- 记录数据库路径、SHA-256、材料数、来源和当前 Motor-CAD 版本。
- 对无法按普通 INI 解析的数据库给出明确错误；加密 Granta 数据需先通过 Motor-CAD/Granta 导入到普通工作数据库。
- 提供材料查询、详情、新建、编辑、复制、删除和 managed `.mdb` 导出。
- 编辑 Motor-CAD 导入快照时创建 `studio_custom` 副本，来源快照继续保持只读。
- managed 导出按材料名去重，同名 Studio 管理材料优先，避免一个 `.mdb` 出现重复 INI section。

新增数据库表：

- `material_databases`
- `material_library_records`

保持 `Database.SCHEMA_VERSION = 19`，通过 `CREATE TABLE IF NOT EXISTS` 在 V0.60.1 稳定补丁内兼容旧项目。

新增 API：

### 新增前端

新增 `motorcad_studio/static/v061.js`：

- 扫描工作站实际 Solids/Fluids 数据库。

## 5. “刷新当前项目”报错修复

### 根因

原绑定：

```js
$('#workspaceRefresh')?.addEventListener('click',loadWorkspace);
```

浏览器会把 `MouseEvent` 作为第一个参数传给 `loadWorkspace(routeCtx)`。函数内部随后调用 `routeCtx.active()`，而 `MouseEvent.active` 不存在，因此报错：

`routeCtx.active is not a function`

### 修复

改为显式无参包装：

```js
$('#workspaceRefresh')?.addEventListener('click',()=>loadWorkspace());
```

并扫描同类绑定，修复以下潜在同源问题：

- `refreshTasks -> loadTasks()`
- `refreshTimeline -> loadTaskTimeline()`
- `refreshLogs -> loadLogs()`
- `logCurrentSession -> loadLogs()`
- `loadCaseViewer -> openCaseViewer()`

涉及文件：`motorcad_studio/static/app.js`

## 6. 几何完成后缺少下一步路径

### 原因

设计区原有的径向、装配剖面、绕组、槽、材料属于“视图切换”，缺少流程语义。工程师完成几何参数后仍需要自行判断下一项应该进入哪个页面，界面没有提供 handoff。

### 修复

新增 `designNextStep()` 和“推荐路径”CTA：

`径向/几何/装配剖面 → 绕组 → 槽内定义 → 材料 → 输入数据`

每个设计视图底部显示当前阶段的直接下一步按钮。到“材料”后直接跳转输入数据中心，减少在顶部导航和侧栏之间寻找入口。

涉及文件：

- `motorcad_studio/static/v031.js`
- `motorcad_studio/static/styles.css`

## 7. 绕组视图短暂选中后跳回其他截面

### 根因

`decorateDesignViewer()` 在每次异步工作区/Revision 重装饰时都重新使用 `preferred` 视图覆盖 `visualState.view`。用户点击“绕组排布”后，后续工作区刷新或 revision 事件到达，视图会被重置。因此表现为绕组先选中，随后快速跳回另一截面。

`v046.js` 的 `openContext()` 还使用延迟 `.click()`，与异步重绘存在竞争条件。

### 修复

- `visualState` 新增 `designId`、`revisionId`、`requestedView` 和 `requestToken`。
- 用户点击视图后保存 `requestedView`。
- 同一设计且视图仍可用时优先保留当前选择。
- 外部上下文跳转先写入 `requestedView`，再触发导航。
- 使用 request token + revision id 丢弃过期异步响应，防止旧请求覆盖新 UI。
- 移除脆弱的 350 ms 延迟点击链路。

涉及文件：

- `motorcad_studio/static/v031.js`
- `motorcad_studio/static/v046.js`

## 8. Geometry / Winding / Input Data 流程栏被压缩

### 根因

`.project-shell` 是两列 grid；旧 `.motorcad-context-nav-v046` 没有设置 `grid-column:1/-1`，因此浏览器自动把它放进第一列。截图中左侧导航被挤成小块、右侧留白正好与该布局行为一致。

### 修复

桌面端：

```css
.motorcad-context-nav-v046{
  grid-column:1/-1;
  width:100%;
  display:grid;
  grid-template-columns:repeat(auto-fit,minmax(132px,1fr));
}
```

820 px 以下切换为横向滚动的固定宽度按钮，避免移动端过度压缩。

涉及文件：`motorcad_studio/static/styles.css`

## 9. 同步发现并处理的相关问题

- `MouseEvent` 误传业务函数的问题存在于多个刷新入口，本次统一处理，避免相同异常在日志/任务/结果查看器中再次出现。
- 设计视图状态与异步工作区状态此前耦合过强，本次增加“用户请求视图”和“请求版本”两个层次，降低刷新触发 UI 回退的概率。
- 绕组布局断点此前依赖 viewport，现增加组件容器宽度约束，适配带左右侧栏的工程工作台。
- 材料数据此前只在计算配置中保存路径，没有数据治理层。本次增加来源、版本、哈希、快照与 managed copy，便于后续 Revision 冻结与结果可追溯。
- 材料模块保留未知 Motor-CAD 字段，可在 Motor-CAD 新版本增加字段时继续导入，减少字段白名单带来的兼容性风险。

## 11. Windows + Motor-CAD 实机验收

自动测试环境没有 Windows Motor-CAD GUI、许可证和本机 Ansys 材料数据库，因此还需要在目标工作站完成一次原生运行验收。建议验收顺序：

1. 打开现有项目并点击“刷新当前项目”，确认不再出现 `routeCtx.active is not a function`。
2. 进入绕组排布并等待至少 2 秒，同时触发一次项目刷新/Revision 重载，确认当前视图保持在绕组。
3. 查看径向磁通 BPM/SPM 的“纵向装配剖面”，确认磁体和气隙关于转轴上下对称，端绕组位于叠片两端。
4. 在 1920、1440 和较窄窗口下查看绕组排布，确认槽表和参数栏互不覆盖。
5. 确认 Geometry / Winding / Input Data 上下文导航占满项目工作区宽度。
6. 按“推荐路径”依次执行几何 → 绕组 → 槽内定义 → 材料 → 输入数据。
7. 打开“Motor-CAD 材料库”，扫描本机数据库，确认能识别当前 `Solids.mdb` / `Fluids.mdb`。
8. 打开 N30UH、M19 或工作站实际使用材料，核对物性、B-H/退磁/损耗点与 Motor-CAD GUI。
9. 编辑一个导入材料，确认系统创建 Studio 管理副本；重新扫描后修改仍保留。
10. 导出 managed solids 数据库并“用于当前计算配置”，执行一次真实 Motor-CAD 任务，确认 `select_material_database()` 成功加载该路径并正常求解。
