# V0.24 后续深层优化路线图

## 结论

V0.24 已把参数编辑从“表单 + 示意图”推进到“模型工作台 + 参数依赖 + 原生证据”。当前最主要的技术债已经集中到三个系统层：前端页面生命周期、Motor-CAD 持久 Worker、原生模型结构化提取。

## P0 — V0.25 Route-first Frontend Core

当前仍存在约 55 处 `setTimeout()` 和 8 处 `previousShowTab` 引用。V0.20 的 URL Router 外面仍包着旧 Tab 生命周期，异步响应覆盖当前页面的风险仍然存在。

目标：

```text
Router
  ↓
Context Resolver
  ↓
Page Controller
  ├─ load(AbortSignal)
  ├─ render()
  ├─ bind()
  └─ dispose()
```

必须完成：

- `DesignRevisionWorkbenchPage`
- `SimulationSetupPage`
- `TaskMonitorPage`
- `CaseResultPage`
- route transition 自动 Abort 旧请求
- 统一 Store，减少 `state.*` 隐式共享
- 删除 `setTimeout` 驱动的“等页面渲染后再恢复状态”
- 用 ES Module 按页面拆分当前大文件

验收标准：连续快速切换 Project/Design/Revision/Task，任何旧请求都不能覆盖新路由。

## P0 — V0.26 Persistent Motor-CAD Worker Pool

V0.23 已明确短生命周期 multiprocessing Case worker 无法可靠承载跨 Case PyMotorCAD session 复用。下一步建立长期存在的 Windows Solver Worker：

```text
Studio Scheduler
  ↓
Motor-CAD Worker Pool
  ├─ Worker A -> Motor-CAD Session A
  ├─ Worker B -> Motor-CAD Session B
  └─ Worker C -> Motor-CAD Session C
```

每个 Worker 持有 PyMotorCAD 对象并负责：

- template reset / load
- clear message boundary
- parameter write/readback
- validation
- solve
- artifact/evidence export
- release/recycle

recycle 条件：

- Job count 超阈值
- RSS 超阈值
- RPC 异常
- Motor-CAD native state 异常
- 显式维护操作

完成后才能安全启用 `reuse_parallel_instances` / `keep_instance_open` 类实例复用能力。

## P1 — V0.27 Native Geometry + Structured Winding Evidence

### Geometry

通过 PyMotorCAD Adaptive Geometry API提取 Region/Entity：

```text
Geometry Tree
  ↓
Region
  ↓
Line / Arc / Coordinate / Material / Area
```

工作台增加：

```text
[快速几何] [Motor-CAD Native Geometry]
```

Native Geometry 必须带来源 Case/Validation ID 和时间戳。

### Winding

在 `save_winding_pattern()` 文本证据之外，增加结构化 coil evidence：

```text
Phase
 Path
  Coil
   go slot / position
   return slot / position
   turns
```

结构化数据来自 `get_winding_coil()`，工作台可绘制真实 go/return coil arcs。只有 API 实际成功返回的 coil 才显示。
