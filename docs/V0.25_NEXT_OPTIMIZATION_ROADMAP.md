# V0.25 后续深层优化路线图

## 总体判断

完成 V0.25 后，前端最危险的异步覆盖链已经被收敛。下一阶段的 P0 应从前端切换到 Motor-CAD Runtime。当前最需要解决的体验差距是：Studio 的“检查”和“正式求解”仍可能由不同进程、不同 Motor-CAD 实例、不同时间点完成；即使两者使用同一 Run Configuration，也存在运行时状态漂移的机会。

## V0.26 — Persistent Motor-CAD Worker Pool + Validate-and-Run Lease（P0）

目标：让一次 Case 从原生检查到正式求解尽可能发生在同一个持久 Worker / Motor-CAD Session 中。

```text
Scheduler
   ↓
License-aware Worker Pool
   ↓
lease Worker MC-01
   ↓
load canonical model
   ↓
apply parameter + readback
   ↓
Native Geometry/Winding validation
   ↓
Solver smoke (可选)
   ↓
保持同一 Session
   ↓
Full Solve
   ↓
FEA evidence / outputs
   ↓
reset or recycle
```

关键优化：

1. 持久 Python Worker 持有 PyMotorCAD client，才能安全利用 Motor-CAD 实例复用。
2. 每个 Worker 有明确状态：IDLE / LEASED / VALIDATING / SOLVING / EXPORTING / RESETTING / RECYCLE。
3. `Validation Evidence` 与 Full Solve 绑定同一 Session ID、MOT hash、parameter readback hash。
4. 解决当前“资格检查 PASS，但 Task Worker 重新载入模型后失败”的 TOCTOU（check/use 分离）风险。
5. Worker 根据 Job Count、RSS、RPC error count、native abnormal state 自动 recycle。
6. Scheduler 同时考虑 EMag/Therm license resource，不让并行 DOE 先启动大量无许可证 Worker。
7. Case 失败后区分 Model Invalid、Runtime Lost、License Wait、Worker Recycle、Solver Native Error。

建议验收：连续 100 个基准 Case 无 orphan Motor-CAD；同一输入的 validation/readback/full-solve fingerprint一致；强制杀死一个 Worker 后其 lease 能恢复且不重复提交 Case。

## V0.27 — Native Geometry + Structured Winding Workbench（P1）

目标：继续缩小与 Motor-CAD Geometry / Winding Editor 的可视化差距。

- Native Region / Entity tree
- 真实 line / arc / coordinate geometry
- Material / Area / Parent-child
- `get_winding_coil()` 结构化 Phase / Path / Coil
- go slot / return slot / turns / position
- Studio 参数 → Motor-CAD Entity / Region 映射
- 点击 native region 直接定位可编辑参数
- 当前 Revision 与上一可行 Revision 原生几何差异

工作台最终形成：

```text
Parameter / Region Tree | Native Geometry / Winding | Constraints / Evidence
```

## V0.28 — Native FEA Mesh Renderer（P1）

当前 V0.23/V0.24 已保留 `save_fea_data()` 原始证据和点云回放。下一步应重建：

- element / node connectivity
- mesh layer
- B / Pt / J 等 scalar field contour
- vector layer
- consistent color scale
- step animation
- Region isolation
- value probe

仍然坚持证据边界：无法从 Motor-CAD 原始导出重建的内容不伪造。

## 可靠性主线 — Formal Migration + Browser E2E + Windows Contract（P0/P1）

### 数据库

当前仍存在开发期的 `CREATE TABLE IF NOT EXISTS + ensure_column + query-time no-such-table recovery`。正式版本应采用：

```text
backup
→ read schema version
→ ordered migration
→ integrity check
→ service ready
```

失败时在 Runtime 页面阻断工程服务，不在查询过程中自动补表。

### 浏览器 E2E

Playwright 应真实点击：

```text
Project → Template → Design → Revision → Scenario
→ Setup → Native Validation → Submit → Monitor → Result
→ Refresh → Back → Forward
```

重点验证快速连续导航时 DOM 永远对应最终 URL。

### Windows Motor-CAD Contract

需要在真实工作站自动执行：

- Motor-CAD startup / RPC
- license unavailable
- RPC timeout
- Motor-CAD crash
- Worker kill
- orphan process
- `save_fea_data()` 格式
- winding pattern export
- concurrent read experiment

## 后端代码边界优化

V0.25 后主要文件规模约为：

```text
main.py             1824 lines
task_manager.py     1321 lines
motorcad.py         1710 lines
```

在 V0.26 运行时稳定后，应拆分：

```text
api/routers/*
services/task_submission.py
services/validation_evidence.py
runtime/worker_pool.py
runtime/session_lease.py
solvers/motorcad/model_io.py
solvers/motorcad/validation.py
solvers/motorcad/results.py
```

拆分目标是建立边界和测试替身，不追求单纯减少行数。

## AI-ready 数据血缘

在 Worker/Validation Evidence 稳定后，Dataset 应继续冻结：

- Run Configuration content hash
- Validation Evidence hash
- Motor-CAD / PyMotorCAD version
- template/MOT hash
- Automation registry hash + unit
- material database and BH/loss curve hash
- FEA evidence hash
- result extraction mapping version

只有这些证据完整后，后续代理模型和优化算法才能区分“物理设计差异”和“求解/映射版本差异”。
