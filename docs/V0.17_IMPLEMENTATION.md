# MotorCAD Studio V0.17 Implementation

## 定位

V0.17 是 End-to-End Workflow Integrity 版本。目标是让项目、设计、工况、Task、结果和数据工厂使用同一工程上下文，并在正式 Task 创建前建立 Motor-CAD Runtime Gate。

## 后端变化

### Schema 11
`design_revisions` 新增 `explicit_parameter_ids_json`。这使 Design Revision 能保存参数数值之外的“明确设计意图”，避免仅凭与 MTT 默认值比较推断参数是否应该写入 Motor-CAD。

`datasets.project_id` 的 V0.17 项目化逻辑继续保留；历史单项目 Dataset 可自动回填归属。

### Design/Scenario lineage validation
Task validation 检查 Design Revision 与 Project/Template 一致，并检查 Scenario Revision 与 Project 一致。

### Runtime Gate
产品模式创建 Motor-CAD Task 前运行缓存式深度预检：成功证据有效期默认 300 s。无启动/RPC证据时自动深检；失败不创建 Task。

### Workflow readiness API
新增/扩展 `/api/workflow/readiness`，输出 Project、Design、Motor-CAD、Qualification、Results/Data 五阶段状态，以及 Runtime Gate 状态。

### Data Factory project isolation
`/api/data-factory/summary`、`/api/datasets` 和 Dataset Build 均支持 Project scope。跨项目 Dataset 构建默认阻断。

## 前端变化

新增 `static/workflow.js`，将新的生产流程逻辑从历史单体 `app.js` 中继续拆出：

- 当前 Project 上下文；
- Design Revision 选择；
- Design 参数基线与运行覆盖；
- 保存为新 Design Revision；
- Scenario Revision 选择/保存；
- Workflow readiness ribbon；
- 首次启动引导；
- Project 切换状态清理；
- `/api/validate` 工程上下文补齐。

## Design Revision 行为

Design Revision 不再只是参数 JSON；它是长期设计基线。Task 可以在 Revision 上临时覆盖参数；如果希望长期保留，可在 Task Builder 直接保存为新的不可变 Revision。

## 兼容性

- 数据库启动自动迁移到 Schema 11；旧 Revision 的 explicit intent 默认为空列表。
- V0.14 的 `TaskManager._explicit_parameter_ids()` 静态接口保留；新增 `_effective_explicit_parameter_ids()` 合并 Revision intent，避免破坏旧回归契约。
- 正式产品仍为 Motor-CAD-only；Mock 只供测试环境。
