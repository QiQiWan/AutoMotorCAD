# MotorCAD Studio V0.62.0 — 前端收敛、设计草稿与版本语义迭代报告

## 1. 本轮目标

V0.60.1 已解决轴向/纵向装配视图、绕组遮挡、材料数据库入口、项目刷新异常和基础下一步提示，但代码仍存在多代前端补丁共同控制 DOM、设计视图状态缺乏完整 URL 表达、Design Revision 与 Analysis Definition 版本关系过于隐式，以及设计编辑在刷新/并发场景下缺少持久草稿等系统性风险。

V0.62.0 将迭代重点放在状态所有权、工程对象语义和持续可维护性。主原则如下：

1. URL 负责表达项目、Design、Revision、设计子视图与编辑状态；
2. Design Revision 永久不可变，修改先进入持久 Design Draft；
3. Analysis Definition 固定引用一个 Design Revision，设计新版本不会静默推动所有分析；
4. Motor Design 可以被多个分析案例复用；
5. Material Library 管理材料事实源，Material Assignment 只处理电机部件绑定；
6. 生命周期事件替代页面级全局 DOM 扫描；
7. 工程师主流程维持一套明确路径，不再叠加平级导航。

## 2. 信息架构收敛

项目主路径统一为：

```text
电机设计 → 分析设置 → 计算 → 结果
```

电机设计内部统一为：

```text
几何 → 绕组 → 材料 → 设计验证
```

对应子视图：

```text
几何：径向截面 / 纵向装配剖面（AFPM 为轴向堆叠剖面）
绕组：绕组连接 / 槽内定义
材料：部件材料配置
设计验证：模型检查
```

“版本对比”作为设计辅助工具，不再与几何/绕组/材料处于同一主阶段。“Input Data”归入分析设置。普通 engineering/operator 模式隐藏重复的 `Geometry / Winding / Input Data` 上下文栏，避免用户同时面对多套流程层级。

## 3. 设计深链接与状态所有权

新增 `static/app-core-v062.js`，集中维护设计阶段和视图映射。Router 现在能够表达精确设计位置，例如：

```text
/app/projects/{P}/designs/{D}/revisions/{R}/geometry/radial
/app/projects/{P}/designs/{D}/revisions/{R}/geometry/axial
/app/projects/{P}/designs/{D}/revisions/{R}/winding/pattern
/app/projects/{P}/designs/{D}/revisions/{R}/winding/slot
/app/projects/{P}/designs/{D}/revisions/{R}/materials
/app/projects/{P}/designs/{D}/revisions/{R}/validation
```

编辑状态在路径末尾增加 `/edit`。刷新浏览器、前进/后退或从深链接进入后，Router 会把 `designSection / designSubview / designView / editRevision` 重新应用到只读设计器或 Draft 编辑器。

V0.60.1 中依赖 `requestedView + setTimeout + DOM decorator` 维持选择状态的路径进一步收敛。`v031.js` 和 `v024.js` 都通过 `MCSRouter.syncDesignView()` 更新 URL，当前视图不再只存在内存中。

## 4. 持久 Design Draft

数据库 Schema 升级至 20，新增 `design_drafts`。每个 Motor Design 最多存在一个未冻结草稿，记录：

- `design_id`；
- `base_revision_id`；
- 参数快照；
- 材料快照；
- 显式参数 ID；
- 当前设计视图；
- 草稿说明；
- 创建/更新时间。

新增 API：

```text
GET    /api/designs/{design_id}/draft
PUT    /api/designs/{design_id}/draft
DELETE /api/designs/{design_id}/draft
POST   /api/designs/{design_id}/draft/commit
```

编辑器行为：

1. 进入编辑后从 Design Revision 初始化；
2. 若存在同基准 Revision 的草稿，自动恢复；
3. 参数和材料修改自动保存到后端 Draft；
4. 用户把所有字段恢复到基准值后，自动删除零差异 Draft；
5. “退出编辑”保存 Draft 后返回只读视图；
6. “放弃草稿”通过 Studio 页内确认对话框删除；
7. “保存为新 Revision”冻结 Draft 并清除草稿。

### 4.1 跨 Revision 冲突

如果同一 Design 已存在基于另一个 Revision 的 Draft，PUT 不允许直接覆盖。编辑器显示冲突 Banner，并锁定当前编辑体，提供：

- 打开现有草稿；
- 删除旧草稿并从当前 Revision 重新编辑。

### 4.2 并发提交保护

提交 Draft 时再次比较 `base_revision_id` 与当前 Design 最新 Revision。如果另一个会话已经产生更新版本，接口返回 HTTP 409。用户必须重新选择最新版本或处理旧草稿，避免静默生成不可预期的版本分支。

## 5. Design / Analysis 版本语义修正

V0.60.1 创建 Design Revision 后会把该 Design 的全部 Analysis Definition 自动更新到最新 Revision。对于工程复现，这会让已有分析案例的设计基线发生隐式变化。

V0.62.0 改为显式绑定：

```text
Analysis Definition → pinned Design Revision
```

新增：

```text
PUT /api/analysis-definitions/{analysis_id}/design-revision
```

后端校验目标 Revision 必须：

- 存在；
- 属于同一 Motor Design；
- 属于同一 Project。

创建普通 Design Revision 不再修改任何 Analysis Definition。

Draft 保存确认框如果发现当前活动分析案例正在引用该 Motor Design，会明确显示：

```text
让当前分析案例采用新版本
“案例名称”将切换到新 Revision；其他分析案例保持原版本。
```

用户可以取消勾选。这样分析版本切换成为可见且可审计的操作。

## 6. 一个 Design 服务多个分析案例

`AnalysisCaseCreate.source_kind` 新增 `existing`，并支持 `design_id`。案例创建器增加“已有电机设计”入口。

行为：

- 选择已有 Design 时读取该 Design 最新 Revision；
- 只创建新的 Analysis Definition；
- 不复制 Motor Design；
- 分析配方根据复用 Design 的电机类型重新筛选；
- 创建失败时不会删除被复用的 Design。

因此可以形成：

```text
BPM Design Rev.4
  ├─ 基准电磁分析 → Rev.4
  ├─ 稳态热分析   → Rev.4
  └─ 退磁分析     → Rev.4
```

随后只让“基准电磁分析”升级到 Rev.5，其余分析仍保持 Rev.4。

## 7. 材料事实源与材料绑定分层

### 7.1 Material Library

继续读取 Motor-CAD 标准 `.mdb`，保留完整原始属性、B-H 点、退磁点、损耗点和温变属性。导入 Motor-CAD 数据库得到只读快照；修改导入记录会生成 Studio 管理副本，后续扫描不会覆盖用户改动。

材料记录现在同时提供：

- `source_database_path`；
- `source_database_hash`：整个 `.mdb` SHA-256；
- `material_section_hash`：单个材料段的稳定 SHA-256；
- `motorcad_version`；
- `source_kind`。

单材料段哈希由材料名称、介质类型、材料类型和完整 Properties 规范化后计算。即使同一 `.mdb` 后续增加其他材料，也能够判断当前具体材料参数是否变化。

### 7.2 Material Assignment

Design Revision 只绑定电机结构材料：

- 定子铁心；
- 转子铁心；
- 永磁体；
- 绕组导体；
- 转轴；
- 机壳；
- 其他模型特定结构材料。

每个绑定保存材料名称与 provenance。设计材料页只展示部件、材料和来源，原始 Motor-CAD Key 留在 Material Library 高级详情。

冷却水、油、空气、入口温度、流量和对流边界继续属于 Analysis Input，允许同一 Design Revision 对比不同热管理方案。

## 8. 生命周期与全局 DOM 扫描收敛

V0.62 移除 `v020/v031/v041/v046/v059/v060` 等页面级全局 `MutationObserver`，页面逻辑改为监听明确的生命周期事件，包括：

- `mcs:workspace-rendered`；
- `mcs:analysis-rendered`；
- `mcs:guidance-updated`；
- 路由状态和监控渲染事件。

当前静态前端仅保留 1 个 `MutationObserver`，用途是 i18n 在英文模式下翻译动态插入节点。

这一步降低了“一个模块重绘 DOM，多个历史补丁同时重新 decorate 页面”的风险。后续 V0.63 仍应继续删除历史 `v0xx.js` 和全局 `window` 导出，迁移到稳定模块目录。

## 9. 错误提示收敛

`toast()` 增加错误签名注册表：

- 同级别、同文本 5 秒内聚合；
- UI 显示 `×N`；
- 最多同时保留 3 个 Toast；
- 淘汰旧 Toast 时同步清理注册表。

类似 `routeCtx.active is not a function` 的连续后台异常不会再生成整列重复提示。后续可以进一步把高频后台错误升级到“问题中心”持久条目。

## 10. 响应式与编辑态布局

V0.62 针对设计工作台继续做结构性约束：

- Workspace / Canvas / Viewer / Workbench 主区域统一 `min-width: 0`；
- 根工作区限制横向溢出；
- 编辑 Design Draft 时隐藏项目树和只读 Inspector，把中央画布扩展到可用宽度；
- 大屏编辑器采用左侧参数组 + 中央画布 + 右侧检查；
- 中等宽度时诊断区下沉；
- 更窄宽度改为单列；
- 设计阶段栏在空间不足时横向滚动，不再压缩成左侧小块。

仍需在 Windows 125% / 150% DPI 进行真实浏览器验收。

## 11. 修复的附带问题

本轮同时处理：

1. 材料 Draft 比较原来使用 `JSON.stringify` 数组 replacer，嵌套 provenance 可能被过滤；改为递归稳定值后再序列化。
2. Draft 变化恢复为零时服务端旧 Draft 可能残留；现在自动 DELETE。
3. 创建新 Revision 后，旧分析案例隐式全部跟随；现在全部保持 pin，只有用户明确选择的案例可采用新版本。
4. 分析案例原来只能伴随新电机创建；现在可以复用已有 Design。
5. 设计草稿放弃/冲突处理原来依赖浏览器确认框；现在使用 Studio Dialog，避免主题、遮罩、键盘行为不一致。
6. Material Assignment 只能记录数据库级哈希；现在增加材料段级哈希，提高具体材料可追溯性。

## 13. Windows + Motor-CAD 2026R1 实机验收清单

当前 Linux 环境无法完成以下原生验收。目标工作站应按顺序执行：

### 13.1 深链接和刷新

1. 打开某项目的 BPM Design Rev.N；
2. 分别进入径向、纵向装配、绕组、槽内、材料、模型检查；
3. 每个页面 F5；
4. 应恢复同一 Design / Revision / 子视图；
5. 点击“编辑设计”后 URL 含 `/edit`；F5 后仍恢复对应 Draft 子视图。

### 13.2 Draft 持久化

1. 修改气隙和磁体厚度；
2. 更换永磁体材料；
3. 等待自动保存提示；
4. F5；
5. 三项修改全部恢复；
6. 将所有值恢复基线，服务端 Draft 应自动消失。

### 13.3 Draft 冲突

1. 基于 Rev.4 创建 Draft；
2. 切到 Rev.3 再进入编辑；
3. 页面必须锁定并提示已有 Rev.4 Draft；
4. “打开现有草稿”跳回 Rev.4；
5. “删除旧草稿并继续”经过 Studio 页内确认后才能编辑 Rev.3。

### 13.4 并发 Revision

1. 会话 A 基于 Rev.4 编辑 Draft；
2. 会话 B 先保存 Rev.5；
3. 会话 A 再提交；
4. 应收到 409，并提示存在更新 Design Revision；
5. 不能静默产生基于旧 Rev.4 的 Rev.6。

### 13.5 一个 Design 多分析

1. 对同一 BPM Design 创建电磁、稳态热、退磁三个分析案例；
2. 确认三个案例可以引用同一 Design Revision；
3. 编辑产生新 Revision；
4. 保存确认框只选择电磁案例采用新版本；
5. 电磁案例进入新 Revision；热/退磁继续指向旧 Revision。

### 13.6 材料追溯

1. 扫描真实 Motor-CAD `Solids.mdb`；
2. 选择 N30UH/M350-50A/Copper 等材料；
3. 确认材料详情显示源数据库 SHA-256 和材料段 SHA-256；
4. 在外部复制并修改数据库中另一个无关材料，验证当前材料段哈希保持；
5. 修改当前材料参数后验证材料段哈希变化；
6. Design Revision 中的 provenance 与 Material Library 对应。

### 13.7 响应式

至少验证：

- 1366×768 @ 100%；
- 1440×900 @ 100%；
- 1920×1080 @ 100%；
- Windows 125%；
- Windows 150%。

要求根页面无水平滚动，绕组/槽表不被右侧参数区遮挡，设计阶段栏不缩成左侧小块，编辑态中央画布可用。

### 13.8 Motor-CAD 原生一致性

BPM / SPM / IPM / AFPM 各至少准备一个原生基准模型，验证：

- Studio 快速几何拓扑与 Motor-CAD 原生拓扑一致；
- Studio 明确区分参数化示意与 Motor-CAD 原生证据；
- 保存 Revision 后计算前检查加载同一参数和材料；
- 真实计算结果归档到正确 Analysis / Design Revision。

## 14. 下一轮建议：V0.63 模块迁移

V0.62 已经建立新的状态语义，但历史前端仍加载约 35 个脚本，保留大量 `innerHTML`、`window` 全局接口、`setTimeout` 和 CSS 后置覆盖。V0.63 建议停止新增 `v063.js` 覆盖层，开始按页面迁移：

```text
static/app/
  store.js
  router.js
  api.js
  errors.js
  design/
    workbench.js
    geometry.js
    winding.js
    materials.js
    validation.js
  analysis/
    workbench.js
    inputs.js
    precheck.js
  solve/
    monitor.js
  results/
    viewer.js
```

每迁移一个模块即删除对应旧版本脚本中的 DOM ownership。优先顺序建议：

1. Design Workbench；
2. Analysis Case / Input；
3. Project Shell；
4. Monitor / Results；
5. Material Library；
6. i18n 动态渲染。

验收重点从“页面是否看起来正确”升级为“单一状态源、单一渲染所有者、可刷新 URL、可恢复 Draft、不可变版本、可追溯材料和可重复分析”。
