# MotorCAD Studio V0.42–V0.46 完成度报告

## 结论

V0.42–V0.46 的 Studio 软件实现已完成。完成口径覆盖配置合同、服务端校验、API、前端工作台、工程结果视图、资格状态和静态验收。目标 Windows + Motor-CAD 2026R1 的原生资格仍按模板 × 配方单独积累；没有真实 PASS 证据的配方最高显示为 `RESULT_VISIBLE`。

| 版本 | 目标 | 软件实现 | 原生资格 | 关键交付 |
|---|---|---:|---:|---|
| V0.42 | 配方与能力合同 | 100% | 按配方积累 | Schema V3、17 配方、五级能力证据 |
| V0.43 | Motor-CAD 工程上下文 | 100% | 不适用 | 九上下文、八 Input Data 域、四绕组页 |
| V0.44 | 专用分析配置 | 100% | 按配方积累 | 动态编辑器、默认值和六类保存校验 |
| V0.45 | 工程结果中心 | 100% | 按 Case 积累 | 结果完整度、场/图/表、热/应力/NVH |
| V0.46 | Sensitivity、Flow、Scripting、资格 | 100% | 待目标机 | DOE 估算、流路校验、脚本白名单、覆盖矩阵 |

## Motor-CAD 流程对齐

| Motor-CAD 关注点 | V0.46 对应实现 | 证据边界 |
|---|---|---|
| 启动即有默认模型 | 新项目默认 BPM；可按机型、模板、MOT、Revision 建模 | 默认基线仍需目标机回读 |
| Geometry 多维视图 | 径向、轴向、槽内、材料、原生证据、版本比较 | 参数范围由模板与注册表约束 |
| Winding | Pattern、Definition、Positions、Diagnostics 信息架构 | 原生 Positions 缺失时不生成伪数据 |
| Input Data | 八个物理域，Flow Circuit 独立表达冷却回路 | 材料/界面高级参数依赖 Automation 注册表 |
| Calculation | 五模块、17 配方、专用字段与结果合同 | 方法签名需目标版本验证 |
| Temperatures | 热网络、温度曲线、热流、图谱 | 摘要与原生拓扑严格区分 |
| Output Data / Graphs | 按结果类型与单位呈现，默认隐藏 JSON | 未提取结果显示缺失，不做合成 |
| Sensitivity | 单点、全因子、LHS、NSGA-II 计算量估算 | 实际调度继续使用不可变 Run Configuration |
| Scripting | 白名单草稿与静态校验 | 原生执行在资格完成前关闭 |

## 未伪装为完成的边界

- 当前交付容器没有 Motor-CAD、Windows GUI、许可证和 PyMotorCAD 运行实例，因此 `native_motorcad_workstation_qualification_percent` 初始为 0；
- 资格记录会在真实 Task/Case 成功后自动提升，也可执行模板资格 Smoke Test；
- Headless 浏览器布局回归需要 CI/Windows 浏览器环境；本版本已经完成 CSS 响应式和 JavaScript 静态验收；
- API 图名候选仍以结果校准为准，未验证候选不会获得 `NATIVE_QUALIFIED`。

## 建议的原生验收顺序

1. 每种目标机型先完成默认模型加载、参数回读、Geometry/Winding 检查；
2. 每个配方执行 1 个最小 Smoke Case，核对方法签名和必需输出；
3. 对 FEA、热网络、Lab 图谱、机械场执行结果校准；
4. 通过 20/100/500 Case 运行合同验证许可证、Worker 回收、内存和崩溃恢复；
5. 资格覆盖矩阵达到目标后再开放脚本原生执行和批量优化。
