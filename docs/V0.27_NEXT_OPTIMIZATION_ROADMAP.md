# V0.27 之后的深层优化路线

## 结论

V0.27 已把正式 Motor-CAD Case 的 Worker、Studio 本地许可证容量和内存余量收敛成一个原子资源租约，同时补齐运行时有效 EXE 权威、Worker capability handshake 和 Runtime Contract。此后最值得投入的方向已经不再是继续增加普通页面，而是让系统具备可升级、可故障注入、可证明长期稳定的生产级运行基础。

推荐顺序：

```text
V0.27 Runtime Contract + Atomic Resource Scheduler        DONE
V0.28 Reliability Core + Formal DB Migration              P0
V0.29 Native Geometry + Structured Winding                P1
V0.30 Native FEA Mesh Renderer                             P1
V0.31 Engineering Decision Workspace                      P1
V0.32 AI-ready Engineering Provenance                     P2
```

## P0：V0.28 Formal Database Migration

### 当前问题

数据库仍使用：

```text
CREATE TABLE IF NOT EXISTS
_ensure_column()
query-time no-such-table retry
```

这种机制适合快速迭代，无法为生产升级提供清晰事务边界。升级失败后，用户可能直到访问某页面才看到数据库错误。

### 目标

```text
Studio bootstrap
      ↓
Migration lock
      ↓
DB backup
      ↓
read schema version
      ↓
ordered migrations
  16 -> 17
  17 -> 18
  ...
      ↓
PRAGMA integrity_check
      ↓
PRAGMA foreign_key_check
      ↓
READY
```

失败时：

```text
ENGINEERING SERVICE = BLOCKED

显示：
Migration ID
Source schema
Target schema
Backup path
Error
Restore action
```

数据库恢复不能藏在普通页面查询重试中。

## P0：浏览器 Playwright E2E

目前 206 项自动测试仍有相当一部分属于 API / 服务 / 静态契约测试。Route-first 已经降低旧请求覆盖风险，但生产体验最终需要浏览器真实点击链验证。

最低完整路径：

```text
运行环境
→ 绑定 Motor-CAD
→ Project
→ Template
→ Design
→ Workbench
→ Revision
→ Scenario
→ Solver / Output
→ Submit
→ Runtime Resource Queue
→ Execution Lease
→ Monitor
→ Result
→ Refresh
→ Back / Forward
```

重点断言：

- 路由刷新后工程对象不丢；
- 旧 Abort request 不能覆盖新页面；
- Task 双击/响应丢失不创建重复 Task；
- 删除 Task 后 Monitor 停止轮询；
- 页内 Dialog 不阻塞浏览器主流程；
- submit button 状态与 model gate 同步；
- Runtime Resource Lease 可见；
- Case 成功但 Result Quality Warning 不显示成“求解失败”。

## P0：Scheduler 第二阶段

### 1. Head-of-Line Blocking

V0.27 当前调度器是严格 FIFO。

例：

```text
Worker = 2
EMAG = 2
THERMAL = 1

Case A = EMag+Thermal  (queue head, THERMAL busy)
Case B = EMag          (EMAG free, Worker free)
```

A 无法运行时，严格 FIFO 会让 B 一并等待。

建议 V0.28 实现 bounded bypass：

```text
FIFO is default
↓
head blocked
↓
允许有限扫描后续可运行 Case
↓
记录 bypass count / waited age
↓
达到 anti-starvation 条件后为老请求保留所需资源
```

需要兼顾吞吐量与任务饥饿，不能简单改成“谁能跑就跑”。

### 2. Interactive 与 Batch 优先级

单次人工验证与 500 Case DOE 的用户期望不同。

建议引入：

```text
INTERACTIVE
NORMAL
BATCH
```

但必须使用 aging，防止 Batch 永久饥饿。

### 3. Native Licence Circuit Breaker

V0.27 正确地保留 `get_licence()` 作为真实权威，因此外部用户占用浮动许可证后，Studio admission 仍可能获得本地 slot，但 native checkout 失败。

后续不应尝试虚构全局 licence count。更稳妥的是：

```text
native licence failure
      ↓
context-specific cooldown
      ↓
短时间暂停新的同类 admission
      ↓
exponential backoff / half-open probe
      ↓
native checkout success
      ↓
close breaker
```

这样能降低许可证服务器拥塞时大量 Case 立即失败的概率。

### 4. Adaptive Memory Admission

Runtime Contract 已记录：

```text
observed_max_worker_rss_mb
recommended_case_memory_reservation_mb
```

后续可以在足够证据后提供：

```text
Manual
Observed recommendation
Adaptive
```

三种模式。

Adaptive 只有在同一个 environment signature 下达到足够样本后才允许，并需要上下限和回退值，避免一次异常 RSS 把并发永久压到 1。

```text

Motor-CAD process recycle count
RSS trend

message-log error classes
```

特别验证：

- repeated `set_free()` / reuse；
- 运行中 cancel；
- RPC blocking 后硬 recycle；
- Motor-CAD crash 后 Worker generation 变化；

- Studio shutdown；
- 外部人工 Motor-CAD 同时占 licence。

在目标工作站没有通过合同前，UI 应继续显示“观测证据”而非“生产认证”。

## P1：V0.29 Native Geometry + Structured Winding

V0.24 Workbench 已有参数依赖图和 Region 映射，但快速几何仍为 Studio schematic。

下一层需要：

```text
[快速随动]
[Motor-CAD Native Geometry]
[Motor-CAD Native Winding]
```

### Native Geometry 中间模型

建议标准化：

```text
Region
├─ id / name
├─ material
├─ area
├─ parent / child
└─ entities
    ├─ Line
    ├─ Arc
    ├─ Circle
    └─ Coordinate
```

这样浏览器可以直接绘制真实 Motor-CAD Region/Entity，不依赖 GUI 截图。

### Structured Winding

从真实 coil 读取：

```text
phase
path
coil
slot_go
slot_return
position
turns
```

然后支持：

```text
错误 -> Coil -> Slot -> Region -> Parameter
```

例如 Slot Fill 超限时直接高亮真实槽和绕组 coil。
