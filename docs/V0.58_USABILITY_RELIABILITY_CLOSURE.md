# MotorCAD Studio V0.58 可用性、界面与可靠性闭环报告

## 1. 结论

V0.58 对上一轮十项需求进行了源码、配置、交互路径和回归测试四层审计。审计确认：V0.57 已建立主要能力，但仍有四类“页面已展示、操作未闭环”的问题：拓扑卡片不能改变模板选择；参数目录会把未修改参数也固化；结果深链可能重复读取 Case；状态码、结果 ID 和底层接口名仍会进入普通工程界面。V0.58 已完成这些程序内缺口的修复。

当前可以明确区分两类完成度：

- **Studio 软件实现与离线回归：完成。** 309 项自动化测试全部通过，JavaScript 语法、Python 编译和配置解析通过。
- **目标 Windows + Motor-CAD 2026R1 实机资格：仍需执行。** 真实许可证、目标 MOT、图名、表名、有限元导出格式和长时间运行稳定性无法由 Linux 离线环境代替。当前 17 类配方仍应按实际 Case 证据逐项晋级，不应统一标记为实机已验证。

## 3. V0.58 具体修改

### 3.1 电机类型、拓扑与模板

创建模型的真实决策顺序为：

1. 选择 BPM、BPMOR、IM、IM1PH、SYNC、SYNCREL、SRM、PMDC 或 CLAW；
2. 选择该机型下的径向表贴、内置、辐条、轴向磁通等拓扑；
3. 系统按拓扑筛选当前安装已经登记的工程模板；
4. 选择工程模板时创建动作实际使用该模板 ID；
5. 所选拓扑没有模板时使用机型默认模型、导入 MOT 或复制现有设计版本。

这修复了“拓扑卡片看起来可以选，实际所有模板仍混在一起”的假闭环。机型默认模型仍是首选起点，模板承担企业基线和映射资产，两者可以并存。

### 3.2 参数编辑可靠性

参数目录现在使用以下保存合同：

- 数值字段必须是有限数；整数类型禁止小数；
- 最小值和最大值在前端即时校验，后端仍保留最终校验；
- 变化比较包含数值容差，避免格式变化产生无意义 Revision；
- 只将实际修改的标准参数加入显式参数集合；
- Automation 长尾参数只更新实际变化项；
- 没有变化时禁止保存并给出明确提示；
- 错误字段显示红色状态并自动聚焦。

由此避免了“打开全部参数、什么都不改、所有字段却被标记为显式覆盖”的配置污染。

### 3.3 结果加载与并发安全

V0.57 的结果页存在三条自动打开路径：结果首页、`loadViewerCases()` 包装器、深链路由。进入指定 Case 时最多可能触发三次查看器请求。V0.58 将自动打开策略集中到基础 Case 加载器：

- 普通进入结果页：自动打开首个 Case 一次；
- 只有 Task 的深链：加载该 Task 后打开首个 Case 一次；
- 指定 Task + Case 的深链：先填充列表，再打开指定 Case 一次；
- 从批量结果跳转：填充列表时禁止自动打开，再打开目标 Case；
- 切换 Task/Case 很快时，旧请求通过 token 失效，不能覆盖最新选择。

任务中心同步移除 JSON 主按钮，将“查看工程结果”设为第一操作；CSV、工程报告、完整数据包和诊断包按用途命名。

### 3.4 普通界面信息分层

普通工程界面显示：

- 分析名称、求解方式、执行状态、结果验证状态；
- 工程输出名称、单位、数值质量和缺失原因；
- 当前计算使用的设计、工况、材料和求解设置；
- 可操作的曲线、表格、有限元空间场和热网络。

以下内容进入折叠技术信息、开发者模式或任务诊断包：

- JSON、MOT、manifest、SHA、内部证据层级；
- Result ID、Automation 名称和 PyMotorCAD 方法名；
- 原始状态码、归档合同字段和完整文件清单；
- 原始错误栈和底层 RPC 细节。

结果验证未通过时，关键 KPI 继续显示为“—”，避免把缺失值误读为 0 Nm、0 W 或 0%。

### 3.5 UI 与响应式布局

V0.58 增加统一视觉状态：

- 键盘焦点使用高对比焦点环；
- 可选拓扑、模型来源和结果模块使用统一选中态；
- 参数修改、参数错误、加载、空结果、结果阻断和监控警告颜色含义一致；
- 结果页在宽屏使用 240 px 导航 + 主画布 + 290 px 检查器；1380 px 以下将检查器移到下方；980 px 以下改为单列；
- 监控六阶段在宽屏一行、中屏三列、窄屏两列或单列；
- 老旧 8–10 px 信息字号提升到 11–13 px，分析说明改用界面字体；
- 参数保存区在长列表底部保持可见，避免滚动后找不到操作。

### 3.6 页面性能

两处全局 `MutationObserver` 曾在每次 DOM 变化时同步扫描页面。结果加载、监控流和表格渲染会产生大量 DOM 变更，从而放大路由耗时。V0.58 使用 `requestAnimationFrame` 合并同一帧内的重复扫描，并通过单次 Case 请求消除结果页的额外网络与渲染工作。

这属于低风险性能收口。当前仍有多个历史版本脚本按顺序增强同一页面，后续应将其合并为按路由加载的领域模块；本轮没有进行大规模前端重写，以免在缺少浏览器视觉基线时引入高风险回归。

## 4. 当前工程流程

| 阶段 | 工程师看到的主问题 | 系统动作 | 完成门槛 |
|---|---|---|---|
| 选择电机 | 要设计哪类电机和拓扑？ | 创建默认模型、套用模板、导入 MOT 或复制版本 | 建立 Design Rev.1 |
| 设计电机 | 几何、绕组、材料是否合理？ | 参数化视图、整数关系检查、模型检查 | 无确定性阻断 |
| 选择分析 | 要回答哪个工程问题？ | 选择 17 类配方之一并说明输出 | 分析定义可配置 |
| 配置工况 | 转速、电流、温度、冷却和精度是什么？ | 冻结 Analysis Revision | 输入完整且合法 |
| 求解监控 | 计算到哪一步、输入输出是否形成？ | 六阶段监控、Worker/Session/Lease、关键事件 | 执行完成或给出根因 |
| 结果验证 | 数据能否用于工程结论？ | 必需结果、有限元场、数值和归档完整性检查 | VALID/WARNING |
| 工程分析 | 性能、损耗、波形、场、温度和应力如何分布？ | 只开放已有数据模块 | 可视化与数值一致 |
| 数据资产 | 是否进入批量分析或寻优？ | 只摄取符合质量规则的 Case | 血缘和质量完整 |

## 5. 可靠性与监控

有限元监控按六个工程阶段聚合底层事件：

| 工程阶段 | 代表事件 | 主要输入/输出 |
|---|---|---|
| 模型输入 | 加载模型、写入 EMag/Therm 参数、材料、模型检查 | 设计版本、工况、材料、检查结论 |
| 有限元求解 | 电磁/机械求解、恢复求解 | Motor-CAD Session、PID、网格与求解进度 |
| 空间场输出 | FEA 导出尝试、文件生成、标准化 | Step 范围、字段、文件字节、帧数、源单元数 |
| 结果提取 | 电磁/热/耦合/机械/Lab 提取 | 标量、曲线、二维图、表和场 |
| 结果验证 | 必需输出与质量检查 | 缺失、无效、有限元资格和质量状态 |
| 归档 | 归档与检查点 | 清单、哈希、恢复点和诊断资料 |

监控卡显示工程阶段和行动状态，底层 event type、payload、PID、Request ID 和错误栈仍进入日志与诊断包。这样既保留可审计性，也避免普通监控页变成内部日志控制台。
