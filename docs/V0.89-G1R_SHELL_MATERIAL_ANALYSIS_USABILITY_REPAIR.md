# V0.89-G1R — Shell / Material / Analysis Usability Repair

Release: **MotorCAD Studio 0.89.8 / Schema 45**

## Scope

This repair is driven by the August 26 production-use screenshots. It closes the visible regressions that remained after V0.89-G1: abnormal project-shell stacking, material-card overlap, excessive Material Library header/source content, confusing magnetic material charts, Native-check/save dead-end, and Analysis Configuration mount failure leaving a visible but dead page.

The formal Windows + licensed Motor-CAD 2026R1 qualification boundary is unchanged. This package claims local automated qualification only.

## 1. Global Shell repair

### Root cause

The project shell accumulated multiple simultaneous context surfaces: project identity, Design/Validate/Decide stage navigation, technical lineage breadcrumb, and a four-cell engineer-focus dashboard. Engineering mode still exposed the technical breadcrumb. At normal desktop widths this produced two competing context bars and excessive vertical density.

### Repair

- Engineering and Operator modes hide the technical lineage breadcrumb; Expert/Developer retain technical evidence.
- The engineer-focus surface is reduced to three functional regions: **当前**, **状态/需要处理**, **下一步**.
- Project context and stage navigation retain their existing authority; no duplicate state is introduced.
- Responsive rules use 3 columns on desktop, 2 + full-width next action at medium width, and 1 column on narrow screens.
- Header/global navigation heights are reduced while retaining the G1 readable typography floor.

## 2. Material configuration overlap

### Root cause

`.context-rule-v031` was implemented as a one-pixel separator but later reused as a container for two lines of explanatory text. Its `height:1px` remained in CSS, so the content overflowed into the primary `编辑材料配置` action. This is the direct cause of the screenshot overlap.

### Repair

The rule is now a normal auto-height content block with a top border. Copy is shortened to the engineering action:

- current component material;
- material follows the motor version;
- cooling medium is configured in Analysis;
- enter Material Configuration and choose a material on the target component row.

The primary action is now **进入材料配置** and cannot overlap the explanatory block.

## 3. Material Library viewport and information density

- Default dialog: **90vw × 90vh**.
- The old multi-card database introduction is replaced by a compact one-line summary.
- Solids.mdb / Fluids.mdb paths and manual import controls move into a collapsed `<details>` disclosure.
- The material list/detail workspace owns the remaining height.
- Existing picker semantics are retained: the caller provides `target_component`; single click previews, double click assigns, and the sticky primary action explicitly assigns the selected material to that component.

## 4. Magnet chart semantics

### B-H reference

When a Motor-CAD record has no raw BValue_Magnet/HValue_Magnet samples, Studio derives a second-quadrant reference from Br and relative permeability. That line is now labeled **磁体退磁参考线（由 Br / µr 推导）**. It is not presented as a measured hysteresis loop.

### HcJ(T)

Motor-CAD databases can store coercive field with a negative second-quadrant sign. Plotting the signed value directly can make normal temperature degradation look visually increasing. The chart now reports engineering magnitude **|HcJ|** while preserving the raw source convention via `hcj_source_sign`. For a conventional negative temperature coefficient, |HcJ| decreases with temperature.

### Chart rendering

- engineering scaling converts large A/m axes to kA/m;
- data markers are shown;
- axes receive padding rather than using exact min/max bounds;
- raw and derived data are labeled separately.

## 5. Analysis Configuration dead-page recovery

### Root cause

`MCSUnifiedAnalysis.mount()` bound the page actions through the Router-owned route context and then rethrew any initial load exception. The Router correctly disposed the failed route context, which removed every `ctx.listen` handler. The DOM remained visible, producing the observed state: **分析配置加载失败** with all surrounding buttons dead.

### Repair

- initial mount errors are fail-soft and are not rethrown to Router;
- the error body provides **重新加载** and **返回电机配置**;
- route-owned Common/Advanced/Refresh/Create/Back handlers remain alive;
- optional Analysis Catalog and template-guidance failures degrade to empty catalogs and log a warning instead of collapsing the page.

## 6. Native-check / save dead-end

### Root cause

Native validation requires a persisted Draft carrying `editor_transaction.transaction_hash` and `intent_hash`. A clean design with no parameter changes can have no such persisted transaction while the immutable **保存设计** action is correctly disabled because there is nothing new to commit. The UI then asked the engineer to save before checking, but there was no valid save action.

### Repair

`ensurePersisted()` now forces a Draft PUT only when the transaction evidence is missing. `DraftService.persist({force:true})` materializes the transaction hashes even with zero parameter changes. It does **not** create a new immutable motor revision. Native validation can then continue against a persisted editor transaction.
