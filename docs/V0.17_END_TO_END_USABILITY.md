# V0.17 端到端可用性审计与修复

V0.17 不以新增求解算法为目标，而是检查一个非开发人员从第一次打开 Studio 到形成可追溯数据集的完整流程是否连续、明确、可恢复。

## 1. 目标用户流程

```text
启动 Studio
  -> 创建/选择 Project
  -> 从模板创建 Design
  -> 选择不可变 Design Revision
  -> 修改设计参数（可选保存为新 Revision）
  -> 选择/保存 Scenario Revision
  -> 选择分析与任务模式
  -> Studio 快速校验
  -> Motor-CAD Runtime Gate
  -> Task / Case
  -> 实时监控
  -> Result Viewer
  -> Data Factory / Dataset Version
```

任何 Project 相关页面都继承同一个 Active Project，禁止各页面独立选择而产生上下文漂移。

## 2. 本轮发现的主要断点

### 2.1 预检查上下文丢失
V0.16 的 `/api/validate` 请求未完整携带 `project_id / design_revision_id / scenario_revision_id`，因此正式模式可能在已有项目的情况下仍给出 `PROJECT_REQUIRED` 类误报。

V0.17 已修复：预检查、几何检查和正式 Task 使用同一工程上下文。

### 2.2 Design Revision 血缘可跨项目/跨模板错配
此前后端没有对 `Design Revision -> Project -> Template` 做强一致性校验。理论上可以把 B 项目的 Design Revision 挂到 A 项目的 Task。

V0.17 新增阻断规则：
- `DESIGN_REVISION_NOT_FOUND`
- `DESIGN_REVISION_PROJECT_MISMATCH`
- `DESIGN_REVISION_TEMPLATE_MISMATCH`
- `DESIGN_REVISION_REQUIRED`
- `SCENARIO_REVISION_PROJECT_MISMATCH`

### 2.3 Design Revision 的“显式设计意图”没有持久化
V0.14 起为了避免把 MTT 候选默认值全部覆盖到新版本 Motor-CAD，Solver 只写入显式设计参数。但旧 Design Revision 只保存参数值，没有保存“哪些值是工程师明确指定的”。当某个显式值恰好等于模板候选默认值时，后续无法仅从数值判断其设计意图。

V0.17 数据库 Schema 11 新增：

```text
design_revisions.explicit_parameter_ids_json
```

设计版本现在同时保存：
- parameter snapshot
- material snapshot
- explicit parameter intent
- content hash

Solver 执行时将 Task 显式参数与 Design Revision 显式意图合并。

### 2.4 Task Builder 与 Design Revision 仍然偏松耦合
V0.17 将模板改成 Design Revision 的派生属性，不能在任务页独立改模板。新增“将当前设计修改保存为新 Revision”，用于把长期设计修改从一次性运行覆盖提升为不可变设计版本。

### 2.5 Scenario 只能临时填写，复用路径不清晰
V0.17 在 Task Builder 中增加 Scenario Revision 选择/保存。环境温度、冷却和初始条件可以作为项目工况复用；临时工况仍允许保存在 Task 快照中。

### 2.6 Data Factory 仍存在全局视角
V0.17 的 Data Factory summary、Dataset Registry 和 Dataset Build 全部支持 `project_id`。一个 Dataset 默认不能混合多个 Project；历史 Dataset 会在能够唯一推断时回填项目归属。

### 2.7 Motor-CAD 不可用时 Task 仍可能先创建后失败
产品模式下新增 Runtime Gate：在创建正式 Motor-CAD Task 之前，必须具有 5 分钟内的启动/RPC成功证据，否则自动运行隔离深检。失败直接返回 `MOTORCAD_NOT_READY`，不会向任务中心写入一个注定失败的 Task。

手工执行“Motor-CAD 深度检查”也会更新 Runtime Gate，并把证据写入：

```text
data/runtime/diagnostics/BOOT-*/runtime_gate.json
```

### 2.8 Project 切换后保留旧 Task/Viewer 状态
V0.17 切换 Active Project 时主动清空旧项目的 monitor task、selected task、viewer、analytics、optimization 和 scenario/design上下文，避免前端继续显示上一项目的数据。

## 3. Workflow Readiness Ribbon

顶部工程流程条现在是可操作状态导航：

```text
Project -> Design Revision -> Motor-CAD -> Qualification -> Results/Data
```

点击 Project/Design 跳转工程工作区；点击 Motor-CAD/Qualification 跳转系统诊断；点击 Results 跳转结果查看器。

无 Project 的首次启动自动进入工程工作区，而不是让用户从 Dashboard 猜第一步。

## 4. Runtime Ready 语义

V0.17 区分：

- PyMotorCAD 可以 import
- 找到/绑定 Motor-CAD.exe
- 最近一次 Motor-CAD 启动/RPC门禁通过
- 模板 Level 1-4 Qualification
- 当前 model policy 的最低资格要求

“找到 EXE”不再等价于“Motor-CAD 已经可计算”。

## 5. Project-first Data Lineage

正式工程链为：

```text
Project
 -> Design
 -> Design Revision
 -> Scenario Revision (optional)
 -> Task
 -> Case
 -> Result / Artifact
 -> Data Factory
 -> Dataset Version
```

项目软删除只影响工作区可见性，不解除历史 Task/Case/Dataset 血缘。

## 6. 当前仍需真实工作站验证的边界

V0.17 解决的是软件流程一致性，不替代真实 Motor-CAD 物理验收。仍需：

1. i5/e9/e14 在目标 Motor-CAD 版本完成 Level 4 Qualification；
2. e14 Yokeless AFPM 的槽型/Slot Opening 继续做实机校准；
3. 完成实际材料 Binding；
4. 校准 Lab / FEA Graph 名称和结果数据合同；
5. 100/500 Case 长时间运行；
6. SessionPool 仍未进入生产级长期复用。
