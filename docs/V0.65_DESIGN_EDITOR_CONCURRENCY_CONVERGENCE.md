# MotorCAD Studio V0.65.0 深度迭代报告：Design Editor 与 Draft 并发收敛

## 1. 本轮迭代目标

V0.64 已经把几何、绕组、材料、设计验证和参数 Inspector 的渲染职责迁入 `static/design/`，但 Design 编辑主生命周期仍由历史 `v024.js` 承担，项目工作流和结果视觉兼容仍挂在 `v031.js` 上。与此同时，持久化 Design Draft 已具备串行自动保存，却仍存在多窗口并发边界：旧窗口可能覆盖新窗口、删除其他窗口更新后的草稿，或者在最终提交 Revision 时冻结一个已经被其他窗口更新过的 Draft。

V0.65 的目标是同时收敛三类问题：

1. 物理移除 `v024.js` / `v031.js` 的活动职责，继续降低历史版本脚本对页面 DOM 和状态的控制。
2. 把 Design Draft 从“单窗口串行保存”升级为“同窗口串行 + 多窗口乐观并发控制”。
3. 将路由离开、Studio 检查、Motor-CAD 原生检查统一纳入编辑会话生命周期，消除后台旧请求和绕过路由守卫的入口。

## 3. Design Draft 乐观并发协议

### 3.1 数据库 Schema 21

`design_drafts` 新增：

```text
version INTEGER NOT NULL DEFAULT 1
```

每次成功 PUT 都将 Draft version 单调递增。前端把服务器返回的 version 作为下一次写操作的乐观锁令牌。

### 3.2 PUT：防止旧窗口覆盖新窗口

请求携带：

```json
{
  "expected_version": 3,
  "base_revision_id": "...",
  "values": {},
  "materials": {}
}
```

服务端在同一数据库锁内读取当前 Draft 并比较 version。若服务端已经是 v4，则返回 HTTP 409：

```json
{
  "code": "DESIGN_DRAFT_STALE",
  "current_version": 4,
  "updated_at": "..."
}
```

旧窗口不能继续静默写入。

### 3.3 修复同一窗口“伪冲突”

V0.64 的串行队列还存在一个隐蔽情况：

```text
A 修改 -> PUT expected=1 正在运行
B 修改 -> 在 A 返回前进入队列
```

如果 B 在“入队时”绑定 expected version，它同样会携带 1。A 成功后服务器 Draft 已到 v2，B 随即被错误判定为 stale。

V0.65 将 `expected_version` 推迟到每一个串行 PUT 真正发送前解析：

```text
A send: expected=1 -> server v2
B send: expected=2 -> server v3
```

`scripts/verify_v065_draft_queue.js` 直接运行该时序，验证两个 payload 快照依次保存，并确认第二次 PUT 使用更新后的 version。

### 3.4 DELETE：禁止删除其他窗口的新草稿

V0.64 的删除语义只经过本地串行队列。若 Tab A 持有 v2，而 Tab B 已经更新到 v3，Tab A 的“放弃草稿”仍可能删除服务器 v3。

V0.65 DELETE 改为：

```text
DELETE /api/designs/{id}/draft?expected_version=2
```

服务器发现当前 version=3 时返回 `DESIGN_DRAFT_STALE`，删除被取消。空 Draft 使用 version 0 表示“我确认当前服务器上没有 Draft”，因此并发新建同样受到保护。

### 3.5 COMMIT：冻结 Revision 前再次校验 Draft

只在前端 flush 完成后调用 commit 仍有一个时间窗口：另一个 Tab 可以在 flush 与 commit 之间更新 Draft。

V0.65 的 commit payload 携带 `expected_version`。后端执行：

```text
Database RLock
  ├─ read current Draft
  ├─ compare expected_version
  ├─ verify base Revision is still latest
  ├─ create immutable Design Revision
  ├─ optionally relink current Analysis Definition
  └─ delete Draft with the same current version
```

上述步骤在同一数据库临界区完成。并发 PUT / DELETE 无法插入“检查后、提交前”的间隙。

## 4. 并发冲突的界面语义

检测到同 Revision Draft 被其他窗口推进后，编辑器进入明确的 stale 状态：

- 显示“草稿已在另一个窗口更新”；
- 阻止继续自动保存；
- 阻止携带未解决本地修改直接离开；
- 阻止保存新 Revision；
- 要求重新加载最新草稿后继续。

这与“基于其他 Revision 的旧 Draft”保持区分。前者属于同一基线上的多窗口并发，后者属于 Revision 基线冲突。

## 5. 路由离开现在经过 Draft 安全边界

V0.64 仍有若干入口可以绕过编辑器：项目树直接调用 `openWorkspaceDesign()` / `selectWorkspaceRevision()`，从而在没有执行 Draft flush 的情况下切换对象。

V0.65 增加统一路由守卫：

```text
navigate / popstate / tree Design click / Revision click
             ↓
MCSDesignEditor.prepareRouteChange(targetRoute)
             ↓
      flush current Draft
        ├─ success -> continue route
        └─ failure -> keep/restore lastStablePath
```

项目树和 Revision chip 统一通过 `MCSWorkspaceNavigationV065` 构造精确 URL 后交给 Router。浏览器后退/前进同样受守卫约束。

离开成功后编辑器会终止当前 shell event lifecycle，并 dispose validation session，避免旧页面回调继续改变新页面。

## 6. Studio / Motor-CAD 验证改为显式、版本感知

### 6.1 删除每次输入后的网络验证

工程参数连续输入时，网络检查既影响交互速度，也容易让旧响应覆盖新草稿。V0.65 的输入路径只执行：

```text
参数输入
  -> 本地值校验
  -> 本地几何/绕组/材料预览
  -> Draft autosave
  -> editVersion +1
```

Studio 确定性检查和 Motor-CAD 原生检查由工程师显式触发。

### 6.2 验证结果绑定 editVersion

`MCSDesignPrecheck` 分别记录：

```text
precheckVersion
nativeVersion
```

如果检查完成后参数再次变化，历史检查结果仍可展示，但其版本低于当前 `editVersion`，界面将其视为过期证据，要求重新运行。

### 6.3 Motor-CAD 检查增加独立取消与 session token

原生模型检查可能运行较长。仅比较 `editVersion` 仍不足够：退出编辑器后重新进入，新会话的 editVersion 可能再次从 0 开始，旧请求有机会“碰巧匹配”新会话。

V0.65 增加：

- `nativeAbort: AbortController`
- editor `session`
- Studio/native 请求都捕获 session + editVersion
- `begin()` / `dispose()` 同时 abort 旧请求并推进 session

因此旧 Motor-CAD 检查无法回流到后续新编辑会话。

## 7. 设计验证 UI 继续收敛

设计验证页现在将两层证据显示为明确管线：

```text
Studio 设计检查  ->  Motor-CAD 原生验证
```

工程师可以分别看到：

- 当前阶段状态；
- 检查是否与当前 Draft 版本一致；
- 问题清单；
- 显式运行操作；
- 原生验证结果；
- “保存为新 Revision”这一不可变版本边界。

`design-workspace` 容器宽度低于 760 px 时，验证管线由横向切为纵向，两个检查按钮由双列切为单列，冲突提示也转成纵向操作布局。Playwright/Chromium 已验证宽屏与 700 px 组件宽度下无根容器水平溢出。

## 8. 本轮发现并修复的隐藏问题

本轮在继续模块迁移时额外定位出 5 个高价值问题：

1. **串行 Draft 队列仍可能产生伪 stale 冲突**：原因是 expected version 在入队时捕获；改为发送时绑定。
2. **旧窗口可以删除新窗口的 Draft**：DELETE 增加 version guard。
3. **flush 与 Revision commit 之间存在并发窗口**：commit 增加 version guard，并在数据库临界区完成检查、Revision 创建与 Draft 删除。
4. **长时间 Motor-CAD validation 可跨越编辑会话**：增加 native AbortController + session token。
5. **项目树切换可绕过 route guard**：Design/Revision 树入口统一改走 Router。

这些问题大多不会在单窗口手工测试中稳定出现，但会造成难以复现的“草稿突然变旧、版本保存错了、页面跳转后又出现旧检查结果”等工程软件高风险故障。

## 10. 仍需 Windows + Motor-CAD 实机验证的边界

当前执行环境没有目标 Windows Motor-CAD 2026R1 GUI、许可证和用户工作站材料数据库，因此下列项目仍保持“待实机验收”：

1. BPM / SPM / IPM / AFPM 参数化快速预览与目标 Motor-CAD 原生几何逐模型对照；
2. Windows 125% / 150% DPI 下 1366×768、1440×900、1920×1080 的整应用视觉验收；
3. 实际 PyMotorCAD RPC 长时运行、异常断链和重连；
4. 本机 `.mdb` 材料库发现、导入、managed database 写入与真实求解；
5. Motor-CAD 原生验证请求被页面切换取消时，目标版本 PyMotorCAD/HTTP 边界是否能立即中止底层调用；
6. 双浏览器/双窗口真实操作下的 Draft 409 冲突 UX。

这些项目没有在本轮报告中标记为已完成。

## 11. V0.66 建议推进方向

下一轮建议继续沿“物理移除历史所有权”的路径推进，优先级如下。

### P0：迁移并删除 `v020.js`

`v020.js` 仍承担运行环境 gate、部分模型指导、旧编辑入口 fallback 和 UI 词汇兼容。建议拆成：

```text
runtime/model-gate.js
workflow/guidance.js
compat/legacy-ui-terms.js   （若仍必须保留）
```

随后从 `index.html` 删除 `v020.js`。

### P0：迁移 `v025.js` 路由兼容职责

当前 Router 已经成为 Design route 真值源，`v025.js` 中剩余路由 controller 应逐项迁出，避免两套 route lifecycle 长期共存。

### P1：浏览器级真实交互 E2E

增加本地 ASGI/浏览器测试，覆盖：

- Draft 编辑后 F5 恢复；
- back/forward 前的 autosave flush；
- 两个 browser context 同 Revision 竞争写；
- stale DELETE；
- stale COMMIT；
- 验证运行中切换 Revision；
- 快速切换几何/绕组/材料视图；
- 1366/1440/1920 + DPI 等效 viewport。

### P1：减少粗粒度 DOM 重绘

当前仍有 365 处 `innerHTML`。下一阶段应优先对高频 Design/Analysis/Monitor 区域使用 keyed DOM update 或局部组件替换，减少输入光标、滚动位置、焦点和辅助技术语义被重建。

### P2：收敛全局接口

当前显式 `window.*` 赋值约 114 个。稳定模块应逐步改成少量 namespace/registry，避免隐藏依赖继续阻碍历史脚本删除。

## 12. 本轮结论

V0.65 已把 Design 编辑器从历史版本脚本中正式抽离，并补齐 Draft 多窗口并发安全、删除安全、提交原子边界、路由离开 flush 和验证会话取消。当前 Design 工作台的状态所有权已经明显集中，后续可以继续删除历史脚本，而无需依赖新的 `v066.js` 后置覆盖。

下一阶段的关键衡量标准应从“新增多少 UI 修补”转向“能够删除多少历史所有权，并用浏览器 E2E 与真实 Motor-CAD 证据证明迁移后行为一致”。
