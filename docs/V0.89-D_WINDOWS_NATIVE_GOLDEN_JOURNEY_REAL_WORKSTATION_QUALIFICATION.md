# V0.89-D — Windows Native Golden Journey & Real Workstation Qualification

Release target: **MotorCAD Studio 0.89.4 / Schema 45**

## 1. Goal

V0.89-D closes the gap between a qualified Motor-CAD integration and a workflow that an engineer can actually execute through the production Studio shell. Formal qualification is layered on top of the existing V0.88-F `WindowsMotorCADProductionQualificationV2`; it does not replace or weaken the four Native scenario, 17-fault, runtime-lifecycle, restart/reopen, binding/readback/repair/preview/spatial gates.

A workstation is V0.89-D formally qualified only when the same licensed Windows + Motor-CAD 2026R1 environment also completes three live full-shell UI journeys:

| Journey | Golden starter | Motor-CAD template |
| --- | --- | --- |
| SPM | `golden_spm_servo` | `i5_Industrial_SPM_Servo_Tooth_Wound` |
| IPM | `golden_ipm_emobility` | `e9_eMobility_IPM` |
| AFPM | `golden_afpm_ssdr` | `e14_eMobility_AFM` |

## 2. Qualification authority

New authority: `WindowsNativeGoldenJourneyQualificationV1`, contract `0.89-D`.

The imported run must reference the immutable `run_id` and `content_hash` of a formal `WindowsMotorCADProductionQualificationV2` predecessor. The service fails closed when the predecessor is missing, not formal, non-Windows, targets another Motor-CAD version, or its content hash differs.

Formal V0.89-D also requires the release gates:

- `global_workflow_truth` — V0.89-A;
- `full_button_hmi_qualification` — V0.89-B;
- `editor_navigation_transaction_hardening` — V0.89-C.

## 3. Live Golden Journey

`motorcad_studio.acceptance.windows_golden_journey` uses Playwright Chromium against a **live Studio URL**. Formal mode is rejected outside Windows.

Each journey executes the engineer path through real UI controls:

1. open the production Studio shell;
2. create and enter a project;
3. enter Design;
4. select the required Golden Starter;
5. create the immutable Motor Rev.1;
6. enter Analysis Configuration;
7. create `rated_emag` Analysis Rev.1 from the current Motor Revision;
8. enter Check and run the full Native calculation precheck;
9. submit a real Motor-CAD task through the UI;
10. wait for task completion and a completed Case;
11. obtain the ResultBundle and immutable hash;
12. reload the live shell and enter Decide;
13. select the exact Task and Case and open the result through the result viewer;
14. verify Project → Solution → Motor Revision → Analysis → Analysis Revision → Task → Case → ResultBundle lineage.

The following gates are mandatory per journey: `live_studio_shell`, `project_created_via_ui`, `starter_opened_via_ui`, `rev1_created_via_ui`, `analysis_created_via_ui`, `full_native_precheck_via_ui`, `task_submitted_via_ui`, `task_completed`, `result_bundle_ready`, `result_opened_via_ui`, `lineage_consistent`, `no_page_errors`, `no_console_errors`, `screenshot_evidence`, and `trace_evidence`.

## 4. Evidence package

Every SPM/IPM/AFPM journey freezes:

- `summary.json`;
- design screenshot;
- full-precheck screenshot;
- result-viewer screenshot;
- Playwright `trace.zip` including screenshots, DOM snapshots and sources.

All referenced files are covered by a SHA-256 evidence manifest. Formal import verifies path containment, file existence, file size, file hash, evidence-to-manifest linkage and manifest hash. Evidence tampering is fail-visible.

## 5. UI qualification state

The Runtime → Windows Motor-CAD qualification panel now prefers `/api/windows-golden-journey-qualification` and displays two distinct layers:

- V0.88-F Native base qualification: 4/4 Native scenarios + 17/17 fault evidence;
- V0.89-D live UI qualification: 3/3 SPM/IPM/AFPM Golden Journeys.

The Golden Starter catalog receives its `production_verified` flag only from a formally qualified V0.89-D journey for the corresponding starter. A template, local unit test, mocked browser E2E, or V0.88-F Native pass alone cannot set that badge.

## 6. Windows execution

Run from an authorized Windows workstation:

```powershell
.\run_windows_production_qualification.ps1 -Install
```

The qualification script builds and installs the current wheel in a neutral directory, executes current release gates, performs V0.88-F preflight/Native scenarios/runtime/fault-evidence finalization, and then launches V0.89-D live Chromium journeys. If the fault matrix needs manually observed evidence, the script exits with code 4 and prints the exact `-ResumeOnly` command. V0.89-D runs after the predecessor is formally frozen.

The standalone V0.89-D runner is also available after the predecessor exists:

```powershell
motorcad-studio-windows-golden-journey --formal `
  --base-url http://127.0.0.1:8000 `
  --artifact-dir C:\qualification\golden_journey_evidence `
  --release-gates C:\qualification\release_gates.json
```

## 7. Qualification boundary for this release package

The implementation, fail-closed contract, evidence verifier, live browser runner and mocked HMI regression can be validated on non-Windows development hosts. **Formal workstation qualification remains Pending until the package is executed on a real licensed Windows workstation with Motor-CAD 2026R1 and PyMotorCAD 0.8.8.** Development-host test results must not be reported as real-workstation PASS.
