# V0.52 Windows + Motor-CAD 原生验收清单

## 入口条件

- 记录 Windows、Motor-CAD、PyMotorCAD、Studio 版本和电机模板哈希。
- 在系统运行环境页完成 EXE、Automation、许可、写目录和持久 Worker 检查。
- 每个模板至少准备一个基准工作点和一个边界工作点。

## 单 Case 有限元验收

1. 从默认模型或现有 Design Revision 建立 Analysis Revision。
2. 确认 FEA 策略、必需场、结果合同和输出单位。
3. 提交后核对八个执行阶段和同一执行租约。
4. 在 Motor-CAD 原生 UI 与 Studio 中选择相同步和相同物理量。
5. 至少抽查极值点、齿部、轭部、气隙、磁体/转子五类区域；记录相对误差。
6. 核对原始 FEA 文件哈希、帧数、区域、坐标范围、场范围和连接状态。
7. 核对所有必需结果均为 `EXTRACTED`，单位和曲线长度正确。
8. 只有 `quality_status=VALID`、`result_extraction_contract=COMPLETE` 且 required `fea_contract=COMPLETE` 才验收。

## 批量稳定性验收

- 小批：10 Case；中批：100 Case；长稳：连续 8 小时或 500 Case。
- 检查许可峰值、Motor-CAD 进程数、RSS 增长、孤儿进程、超时和重试次数。
- 通过 `fea-result-summary` 确认合格 Case 数与优化可用 Case 数一致。
- 人为中断一个 Case，验证只重试失败/不完整 Case，完整 Case 不重复求解。

## 通过标准

| 项目 | 标准 |
|---|---|
| 必需结果提取 | 100% |
| required FEA 合同 | 100% COMPLETE |
| 原生 UI 抽样差异 | 满足项目定义容差 |
| Case 进程回收 | 无孤儿 Motor-CAD 进程 |
| 长稳任务 | 无持续内存增长；无未解释失败 |
| 资格晋级 | 证据清单、模型哈希、版本和 Case ID 可追溯 |

任何一项失败时保留执行成功事实，同时将工程质量停在 `INVALID` 或 `WARNING`；禁止手工把配方标记为 `NATIVE_QUALIFIED`。
