```bat
where python

```

安装完成后重启 Studio，再执行“运行环境 → 深度检查”。V0.57 的问题中心会将其归类为 `PYMOTORCAD_DEPENDENCY`，并直接显示上述处理路径。

## 4. 交互流程

### 4.1 模型入口

1. 新项目可直接创建默认 BPM，并立即进入径向几何；
2. “新建模型”第一步选择 Motor-CAD 机型；
3. 第二步选择该机型下的拓扑和模型来源；
4. 第三步填写模型名、模板/MOT/Revision 与几何参数化方式；
5. 创建 Rev.1 后直接进入几何与绕组，而无需回到资产列表。

工程模板继续承担企业可行基线和参数映射。机型默认模型提供 Motor-CAD 式的快速起点，两条路径可并存。

### 4.2 分析入口

17 类分析统一按以下信息展示：

- 该分析回答什么工程问题；
- 使用直接求解、扫描、稳态、瞬态、顺序耦合或原生耦合；
- 需要配置哪些工况和精度；
- 完成后可查看哪些 KPI、曲线、二维图、有限元场或热网络；
- 哪些结果缺失会阻止结果验证。

内部的 `native_evidence` 策略属于系统配置，普通分析页面不显示。

### 4.3 结果入口

结果页按以下顺序组织：

1. 选择 Task，自动选中首个 Case；
2. 查看执行状态；
3. 查看结果验证状态和阻断原因；
4. 只进入有数据的性能、损耗、曲线、有限元场、热网络或温度模块；
5. 需要排障时下载当前 Task、当前启动会话的诊断包。

## 5. 绕组绘制约束

绕组圆图采用槽口定位点、径向引出段、端部绕组圆弧、径向回槽段四段式路径。圆弧半径始终大于定子内圆半径，路径不会进入转子区域。进/回槽的 `×`、`•` 仍保留相色和方向含义。

槽内视图采用两个独立多边形裁剪区域：

- 左右绕组分别受槽衬与中央分隔限制；
- 圆导体的直径由槽腔尺寸、目标槽满率和最小间距共同约束；
- 排布采用交错行并执行最小中心距；
- 槽楔、槽衬、分隔条和导体拥有独立边界，不再互相覆盖。

该视图属于参数化工程示意。真实导体根数、线径和 winding pattern 以本次 Case 的 Motor-CAD 结果验证为准。

## 7. Motor-CAD API 修复

V0.57 按 PyMotorCAD UI 方法合同完成屏幕抓取：先调用 `initialise_tab_names()`，再传入 `screen_name` 和 `file_name` 两个参数；主方法失败时使用 `save_screen_to_file()` 回退。成功后检查文件存在性、大小和 SHA-256，失败原因进入 Case 警告和任务诊断包。

有限元数据继续使用六参数 `save_fea_data(file_name, first_step, final_step, outputs, regions, separator)`。每个尝试均记录，不会只留下一个“未知原因”的黑屏。

扭矩—转速结果提取增加多个目标版本候选图名。图名仍需在目标版本 Motor-CAD 的 Graph Viewer 中确认，只有实际提取成功才满足 `torque_speed_envelope` 必需结果。
