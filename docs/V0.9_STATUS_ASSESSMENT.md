V0.9 completes the software-side data factory foundation. It does not complete the real Motor-CAD validation program because the current build environment has no Motor-CAD installation or licence.

## V0.9 completion definition

Software-side V0.9 is complete when:

- adaptive generations are created from evaluated results;
- constraints affect feasible design selection;
- every terminal Task is ingested or explicitly records ingestion failure;
- raw/curated/feature zones are generated;
- dataset versions are immutable;
- dataset rows retain Case lineage;
- schema/content hashes are generated;
- excluded rows are quarantined;
- stable partitions are deterministic;
- test/runtime factory storage is isolated;
- complete automated regression is green.

These criteria are met in the delivered build.

## What remains before calling the data factory engineering-validated

1. Generate i5/e9/e14 real Motor-CAD datasets.
2. Run at least 100 valid Cases per core template.
3. Run an AFPM DOE of at least 500 Cases.
4. Verify no cache collision after material/solver-setting changes.
5. Verify data regeneration yields stable schema and partitions.
6. Verify long-running Motor-CAD concurrency and licensing.
7. Promote only VALID real-solver rows to the first frozen engineering dataset release.

## Recommended next milestone

`V1.0 Data Factory Validation Release` should focus on real Motor-CAD data production, Map2D/Lab data, dataset promotion/freeze/diff, and session reliability. AI should remain out of scope until those gates pass.
