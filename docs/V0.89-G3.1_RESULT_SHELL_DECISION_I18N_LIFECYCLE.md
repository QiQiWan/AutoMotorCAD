## 3. Root causes closed in G3.0/G3.1

### 3.1 Engineering Decision Summary could remain in loading forever

The old result-page decision component read the active project through `window.state`. The application state is exposed as `window.MCSAppState` and also exists as lexical `state`; `window.state` is not a reliable authority. When the project id resolved to null, the request was never started and the original loading placeholder could remain on screen indefinitely.

G3.1 resolves project context in this order:

1. `MCSResultContext.current().projectId`
2. `MCSEngineeringContext.get().projectId`
3. lexical application state
4. persisted active-project hint

The summary now has explicit **loading / ready / degraded** states. A five-second request timeout and retry action prevent a permanent spinner. Missing or partial decision evidence no longer blocks result browsing.

### 3.2 Result-view language was captured from stale page state

The left result-view navigator was built from a language value captured before later language changes. G3.1 reads `MCS_I18N.language` at render time and rerenders the active result view after `mcs-language-change`. Route keys stay stable while labels/descriptions switch between Chinese and English.

### 3.3 Result-view modules exposed a large “module not implemented” blank state

G3.1 removes the generic blank “模块未实现” surface. Output Data, Graphs, Thermal Schematic, Temperatures, Stress, and NVH now use explicit inventory/fail-soft renderers. When the current ResultBundle has no matching data, the page states what is missing and preserves access to available evidence instead of presenting a dead end.

This is a presentation-side preparation for G3.2. It does not manufacture result data that the solver did not extract.

### 3.4 Native FEA viewer could write into a destroyed DOM tree

Rapid module/route changes could finish an older asynchronous frame/evidence request after its viewer DOM had already been removed. The observed failure class was a null DOM write in `field-viewer.js`.

G3.0 adds:

- monotonic mount token;
- explicit `disposeNativeField()`;
- host connectivity and case-identity validation;
- null-safe legend/frame/probe writes;
- guarded ResizeObserver lifecycle;
- automatic disposal on route leave.

A stale asynchronous response can no longer mutate a newer/destroyed result view.

### 3.5 Result-page shell spacing still separated status from the workflow stages

G3.1 gives the desktop shell a bounded four-column authority:

`project identity | Design/Validate/Decide | status/next | flexible remainder`

The stage and engineering-status groups remain spatially adjacent on wide displays instead of stretching status information to the far-right edge. A responsive compact layout takes over below 1380 px. Child cells use border-box sizing so the declared compact shell height remains authoritative.

## 5. Acceptance contract for this increment

G3.1 is locally acceptable when all of the following hold:

1. The Decision Summary cannot remain indefinitely in its loading placeholder when project context or backend evidence is missing.
2. A decision request that exceeds its timeout becomes a degraded summary with an explicit retry action.
3. Chinese/English switching rerenders visible result-view names and descriptions without route reload.
4. No result module displays the generic “模块未实现” dead-end panel.
5. Rapid result-view changes cannot produce a stale FEA DOM write.
6. At desktop width, project identity, workflow stage, and status/next groups remain adjacent and readable.
7. Existing G1 shell regression remains green.
8. A complete-shell browser journey reaches result-page routes without page errors.
