# MotorCAD Studio V0.13 — Production Calibration & Result Discovery

## 1. 版本定位

V0.13 不再继续横向增加大量普通功能，而是把 V0.12 已建立的“资格检查、材料验证、结果查看器”进一步变成可持续的实机校准体系。核心目标是让目标 Windows 工作站产生的验证证据可以持久化、参与任务门禁、进入仿真指纹，并直接影响后续 Solver 结果提取。

## 2. 资格证据持久化

新增数据库实体 `qualification_records`。每次模板资格检查都保存：

- template_id；
- Motor-CAD target version；
- analysis；
- Level 0–4；
- PASS/FAIL；
- 是否执行真实 solver smoke；
- 完整 checks/result；
- 时间。

系统新增资格矩阵 API 和 GUI，可查看模板 × 分析的最新证据。

### 运行门禁

- development：未资格模板仍可开发运行；Level >= 3 后移除 `ANALYSIS_NOT_VERIFIED` 警告。
- validation：Motor-CAD Task 至少需要 Level 3。
- production：Motor-CAD Task 至少需要 Level 4，即真实求解 smoke 已通过。

因此“资格检查”不再只是一个一次性诊断按钮，而成为生产运行策略的一部分。

## 3. 材料绑定证据

新增 `material_bindings`。模板 Qualification 或“目标 Motor-CAD 回读验证”执行真实：

`set_component_material(component, material)` → `get_component_material(component)`。

成功回读后记录 `VERIFIED` binding；仅设置成功但不能确认 readback 时记录 `APPLIED_UNCONFIRMED`；失败记录 `FAILED`。

当前 PyMotorCAD stable Materials API 并没有公开“枚举材料数据库中所有材料名称”的通用接口，因此 V0.13 不伪造全库扫描。当前实现是对工程师选择的材料映射进行目标数据库验证，并持久化证据。

## 4. Result Calibration / Graph Probe

PyMotorCAD 的 Graph API 需要 `graph_name`。官方文档要求从 Motor-CAD `Help -> Graph Viewer` 确认名称，但没有提供通用的 Graph Viewer 名称枚举 API。因此 V0.13 新增“结果校准与 Graph 探测”：

1. 从 versioned output registry 载入已有候选，例如 `TorqueVW`、`B Gap (on load)`；
2. 允许工程师按目标模板修改 Graph Viewer Name；
3. 在隔离 Motor-CAD 进程中调用真实 API 探测；
4. 保存 VERIFIED/FAILED 证据；
5. 后续 Solver worker 优先使用 VERIFIED graph name；
6. 原版本候选仍作为回退。

支持的探测 extractor：

- `magnetic_graph`；
- `magnetic_harmonics`；
- `fea_graph`；
- `magnetic_3d_graph`；
- `temperature_graph`；
- `heatflow_graph`；
- `power_graph`。

## 5. 校准进入 Simulation Fingerprint

V0.13 将已验证 result calibration 纳入 Simulation Fingerprint。若同一模板、参数、材料和工况不变，但 Graph 提取映射发生变化，新的 Case 不会误命中旧缓存。

这使缓存身份从“物理输入身份”进一步覆盖“标准结果提取身份”，保证数据工厂的结果字段来源可追溯。

## 6. 前端模块化第一阶段

V0.12 生产级实时/资格/参数角色逻辑从单体 `app.js` 拆到：

- `app.js`：历史主应用与核心工作流；
- `realtime.js`：统一 SSE/Polling；
- `production.js`：生产资格、材料证据、参数角色、结果校准；
- `i18n.js`：兼容国际化层；
- `locale-data.js`：新增 key-based locale resources。

这不是最终 React/TypeScript 迁移，但停止了继续把生产逻辑直接堆入单一 JS 文件。

## 7. Result Viewer 数据合同扩展

在 `scalar / series / spectrum / map2d / artifact` 基础上新增：

- `mesh_field`：非结构网格节点、单元与标量场；
- `vector_field`：坐标与矢量；
- `table`：工程表格结果。

前端增加初步 MeshField 和 VectorField SVG renderer。当前真实 Motor-CAD 网格/矢量场仍需要目标版本实际结果格式校准，不能把示意 renderer 当作已经完成的全功能 FEA Viewer。

## 8. 诊断包增强

`diagnostics-*.zip` 额外包含：

- `qualification_matrix.json`；
- `material_bindings.json`；
- `result_calibrations.json`。

远程排查可以直接判断：模板是否资格通过、材料是否目标库回读成功、Case 使用的 Graph 名称是否完成实机校准。

## 9. 仍未完成的边界

V0.13 当前执行环境没有 Motor-CAD 安装和许可证，因此：

- i5/e9/e14 Level-4 仍需目标 Windows 工作站执行；
- 不存在自动枚举 Graph Viewer 全部名称的官方 API，因此 Result Calibration 仍需要已知候选或工程师从 Graph Viewer 确认名称；
- 全材料数据库枚举/搜索仍不是当前 PyMotorCAD Materials API 的公开能力；
- Lab Map、真实 MeshField、VectorField 仍需实机数据生产。
