# V0.89-G1 — Global Shell + Typography + Copy Cleanup

## 1. Scope

V0.89-G1 is a presentation-layer convergence increment for MotorCAD Studio 0.89.7. It deliberately does not introduce a new motor-domain authority, change engineering lineage, alter database schemas, change Motor-CAD qualification rules, or modify result semantics.

The increment addresses three product defects observed in real operator screenshots:

1. the top engineer status strip could be compressed into the left project column and wrap Chinese text into unreadable fragments;
2. critical workflow and validation text inherited 9–11 px legacy typography and became hard to read at common Windows display scaling;
3. Guided Chinese surfaces still exposed mixed implementation vocabulary and asynchronous English copy even after the language had been switched to Chinese.

The presentation authority is `GlobalShellTypographyCopyConvergenceV1`, contract `0.89-G1`.

## 2. Root causes fixed

### 2.1 Project-shell grid ownership

`#projectShell` is a two-column CSS grid. V0.89-F added the four-cell engineer focus bar after the context/stage rows, but the focus bar did not explicitly span both grid columns. CSS therefore placed it into the first column under some layouts. The visible symptom was the screenshot where “当前位置 / 当前状态 / 需要处理 / 下一步” collapsed into narrow vertical fragments.

G1 makes both the technical breadcrumb and the Guided focus bar explicit full-width grid children:

`grid-column: 1 / -1`.

The focus bar uses four equal columns on normal desktop widths, two columns below 1180 px, and one column below 820 px. The cells have explicit minimum height, readable label/value/detail typography, and horizontal-overflow qualification.

### 2.2 Typography inherited from diagnostic-era components

Several workflow cards, workbench stage tabs, validation hints, result summaries and optimization summaries still used 9–11 px helper text. That was acceptable when these controls were diagnostic/compact panels, but these components are now on the primary engineer path.

G1 defines presentation tokens and Guided overrides:

- base text: 14 px;
- critical secondary/help text: 12–13 px;
- page section title: 19 px;
- card/section title: 16 px;
- workflow primary values: 14 px;
- critical callout/issue text: 14 px;
- toast text: 14 px.

The underlying Expert/Developer evidence density is left unchanged where compact technical metadata is appropriate.

### 2.3 Cached language state in asynchronous preflight

The page language could change to Chinese while asynchronous preflight messages still read a startup-cached `state.language`. This produced combinations such as a Chinese shell with “Starting isolated preflight process…” and “Maximum 60 seconds…” in the live status area.

G1 introduces a live language resolver that prioritizes `window.MCS_I18N.language` at render time. Shallow/deep-preflight messages therefore follow the current UI language even when they are produced after asynchronous requests complete.

### 2.4 Developer vocabulary leaking into Guided copy

The display layer had accumulated terms such as `Design Revision`, `Analysis Revision`, `ResultBundle`, `Case`, `Execution Plan`, `NativeModelSnapshot`, `BindingPlan`, `GeometryTree`, and implementation-oriented explanations. G1 keeps these identifiers in APIs/evidence, while Guided Chinese presents the corresponding engineer concepts:

- Design/Motor Revision → 电机版本;
- Analysis Revision → 分析版本;
- Case → 计算工况;
- ResultBundle → 计算结果;
- Execution Plan → 执行计划;
- Native Binding → Motor-CAD 参数映射;
- GeometryTree → Motor-CAD 原生几何;
- Draft → 未保存修改.

The cleanup covers the project shell, design creation/editing, winding/validation summaries, analysis configuration/monitoring, result workbench, parameter study/optimization and material-library explanatory copy. Expert/Developer evidence panels still expose raw authority names, IDs and hashes.

## 3. Material-library change in G1

G1 only reduces documentation-style material-library copy and makes the source/read-only status easier to understand. It intentionally does **not** change the material picker to 90% viewport size, does not redesign assignment behavior, and does not change magnetic-curve interpolation/physics. Those items remain in V0.89-G3/G4 so presentation cleanup cannot mask functional changes.

## 4. Global copy audit

`global-shell-convergence.js` exposes:

`window.MCSGlobalShellConvergence.audit()`.

In Guided Chinese mode it checks visible primary surfaces for known raw internal terms and untranslated all-English primary actions. Expert/Developer/code/preformatted evidence is excluded. It also checks the full-width focus-bar contract and horizontal overflow.

The audit currently treats Motor-CAD, SPM, IPM, AFPM, BPM, EMag, FEA, rpm, kW, CSV, DOE and Pareto as allowed engineering/product terms.

## 5. Release integration

The V0.89-F `ReleaseCandidateGateV1` remains the RC authority, with contract overlay `0.89-G1`. The automated gate additionally requires:

- unique/version-pinned G1 CSS/JS assets;
- `GlobalShellTypographyCopyConvergenceV1` in the release manifest;
- the G1 backend/static regression to pass;
- the existing fixed-button and browser-error gates to remain green.

The formal Windows/Motor-CAD qualification boundary does not change. A local G1 PASS cannot promote the licensed Windows qualification from 0%.

## 6. Qualification

V0.89-G1 adds seven non-E2E contract tests and three Chromium HMI tests. The HMI checks cover full-width shell ownership, readable computed font sizes, compact 1366×768 layout without horizontal overflow, and the Guided-copy audit. The existing complete-shell browser regression is also extended to run the G1 audit across Design, Analysis and Results routes.

Current final release inventory is recorded in `TEST_REPORT.md` and `RELEASE_MANIFEST.json`.

## 7. Explicit non-goals / next increments

The following user-reported issues remain intentionally outside G1:

- **V0.89-G2** — save/native-check readiness deadlock, disabled-action explanations, save-and-check orchestration;
- **V0.89-G3** — 90% material workspace and explicit material-to-component assignment flow;
- **V0.89-G4** — Nd-Fe-B B-H / Br(T) / HcJ(T) data semantics, sign/unit/ordering and chart rendering;
- **V0.89-G5/G6** — broader page-layout/scroll convergence and multi-resolution visual qualification.

Keeping these boundaries explicit prevents a typography/copy release from claiming that workflow or material-physics defects have already been repaired.
