# V0.89-A — Global Workflow Truth

Release: **MotorCAD Studio 0.89.2 / Schema 45**

## Purpose

V0.89-A closes the gap between the engineer-facing three-stage journey and the persisted engineering object hierarchy. The browser now has one explicit context authority and the backend exposes one workflow-truth payload whose resume chain is derived from a single deepest persisted leaf.

The visible journey remains:

`Design -> Validate -> Decide`

The persisted object hierarchy is:

`Project -> Solution -> Motor Revision -> Analysis -> Analysis Revision -> Execution Plan -> Task -> Case -> ResultBundle`

These are two views of the same workflow. The first is the engineer's stage model; the second is the authoritative lineage model.

## Authorities

- Backend workflow authority: `GlobalWorkflowTruthV1`
- Contract version: `0.89-A`
- Browser engineering context authority: `MCSEngineeringContextV3`
- Browser context schema: `3.0`
- API: `GET /api/projects/{project_id}/workflow-truth`
- Compatibility API retained: `GET /api/projects/{project_id}/engineering-workflow`

## Coherent resume policy

The server no longer selects the newest Solution, Motor Revision, Analysis and Task independently. It selects the deepest available persisted object and derives every ancestor from that object.

Selection priority:

1. ResultBundle
2. Task
3. Analysis Revision
4. Motor Revision
5. Solution
6. Project only

The returned `canonical_context` includes the complete coherent chain and declares `selection_policy=deepest_leaf_then_derive_ancestry`.

This prevents a newer Solution in one branch from being combined with an Analysis or Result that belongs to another branch.

## Browser restore hardening

Persisted descendant IDs in `localStorage` are treated as **resume hints only** after reload. Only the Project ID can be restored directly as current identity.

A stale stored Solution/Motor/Analysis/Task/Case/Result ID therefore cannot silently become authoritative. Descendants are promoted only after a current route or backend lineage validates their ancestry.

Deep Task/Result routes use the same rule: leaf IDs can be held as pending hints, then `MCSResultContext` applies the backend-validated `EngineeringLineage` before they enter the canonical context.

## Context invariants

The browser context enforces these ancestry requirements:

- Solution requires Project.
- Motor Revision requires Project + Solution.
- Analysis requires Project + Solution + Motor Revision.
- Execution identity requires an Analysis Revision before a Task can become authoritative.
- Result identity requires a Task before Case/ResultBundle can become authoritative.

Invalid ancestry is reported by `MCSEngineeringContext.inspect()` and downstream identity is invalidated when an ancestor changes.

## Engineer-facing context breadcrumb

The main shell now renders a persistent read-only breadcrumb showing the currently authoritative:

`Project -> Solution -> Motor Revision -> Analysis -> Task -> Result`

The breadcrumb also reports context-integrity state. This makes the active engineering object visible even while the top navigation continues to use Design/Validate/Decide language.

## Stage gates

`GlobalWorkflowTruthV1` owns the visible top-stage gates:

- Design: requires an active Project.
- Validate: requires a current Motor Revision or backend evidence that the motor stage is complete.
- Decide: requires current result evidence, a completed results stage, or an existing run-center task.

Blocked controls carry an engineer-facing reason such as “请先保存一个电机版本” or “完成一次分析后进入结果与决策”.

## Regression evidence

Dedicated V0.89-A tests verify:

- persisted descendant IDs reload only as resume hints;
- context ancestry remains valid after Solution/Motor transitions;
- stale downstream identity is cleared on ancestor changes;
- visible stage gates follow the canonical context;
- a project containing multiple design branches resumes one coherent lineage chain;
- the new workflow-truth endpoint and compatibility endpoint return equivalent workflow truth.

## Production boundary

V0.89-A changes workflow/context authority only. It does not claim licensed Motor-CAD 2026R1 workstation qualification. The existing V0.88-F native production contract remains the native execution boundary until live Windows evidence is imported.
