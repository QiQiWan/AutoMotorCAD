# V0.89-G4.1 IPM、绕组、材料、性能与模块化修复报告

## 1. 本轮结论

本轮将用户反馈的 7 项问题拆分为四条可独立验证的链路：

1. **设计派生参数**：IPM 磁块显示、匝数—槽满率关系、槽内导体标记；
2. **材料编辑事务**：只读版本进入草稿、材料库选择、草稿保存与新电机版本冻结；
3. **分析工作区读写**：有界加载、单请求编辑包、保存后局部回写；
4. **工程上下文与语言**：对象身份标签、版本标签、单位和动态界面重绘。

本地回归可以证明 Studio 的确定性逻辑、API 载荷边界和浏览器源码合同。IPM 真实磁桥、导体排布、实际槽满率和最终可解性仍以目标 Windows 工作站上 Motor-CAD 原生模型回读与验算为准。

## 3. 匝数—槽满率关系

槽满率不是只由匝数决定。只有在线径、漆膜/绝缘、并绕根数、槽型和压实系数保持不变时，才可近似认为槽内铜面积随匝数线性变化。本轮采用以下相对关系：

\[
k_{fill,new}=k_{fill,base}\cdot
\frac{N_{new}}{N_{base}}\cdot
\frac{s_{new}}{s_{base}}\cdot
\frac{A_{slot,base}}{A_{slot,new}}
\]

其中槽面积仅使用结构化槽口、槽宽、槽深与圆角构造稳定的相对近似。界面提供两种状态：

- **自动联动**：修改匝数、并绕根数或槽尺寸时自动更新；
- **手动值**：用户直接修改槽满率后停止自动覆盖，可显式恢复自动联动。

恢复草稿时，系统会比较草稿槽满率与派生值，重新识别自动/手动状态。若匝数已偏离模板而槽满率仍停留在模板值，本地绕组守卫会提示；估算超过 1.0 时在启动 Motor-CAD 前阻断。

## 4. IPM 重叠判断

截图中的重叠首先是 **Studio SVG 投影错误**，不能直接据此判定 Motor-CAD 原生模型也发生实体相交。旧投影把 V 型两支矩形放在同一局部原点并分别旋转，因此矩形内端必然可能覆盖；磁体宽度还可跨出当前极距。

修复后的显示不变量是：

- 左支腿最内端在 `-bridge/2`，右支腿最内端在 `+bridge/2`；
- `bridge >= 1.15 × 显示厚度`；
- 每支显示宽度不超过单极扇区半弦长的安全比例；
- 多层磁体逐层缩短并径向错开。

若参数要求的磁体宽度超过显示上限，界面明确提示“投影宽度已收敛”，但不回写用户参数。真实模型是否存在磁桥过薄、磁腔相交或制造余量不足，仍由 Motor-CAD 几何检查给出。

## 5. 性能数据流

### 5.1 旧路径

`项目 → 每个方案的全部电机版本 → 每条分析的全部历史版本 → 输入目录 → 建议 → 保存后再重复读取`

其时间和响应体会随不可变历史持续增长，且多次解码相同 JSON。

### 5.2 新路径

`analysis-workspace → 每个方案最新电机版本 + 当前引用旧版本 → 打开某分析时读取 editor bundle → 保存后直接回写 bundle`

新合同具备以下约束：

- 项目引导载荷中，每个方案默认只返回最新电机版本；
- 当前分析引用或路由选中的旧版本始终保留，不破坏谱系；
- 分析列表每条只带最新分析版本；
- 编辑接口一次返回分析定义与输入目录；
- 保存建议刷新采用去重延后，不阻塞按钮完成；
- 设计提交使用已返回的新版本，不再同步重取完整项目图；
- Draft 幂等重放按提交键走 SQLite JSON 索引式查询，不再逐条解码历史。

## 7. 深化迭代方案

### G4.2：路由与读模型拆分

- 将 `main.py` 按 projects、solutions、analysis、runtime、results、materials 拆为 `APIRouter`；
- 为列表/工作区建立只读 DTO，禁止默认携带全部历史大字段；
- 为 bootstrap、editor bundle、history endpoint 增加响应大小与 SQL 次数基准。

### G4.3：领域服务与仓储接口

- 将分析定义、输入域、模板/建议从 `EngineeringPlatform` 拆为独立服务；
- Repository 只返回领域记录，不拼 UI 文案；
- 兼容字段集中到 adapter，禁止在新模块继续传播 `design_id/solution_id` 双词汇。

### G4.4：前端控制器拆分

- 将分析五步拆为 definition/operating/inputs/solver/check controller；
- 将设计编辑器拆为 parameter transaction、material transaction、verification orchestration；
- 每个控制器只通过 store/client 协作，禁止直接全局读取另一页面 DOM。

### G4.5：Motor-CAD 端口与资格

- 定义 `MotorCADPort`：bind、validate geometry、regenerate winding、solve、readback、cancel；
- Mock/Windows COM/API 实现共享同一合同测试；
- 以 SPM/IPM/AFPM 各自的合法/非法槽极组合、磁桥极限、槽满率边界建立实机 Golden Cases。

### G4.6：持续质量门禁

- 中文和英文各渲染一次主流程，扫描非技术性混搭文本；
- 建立 1/20/100 方案 × 1/20/100 历史版本性能基准，记录 P50/P95、SQL 次数和响应字节；
- 将 IPM 不相交、槽满率联动、材料可编辑、保存请求数和工作区历史边界纳入 CI。

## 8. 验收边界

本轮可在本地验收：

- IPM 投影两支磁块具有非零铁桥并受极距约束；
- 96 匝以内槽图标记数与匝数一致；
- 固定导体假设下 6 匝/0.4 改为 9 匝时派生为约 0.6；
- 手动槽满率不会被继续覆盖，且可恢复自动联动；
- 材料只读页可进入草稿，草稿内可调用材料库并写入材料绑定；
- 多历史版本项目的工作区只返回最新版本和被引用旧版本；
- 编辑保存响应只包含最新分析版本，且不阻塞等待建议刷新；
- 工程上下文、版本标签和 `turn/ratio` 单位经过语言权威。

必须在目标工作站补齐：Motor-CAD 原生 IPM 几何不相交、实际槽满率、绕组重建成功、材料名能够绑定到目标 `.mdb`，以及完整电磁/热求解通过。
