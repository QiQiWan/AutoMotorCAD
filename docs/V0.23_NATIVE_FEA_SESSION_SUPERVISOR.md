# MotorCAD Studio V0.23.0 — Native FEA Evidence 与 Motor-CAD Session Supervisor

## 1. 本轮定位

V0.22 已经把项目内流程收敛为“概览 → 模型 → 计算 → 求解过程 → 结果 → 数据”，并加入求解运动示意与 Motor-CAD 结果曲线回放。V0.23 继续处理两个更深层问题：

1. 求解过程中的动画必须逐步从“过程示意”升级为可追溯的 Motor-CAD 原生有限元证据；
2. Motor-CAD 不能继续被当作一个无状态 Python 函数调用，需要明确 Session、PID、Case Owner、内存和释放状态。

本轮仍坚持一个原则：如果当前工作站的 `save_fea_data()` 导出格式无法被 Studio 解析，界面只显示“已保存原始证据”，不会根据几何示意伪造 B / Pt 场云图。

## 2. 与 Motor-CAD 可视化链路的差距

Motor-CAD FEA Display 可以显示有限元 shading、mesh、equipotential、vectors，并可重新打开已有结果进行动画回放。Studio V0.22 的实时监控虽然已经有转子运动和 TorqueVW / B Gap 回放，但仍有三个差距：

- 求解中的运动图主要是进度/拓扑示意，不能作为真实有限元场证据；
- 完成后主要展示 Graph 数据，没有持久化节点/场级证据；
- Case 与 Motor-CAD 实例之间缺少显式 ownership，残留进程很难判断属于 Studio、用户手动打开还是历史异常。

V0.23 将这三个问题拆成“过程动画 / Native FEA / 结果曲线”三个明确层级。

## 3. Native FEA Evidence

### 3.1 求解后原生导出

EMag 求解完成后，Studio 使用 PyMotorCAD 官方 `save_fea_data()` 尝试导出当前 FEA solution：

```text
Case work_dir/
└─ native_fea/
   ├─ native_fea_manifest.json
   ├─ native_fea_raw.csv
   └─ frames/
      ├─ frame_0000.json
      ├─ frame_0001.json
      └─ ...
```

默认请求字段：

```text
RegCode, X, Y, B, Pt
```

并记录：

- Motor-CAD version；
- source MOT SHA-256；
- raw CSV SHA-256；
- first/final step；
- 原始列名；
- 坐标/场列识别结果；
- 每帧原始点数与显示采样点数；
- 全局 B/Pt 数值范围。

### 3.2 导出失败不反向污染求解状态

FEA Evidence 属于结果证据增强层。Motor-CAD 已经完成工程求解后，如果 FEA 导出失败：

```text
execution_status = SUCCEEDED
native_fea.status = WARNING / UNAVAILABLE
```

不会把成功 Case 改成 FAILED。

这与 Output Mapping 的处理原则一致：求解器执行状态、结果完整性和可视化证据完整性必须分开表达。

### 3.3 兼容未知 CSV 格式

`normalize_fea_csv()` 同时兼容普通分隔表和 Motor-CAD 官方示例所展示的 `ElementsTable / NodesTable / RegionsTable` 原生表结构。V0.23 默认显式请求 `RegCode,X,Y,B,Pt`；其中 X/Y 是浏览器重建空间位置所必需，不能只请求 B/Pt。解析器支持 `Bx/By -> |B|`。如果没有找到 X/Y 等必要坐标：

```text
native_fea.status = RAW_ONLY
```

原始 CSV 仍保存到 Case artifact，浏览器显示“原始证据可下载”，不生成虚假场数据。

## 4. 浏览器 Native FEA Viewer

求解过程页面现在明确分为：

```text
[实时过程] [原生 FEA] [结果曲线]
```

### 实时过程

继续显示：

- 当前 Case；
- 当前真实 stage/progress；
- 当前机器槽/极拓扑；
- 转子运动；
- Validation / EMag / Thermal 阶段状态。

这一层用于“知道求解走到哪里”，不宣称是节点场云图。

### 原生 FEA

Case 完成且 `native_fea_manifest.json` 可解析时：

- Canvas 绘制真实 Motor-CAD 导出点；
- B / Pt 切换；
- Step slider；
- Play / Pause；
- 每帧显示点数 / 原始点数；
- 全局统一色标，避免每帧自动缩放造成视觉误判。

### 结果曲线

继续保留 TorqueVW、Air-gap B 等 Motor-CAD Graph 数据回放。

## 6. Motor-CAD Session Supervisor V1

V0.23 新增 `motorcad_sessions` 表，Schema 升级到 14。

每次真实 Motor-CAD Case 会生成：

```text
motorcad_session.json
```

主要字段：

```text
Session ID
Task ID
Case ID
Worker PID
Motor-CAD PID / child processes
Motor-CAD Version
PyMotorCAD Version
State
Ownership Mode
Reuse Requested
Reuse Effective
RSS Peak
Jobs Completed
Started / Updated / Released
```

运行状态会经历：

```text
ALLOCATING
→ READY
→ VALIDATED
→ SOLVING
→ EXPORTING_FEA
→ EXTRACTING
→ COMPLETED
→ RELEASED
```

监控层因此可以区分：

1. Studio 当前 Case 拥有的 Motor-CAD 进程；
2. Studio 已释放但进程仍残留；
3. 用户手动启动、没有 Studio ownership evidence 的 Motor-CAD 进程。

第三类不会被武断标为“孤儿进程”。

## 7. 一个重要的运行时修复：短生命周期 Worker 禁止假复用

当前 Studio 的求解隔离模型是：

```text
TaskManager
   ↓
每个 Case 新建一个 multiprocessing child
   ↓
child 创建 PyMotorCAD object
   ↓
Case 完成
   ↓
child 退出
```

PyMotorCAD 提供 `reuse_parallel_instances` 和 `keep_instance_open`，但真正的跨 Case 热复用需要一个持续存在的 Python Owner。把 `keep_instance_open=True` 放在一次性 Case child 中，会出现“Motor-CAD 被标记 free，但原 Owner 已退出”的生命周期错位风险。

因此 V0.23 对 Case Worker 做了明确收敛：

```text
reuse requested = 可记录
reuse effective = False
ownership = isolated_case
Case 完成 = quit + release
```

如果用户环境变量请求复用，日志会产生：

```text
MOTORCAD_REUSE_DEFERRED
```

说明复用请求已记录，但在持久 Worker Pool 上线前，本次 Case 仍冷释放。

这属于正确性优先的处理。真正的实例池应由后续常驻 Worker/Supervisor 持有 Motor-CAD 对象，再使用 PyMotorCAD 的 free/reuse 语义。

## 8. 当前仍未宣称实现“阻塞求解期间的真实节点场流”

PyMotorCAD 公开 API 已明确提供：

- `save_fea_data()`；
- `get_fea_graph()` / `get_fea_graph_point()`；
- 连接/复用 Motor-CAD 实例的构造选项。

但在当前公开文档范围内，没有足够依据证明：一个 Client 正在阻塞式 `do_magnetic_calculation()` 时，第二个 JSON-RPC Client 可以持续、安全读取同一实例不断更新的所有 FEA 节点场。

因此 V0.23 的产品语义是：

```text
求解中：真实 Stage/Progress + 模型运动示意
求解后：真实 Motor-CAD FEA raw evidence + 帧回放
```

下一步必须在 Windows + Motor-CAD 2026R1 工作站做并发 RPC contract experiment，再决定是否开启真正的 in-solve field streaming。

## 10. 实机验收重点

在目标 Windows 工作站验证：

1. `save_fea_data()` 对 i5 / e9 / e14 的实际 CSV 列结构；
2. first_step / final_step 的版本边界；
3. B / Pt 数值和 Motor-CAD FEA Display 的一致性；
4. 采样后 Canvas 色标和场分布是否保持工程可判读性；
5. Case 结束后 Motor-CAD PID 是否稳定退出；
6. 连续 100 Case 是否仍出现残留 Motor-CAD；
7. 同一工作站并发 RPC read-only contract 是否安全。
