# MotorCAD Studio V0.20.0：可路由引导流程、随动示意与模型提交门禁

## 1. 本轮目标

V0.20.0针对V0.19.0操作流程继续收敛，重点处理六类问题：

1. 页面样式与中英文混排可读性；
2. 所有主要操作状态建立可复制、可刷新、可前进后退的URL路由；
3. 恢复Design Revision参数编辑页的随动电机示意图；
4. 仿真五步配置均提供随动示意和中文解释，帮助内容使用页内非阻塞浮层；
5. 统一Studio预检与Motor-CAD原生模型检查的提交判定，禁止“界面提示未通过但仍能提交”的状态；
6. 根据本次诊断包和PyMotorCAD官方自动化建议降低运行期报错与日志噪声。

## 2. 本次诊断包确认的真实失败链

### 2.1 当前Design Revision本身存在历史数据问题

项目 `PRJ-5095E987EF` 的历史Design Revision `DRV-46230BBFF9` 保存了 `slot_count=17`。i5模板的三相、单并联支路关系下：

```text
17 / 3 / 1 = 5.666666...
```

因此该Revision的槽/相/支路关系本身不满足整数约束。旧版“保存新不可变Revision”没有执行与Task一致的模型关系校验，这是一个数据完整性缺口。

V0.20.0在 `POST /api/designs/{design_id}/revisions` 增加服务端模型关系门禁。新Revision在持久化前会合并模板默认值和用户修改，执行几何/绕组确定性检查；存在BLOCKING问题时返回HTTP 422并写入 `DESIGN_REVISION_MODEL_BLOCKED` 审计事件。历史Revision仍保留用于追溯，不原地改写。

### 2.2 17 -> 24槽的任务失败于Motor-CAD原生几何约束

历史Task `TASK-2A709AB01F` 将槽数临时覆盖为24。Motor-CAD原生日志明确报告：

```text
The current value of Slot Opening is not possible within the current machine constraints.
Regions "Stator" and "StatorAir" intersect.
Geometry check failed.
```

允许Motor-CAD尝试几何恢复后，又报告：

```text
Regions "CoilDivider" and "Liner" intersect.
Geometry check failed.
```

因此24槽不能仅凭“24/3为整数”判断可解；槽数与槽口、齿宽、槽深、定子尺寸等几何参数存在强耦合。

### 2.3 17 -> 18槽的最新任务失败于槽满率

最新Task `TASK-A2D154252C` 将槽数覆盖为18。18槽通过了三相整数关系，但Motor-CAD原生MessageLog继续给出：

```text
Slot fill = 1.41 should not be > 1
The Slot Fill or Conductors/Slot must be reduced
```

这是真实模型约束失败。可行修复方向包括降低每槽导体/匝数或等效铜占用，或调整槽面积相关几何；不能把18槽直接视为可行设计。

### 2.4 截图中“预检通过”与“模型可解性未通过”为什么同时存在

V0.19.0存在两套判定：

- `/api/validate`：检查任务结构、参数映射、Studio侧确定性规则等；
- Motor-CAD Runtime Model Check：把当前参数真正写入Motor-CAD后执行原生几何/绕组检查。

旧界面把第一层 `valid=true` 显示为“预检通过”，同时下方原生检查已经FAIL；提交按钮仍可能保持可用。用户看到的是相互冲突的状态。

V0.20.0改为统一“提交门禁”：

```text
Design Revision存在
    AND Studio任务校验通过
    AND Studio确定性几何/绕组检查无BLOCKING
    AND Motor-CAD原生模型检查PASS
    AND 原生PASS对应的参数指纹仍与当前配置完全一致
    => 才允许提交
```

任何参数、材料、工况、分析类型或Revision发生变化，Motor-CAD PASS立即失效，必须对新配置重新检查。

## 4. Design Revision参数页：恢复随动示意图

新的Revision编辑器使用双栏结构：左侧是参数分组，右侧是sticky随动示意和模型关系状态。

参数修改后：

1. 示意图立即按槽数、极数、定转子主要尺寸、气隙等参数更新；
2. 维度摘要同步更新；
3. debounce调用Studio geometry-precheck；
4. BLOCKING问题以中文根因卡显示；
5. 存在BLOCKING时禁用“保存为新Revision”；
6. 提供“恢复模板可行基线”动作，但不会修改历史Revision。

该机制将“设计定义是否合法”前移到Design阶段，减少进入Task Builder以后才发现基础模型不可行的情况。

## 5. 仿真五步引导

每一步都有独立URL、随动示意和中文说明：

### 第1步 基线

显示当前Design Revision、主要几何和绕组参数的电机随动示意。强调长期设计变化应回Design创建新Revision。

### 第2步 工况

显示环境、冷却、速度/电流等工况概念示意，说明Scenario与Design Revision的职责边界。

### 第3步 计算方式

显示 `Revision -> Case生成 -> Motor-CAD求解` 流程，根据Single/Sweep/DOE/Optimization配置更新。

### 第4步 输出

显示Motor-CAD求解结果进入结果提取与数据管线的示意，并同步选中输出数量。

### 第5步 检查提交

显示 `Studio Gate -> Motor-CAD Native Gate -> Submit`。失败时直接显示最高优先级根因、当前参数差异和可执行修复动作。

“查看本步配置说明”统一使用页内Sheet。项目删除等确认操作也迁移到页内Dialog；前端不再调用浏览器原生 `alert/confirm/prompt`。

## 6. Motor-CAD自动化实现对齐

V0.20.0对Motor-CAD模板资格检查进一步采用与PyMotorCAD官方文档一致的运行方式：

- 使用PyMotorCAD RPC接口控制Motor-CAD；
- 自动化改参前切换到 `Scripting` 页面，避免正在显示的输入页与自动写参发生UI耦合；
- 设置 `MessageDisplayState=2` 并调用 `disable_error_messages(True)`（API可用时），阻止Motor-CAD原生模态错误窗口卡住自动化；
- 检查前清理MessageLog，检查后通过 `get_messages(0)`读取原生消息并结构化保存；
- `check_if_geometry_is_valid(0)`用于不修改几何的检查，必要时才调用 `(1)`尝试约束内恢复；其返回值表示是否执行过reset attempt，不能被当作“整机几何有效”的唯一Boolean；
- 原生几何、绕组FAIL会以结构化check返回，并写入 `MODEL_RUNTIME_CHECK.root_cause`。

参考：

- https://motorcad.docs.pyansys.com/
- https://motorcad.docs.pyansys.com/version/stable/user_guide/troubleshooting.html
- https://motorcad.docs.pyansys.com/version/stable/methods/_autosummary_Geometry/ansys.motorcad.core.motorcad_methods.MotorCAD.check_if_geometry_is_valid.html
- https://motorcad.docs.pyansys.com/version/stable/examples/basics/emag_basics.html

## 7. 日志与报错噪声修复

### 7.1 `no such table: cases`

本次诊断包有连续 `SYSTEM_STREAM_ERROR` 和 `OFFLINE_DIAGNOSTIC_WRITE_FAILED`，根因为活动服务遇到数据库替换/初始化窗口时查询 `cases` 表。

V0.20.0在数据库只读查询层对 `OperationalError: no such table` 增加一次schema initialize + retry。该策略只处理schema缺失窗口，不吞掉其他SQLite错误。

### 7.2 已删除/过期Task持续404

日志中存在客户端持续轮询 `TASK-38046F5650` 的summary/cases/events并产生重复404。V0.20.0检测到监控Task 404后立即停止该Task实时通道，清除陈旧选择，只显示一次“任务不存在”，并把路由替换到监控入口。

### 7.3 原生Root Cause结构化

模板/模型runtime check的审计事件现在同时记录：

```text
geometry
winding
parameter_roundtrip
checks[]
root_cause
```

根因不再只存在于Python traceback或Motor-CAD MessageLog文本中。前端统一门禁直接消费结构化root cause。

## 8. 当前项目数据的推荐修复路径

历史Revision `DRV-46230BBFF9` 不应原地修改。推荐：

1. 打开该Revision的“编辑/创建新Revision”路由；
2. 点击“恢复模板可行基线”，先回到已知基线（当前模板为12槽）；
3. 按真实设计意图逐项修改，并观察随动示意和Studio确定性检查；
4. 保存为新的不可变Revision；
5. 进入仿真五步配置；
6. 在第5步执行“完整检查”；
7. 只有Motor-CAD原生检查对当前配置指纹返回PASS后才提交Task。

若坚持18槽，需要继续降低Motor-CAD报告的槽满率1.41，例如检查Conductors/Slot、Turns、线径/铜占用和槽面积相关几何。若采用24槽，需要先解决Slot Opening约束以及Stator/StatorAir、CoilDivider/Liner相交，不能只修改槽数。

另外，当前诊断中出现 `thermal_transient` 能力未实机验证提示。若本次目标是E-Magnetic计算，应在计算方式/分析配置中选择对应的已验证E-Magnetic recipe；能力未验证会继续作为明确的资格提醒显示。
