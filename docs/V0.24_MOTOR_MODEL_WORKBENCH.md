# MotorCAD Studio V0.24.0 — Motor Model Workbench

## 1. 本轮目标

V0.23 已经建立真实 Motor-CAD Case、Native FEA Evidence 和 Session ownership，但模型编辑仍主要表现为参数表单。V0.24 将 Design Revision 编辑升级为连续的 Motor Model Workbench，使操作员围绕“同一台电机”处理参数、几何、绕组、约束和原生证据。

本轮没有把 Studio 快速示意包装成 Motor-CAD 原生几何。即时预览、Studio 静态约束和 Motor-CAD 原生证据始终分层显示。

## 2. 新工作台结构

```text
参数/Region 树             模型与参数编辑                  约束与证据
────────────────────────────────────────────────────────────────────
拓扑                     快速几何                         当前约束
几何                     绕组关系                         参数依赖
永磁体                   Motor-CAD 证据                  上一可行基线
绕组                     版本对比                         原生 Case 证据

点击 Region  ───────────→ 定位参数
点击参数     ───────────→ 高亮相关模型区域
修改参数     ───────────→ 随动示意 + debounce 预检查
点击错误     ───────────→ 定位相关参数 + 恢复建议
```

### 四个中央视图

1. **快速几何**：由当前编辑值驱动槽数、极数、气隙、定子尺寸、齿槽尺寸和磁钢参数的即时示意，并显示主要尺寸与派生关系。
2. **绕组**：显示相/槽/并联支路的关系与整数约束。该图只承担关系解释，不替代真实 coil go/return slot 定义。
3. **Motor-CAD 证据**：关联最近真实 Case 的 `model_validation.json`、pre-solve MOT、Native FEA manifest/raw data 和真实绕组文件。
4. **版本对比**：当前编辑值与上一可行 Revision；若没有历史可行 Revision，则与模板可行基线比较。

## 3. Parameter Dependency Graph

新增 `config/model_workbench.yaml`，用于定义：

- 参数类别与中文标签；
- 参数对应的模型 Region；
- 参数变化会影响的工程量；
- 关联参数；
- Studio / Motor-CAD 错误码到参数与 Region 的映射。

例如 `slot_count` 当前被映射到：

```text
槽数
 ├─ 定子槽
 ├─ 绕组
 ├─ 槽距
 ├─ 齿宽/槽宽关系
 ├─ 每相每支路槽数
 ├─ 槽满率
 └─ 绕组因数
```

这使“错误 → 参数”成为正式配置数据，而非散落在前端文案里的硬编码判断。

## 4. 新工作台 API

```text
GET  /api/design-revisions/{revision_id}/workbench
POST /api/design-revisions/{revision_id}/workbench/precheck
```

`GET` 返回：

- Design Revision 元数据；
- 工作台参数及 Motor-CAD Automation candidate；
- Region/依赖关系；
- 当前 Studio precheck；
- 上一可行基线；
- 最近 Motor-CAD Case 原生证据。

`POST` 对当前编辑值执行即时模型关系检查，并为每项问题补充：

```text
parameter_ids
region_ids
parameter_context
repair_actions
```

典型 16 槽三相 1 并联支路问题会直接绑定到 `slot_count / parallel_paths / pole_count`，并提供恢复上一可行值/模板基线的动作数据。

## 5. 原生绕组证据

真实 Motor-CAD 模型完成几何/绕组验证后，Solver 会 best-effort 调用：

```python
mc.save_winding_pattern(...)
```

并把实际 `winding_pattern.txt` 注册成 Case Artifact。工作台能够直接查看或下载该文件。

因此界面明确区分：

```text
Studio 绕组关系图       → 快速理解与静态约束
Motor-CAD winding file → 实际原生绕组定义证据
```

导出失败只记录 `winding_pattern_export_error`，不会把已经通过的求解错误改判为失败。

## 6. Motor-CAD Region intersection 深化诊断

旧几何解析重点识别 `Stator / StatorAir` 相交。V0.24 增加通用：

```text
Regions "A" and "B" intersect
```

解析，生成：

```text
MOTORCAD_REGION_INTERSECTION
regions = [A, B]
related_parameters = [...]
```

因此此前出现过的：

```text
Regions "CoilDivider" and "Liner" intersect
```

现在会被映射到槽、绕组、匝数和槽满率等相关变量，工作台可直接定位字段。

同时补齐 `MOTORCAD_FEA_ABORTED_BY_WINDING` 的工作台绑定，使 FEA 后果错误继续向上追溯到绕组根因。

## 7. Revision 编辑和对话框

原 `workspaceEditRevision` 会优先打开 V0.24 工作台。深链接 `/revisions/{revisionId}/edit` 同样恢复工作台。

保存继续遵循不可变 Revision 规则：只有存在真实变更且 Studio BLOCKING 约束清零后才能保存。Revision 说明使用 Studio 页内 Sheet；Dialog action 新增 `getValue()` 能力，可在非阻塞浮层关闭前读取表单内容，不使用浏览器原生 alert/confirm/prompt。

## 8. 证据权威层级

V0.24 页面固定显示：

```text
L0 Studio 即时参数示意
L1 Studio 静态模型关系检查
L2 Motor-CAD 原生几何 / 绕组证据
L3 Motor-CAD 真实求解
L4 Native FEA / Result Quality
```

低层级检查不会覆盖高层级证据。历史 Case 结果也不会冒充“当前尚未提交的编辑值已经通过 Motor-CAD”。

## 10. 实机边界

当前 Linux 测试环境无法启动 Windows Motor-CAD 2026R1。因此 `save_winding_pattern()` 的真实文件内容、原生 Geometry Screen 和目标模板的全部 Region/coil 索引仍需在 Motor-CAD 工作站验收。

V0.24 对无法验证的原生内容保持 evidence-only/unknown，不会生成伪造的原生状态。
