# V0.18 日志驱动修复与交互重构

## 1. 本轮目标

本轮以用户提供的诊断包和启动页截图为依据，集中处理四类问题：

1. `浏览本机…` 无法可靠调起 `Motor-CAD.exe` 文件选择窗口；
2. 最新一次真实求解已经成功，但 Task 最终仍显示 FAILED；
3. Motor-CAD 安装路径配置出现得太晚，首次启动流程缺少明确 Runtime Gate；
4. Project 仅作为顶部下拉上下文存在，项目入口、管理能力和工程层级感不足。

V0.18 将信息架构收敛为：

```text
Studio Runtime
  └─ 启动配置 / Motor-CAD Gate

Project Management
  └─ Project
      ├─ Design / Design Revision
      ├─ Scenario Revision
      ├─ Task / Case
      ├─ Result Viewer
      └─ Data Factory
```

## 2. 最新日志结论：求解成功被 Windows Pipe 关闭误判为失败

诊断包中最新 Task 为 `TASK-CB30898B81`，Case 为 `TASK-CB30898B81-C0001`。关键事件顺序：

| seq | event | 结论 |
|---:|---|---|
| 187 | `TASK_CREATED` | Task 创建成功 |
| 189 | `TASK_STARTED` | Task 开始执行 |
| 192 | `LICENSE_ACQUIRED` | EMAG / THERMAL 许可证已获取 |
| 194 | `SOLVER_CHILD_START` | 隔离子进程启动 |
| 197 | `SOLVER_RUN_BEGIN` | Motor-CAD 求解开始 |
| 199 | `SOLVER_RUN_SUCCESS` | 子求解器已经成功完成 |
| 200 | `CASE_FAILED` | 父进程出现 `BrokenPipeError: [WinError 109] 管道已结束` |
| 204 | `TASK_FINISHED: FAILED` | 成功结果被最终状态覆盖为失败 |

`task_state.json` 的 traceback 指向 `runtime/solver_process.py` 中对 `parent_conn.poll(0)` 的再次调用。在 Windows 上，子进程已经发送 final frame 并关闭 Pipe 后，`multiprocessing.connection.poll()` 会进入 `_winapi.PeekNamedPipe()`；此时 Pipe 已结束即可抛出 WinError 109。

因此这次故障发生在求解结束后的父子进程 IPC 清理阶段，不能据此判断 Motor-CAD 求解失败。

### 修复

`SolverProcessRunner` 的规则调整为：

- 仅在 `final_payload is None` 时继续读取 Pipe；
- 一旦收到 final frame，立即停止后续 `poll()`；
- 退出宽限阶段捕获 `EOFError / BrokenPipeError / OSError`，按 Pipe 已正常结束处理；
- 保留 timeout、cancel、子进程异常和缺失 final frame 的真实失败判断。

新增回归测试模拟 Windows 行为：第一次 `poll()` 返回 final frame，第二次 `poll()` 直接抛 `BrokenPipeError(109)`。测试要求 Runner 最终返回 SolverResult，且 `poll_calls == 1`。

## 3. `浏览本机…` 不弹窗：修复路径

Web 页面本身不能通过普通 `<input type="file">` 获取用户电脑上的真实完整可执行文件路径。MotorCAD Studio 为本机 Windows 服务，因此继续采用服务端 PowerShell 调用 WinForms 文件选择器，同时补齐窗口激活和故障诊断。

### 后端

`MotorCADInstallationManager.browse_native()` 当前执行：

1. 检查 Windows 平台和 PowerShell 可用性；
2. 创建 WinForms owner Form；
3. 设置 `TopMost = true` 并主动 `Show()` / `Activate()`；
4. 使用 `OpenFileDialog.ShowDialog(owner)`，降低弹窗隐藏在浏览器后面的概率；
5. 使用 `MCS_PATH=...` 标记解析选中路径；
6. 返回 `backend / returncode / reason / stderr / cancelled`；
7. 成功后直接持久化 Studio runtime selection。

API 同时写入：

- `NATIVE_EXE_BROWSER_REQUESTED`
- `NATIVE_EXE_BROWSER_RESULT`

便于下一次诊断直接确认“请求是否到达后端、PowerShell是否启动、用户是否取消、选择是否成功”。

### 前端

点击“浏览本机…”后：

- 按钮切换为“等待选择…”并暂时禁用，防止重复创建多个 Dialog；
- 明确提示查看任务栏 / `Alt+Tab`；
- 用户取消时显示“已取消文件选择”；
- PowerShell失败时把后端 `reason/stderr` 显示到页面；
- 仍保留直接粘贴 EXE 完整路径的兜底方式。

### 路径优先级修正

原逻辑可能导致用户刚完成手动绑定，运行时仍被 `MOTORCAD_STUDIO_MOTORCAD_EXE` 或 `MOTORCAD_EXE` 环境变量覆盖。V0.18 调整为：

```text
Studio 手动持久化绑定
  > MOTORCAD_STUDIO_MOTORCAD_EXE / MOTORCAD_EXE
  > 自动发现
```

清除 Studio 绑定后才回退环境变量。

## 4. 启动页重构

V0.18 将 Motor-CAD 配置放到第一个页面，并在启动时自动执行浅检查。

首屏包含：

- 安装扫描；
- 当前选中版本和路径；
- 手工 EXE 绑定；
- 本机浏览；
- 浅检查；
- 深度 Motor-CAD / PyMotorCAD / RPC 检查；
- Runtime 状态卡；
- “进入项目管理”下一步入口。

系统诊断页继续保留高阶能力，包括 API Capability、Automation Registry、Qualification、Calibration、运行健康度等，不再重复承担基本安装路径配置。

## 5. Project Management 重构

### 5.1 删除顶部项目切换器

顶部原项目 `<select>` 容易让 Project 看起来只是一个普通过滤条件，也允许用户在任意业务页面突然改变上下文。V0.18 移除该切换器。

顶部只保留紧凑的“当前项目”状态按钮。点击它会返回“项目管理”，不会直接切换项目。

### 5.2 独立项目管理页

项目管理页提供：

- 项目总览指标；
- 项目名称 / ID / 说明；
- Designs / Scenarios / Tasks 数量；
- 新建并进入项目；
- 基本信息编辑；
- 软删除到回收站；
- 回收站恢复；
- “进入项目”明确动作。

新增后端能力：

- `PATCH /api/projects/{project_id}`：更新名称/说明；
- Project list 返回对象计数，避免前端为每个项目重复请求多个统计接口。

### 5.3 项目级页面 Gate

`项目驾驶舱 / 项目工作区 / 模板 / 新建任务 / 实时监控 / 任务中心 / 结果查看器 / 数据工厂` 均标记为 project-scoped。

没有 active Project 时：

- 项目级导航禁用；
- 强制直接打开项目级 tab 时自动返回项目管理并提示；
- Task Builder 和 Workspace 不再提供内部项目选择器。

进入项目后，这些页面复用同一套控制面板，并固定继承 active Project。需要切换时返回项目管理页。

## 6. 其他日志项的处理判断

### `/favicon.ico -> 404`

属于无业务价值的浏览器自动请求，之前会进入结构化问题中心。V0.18 直接返回 204，降低噪声。

### `/api/materials/catalog -> 404`、`/api/result-viewer/catalog -> 404`

这些记录来自更早会话。当前代码已经存在相应能力并有版本 / client-contract 机制防止前后端缓存错配。最新会话已经越过这些阶段并完成真实求解，不再把它们作为本轮主故障。

### `StructuredLogStore.log()` 参数错误

同样来自较早会话，当前实现已经修正。V0.18 保留现有 observability 回归测试，不重复引入第二套日志接口。

### e14 Slot Opening / `Stator` 与 `StatorAir` 相交

这是前序真实几何约束问题。已有版本已经增加 AFPM Slot Opening 保护、几何检查、自动恢复差异审计和 `model_validation.json`。本次最新日志已经出现 `SOLVER_RUN_SUCCESS`，说明当前阻断点已经转移到求解后 IPC，不应再把 WinError 109归因于几何失败。

### “无活动 Worker 但检测到 Motor-CAD 进程”

当前代码只记为信息型 `MOTORCAD_PROCESS_PRESENT_NO_WORKER`，不会仅凭“看到 Motor-CAD 进程”判定 orphan。用户手工打开的 Motor-CAD 或正在退出的实例均可能符合该状态。

## 8. 真实 Windows 工作站建议验收顺序

1. 启动 V0.18，确认第一屏为“启动配置”；
2. 点击“浏览本机…”，确认文件选择器在前台出现；
3. 选择正确 `Motor-CAD.exe`，确认路径持久化；
4. 重启 Studio，确认手工绑定仍优先；
5. 执行浅检查，再执行深度检查；
6. 进入项目管理，新建项目、修改名称/说明、退出并重新进入；
7. 验证项目级页面不能直接切换 Project；
8. 运行此前可触发 `TASK-CB30898B81` 类问题的 Case；
9. 确认出现 `SOLVER_RUN_SUCCESS` 后 Case 保持 COMPLETED，不再生成 WinError 109；
10. 打包新的诊断 ZIP，确认浏览事件、Runtime Gate、Case 时间线均完整。
