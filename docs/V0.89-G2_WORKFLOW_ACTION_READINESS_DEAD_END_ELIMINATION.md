# V0.89-G2 - Workflow Action Readiness and Dead-end Elimination

Release target: MotorCAD Studio 0.89.9 / Schema 45

## Scope

V0.89-G2 makes every engineer-facing primary action explicit about four states:

- READY: executable now.
- BLOCKED: prerequisite missing; a concrete recovery action is mandatory.
- IDLE: disabled because no work is required; this is not a workflow blocker.
- BUSY: an operation is already in progress; duplicate submission remains suppressed.

A BLOCKED action without an executable recovery path is a release-gate dead end. A visible primary action without a readiness rule is an unmanaged primary and also fails the G2 release gate.

## Authority

`WorkflowActionReadinessAuthorityV1`, contract `0.89-G2`, is implemented in `static/workflow/action-readiness.js` and rendered by `static/action-readiness.css`.

The authority owns the disabled state only when it has enough domain information to make the decision. It records:

- readiness status;
- blocker message;
- reason code;
- recovery kind and target;
- whether the recovery target is executable;
- dead-end status.

The HMI qualification registry exports the same fields so release evidence and user-visible state come from the same source.

## Primary action coverage

The source-template audit covers project creation/editing, Solution and Motor entry, Design save/native validation, Analysis creation/step/save/check/submit, Task result/retry, Result loading/comparison, optimization and promotion, qualification campaigns, requirements, decision actions, material save/assignment, system preflight, Native qualification, and modal primary actions.

Static and dynamic primary button templates are checked by the G2 test contract. New future primary actions fail as `UNMANAGED` until they are registered.

## Dead-end repairs

Key closed paths include:

1. Project create updates readiness synchronously when the name is entered. There is no transient disabled window after the prerequisite has been supplied.
2. Project basic-info save reports IDLE when nothing changed and BLOCKED with focus recovery when the name is invalid.
3. Design save reports IDLE when no design changes exist; Draft conflicts expose an explicit reload recovery.
4. Motor-CAD Native Check exposes Studio precheck and first-blocker recovery. The G1R clean-Draft transaction bootstrap remains the underlying save/check deadlock repair.
5. Analysis creation requires a saved Motor Revision and routes back to Motor Configuration when missing.
6. Analysis submit walks an explicit chain: Analysis -> Execution Plan -> blocking fixes -> full Motor-CAD check -> submit.
7. Result load/compare actions expose Task/Case selection recovery instead of opaque disabled buttons.
8. Optimization submit requires a preview; blocked previews link to the preview result; candidate promotion requires validation and treats the baseline as IDLE.
9. Material-save and Automation import actions focus the missing input immediately.
10. Task results use retry/refresh recovery when formal result cases are not yet available.

## User-visible presentation

Blocked primary actions render an inline warning with a 13-14 px explanation and a concrete recovery button. Tooltips and `data-action-*` attributes carry the same reason for automation and accessibility. IDLE actions do not render warning noise.

## Release gate

V0.89-G2 extends `ReleaseCandidateGateV1` with mandatory checks:

- G2 contract tests PASS;
- `WorkflowActionReadinessAuthorityV1` present;
- contract version is `0.89-G2`;
- dead-end count = 0;
- unmanaged primary count = 0;
- G2 readiness release gate = PASS.

Formal Windows + licensed Motor-CAD qualification remains governed by the existing predecessor chain and is not claimed by this local HMI/action-state iteration.
