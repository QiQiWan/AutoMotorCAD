# MotorCAD Studio — V0.23 之后的深层优化路线

## 1. V0.23 完成后，真正的 P0 风险发生了变化

V0.23 已经补齐“原生 FEA 证据出口”和“Motor-CAD Session ownership”两个基础设施。系统下一步不应继续增加更多平级功能页，重点应转向四项结构性能力：

1. 模型编辑器与 Motor-CAD Geometry/Winding 的交互差距；
2. route-first 页面生命周期，消除旧全局状态和异步覆盖；
3. 持久 Motor-CAD Worker Pool，真正实现安全热复用；
4. Windows + Browser 全链路可靠性验证。

当前代码仍能看到明显的历史技术债：static JS 中约 52 处 `setTimeout`、8 处 `previousShowTab` 引用；`main.py`、`task_manager.py`、`solvers/motorcad.py` 均已超过千行。继续用包装层叠加功能，会再次出现“路由已经有了，但页面生命周期仍由旧 Tab 状态控制”的问题。

## 2. V0.24 — Motor Model Workbench（P0）

### 目标

让用户面对“一个持续存在的电机”，而不是参数表单集合。

### 建议布局

```text
┌──────────────────┬──────────────────────────────┬──────────────────┐
│ 参数 / Region 树  │ 快速示意 / Native Geometry   │ Constraints      │
│                  │                              │ Validation       │
│ 拓扑             │       电机截面                │ Winding          │
│ 几何             │       尺寸标注                │ Geometry         │
│ 永磁体           │       Region 选中             │ Slot fill        │
│ 绕组             │                              │ 修复动作         │
│ 材料             │                              │ Evidence         │
└──────────────────┴──────────────────────────────┴──────────────────┘
```

### 必做

- 参数 dependency graph；
- Slot / Tooth / Airgap / Magnet 区域点击反向定位参数；
- Winding Pattern 独立视图；
- Motor-CAD native snapshot 与快速 SVG 双视图；
- Error → Parameter → Previous feasible value 闭环；
- 当前 Revision 与上一可行 Revision 叠加比较；
- 单位、Motor-CAD Automation Name、readback 同屏；
- “恢复本组参数”代替大范围回滚。

### 关键收益

类似 `Slot fill = 1.41` 的错误不再要求用户去问题中心阅读日志，而是直接落在绕组/槽区域并给出相关变量。

## 3. V0.25 — Route-first Frontend Core（P0）

### 当前问题

V0.23 虽然 URL 已经表达 Project / Revision / Task / Case，但页面内部还保留：

```text
showTab
previousShowTab
global state
setTimeout 恢复状态
动态 wrapper monkey patch
```

这仍然是模板选择被异步刷新吞掉、后退/刷新状态错位一类故障的潜在来源。

### 目标架构

```text
Router
  ↓
Route Resolver
  ↓
Project Context
  ↓
Page Controller
  ├─ load(AbortSignal)
  ├─ render()
  ├─ bind()
  └─ dispose()
```

拆成 ES Modules：

```text
/core/router
/core/store
/core/api
/core/i18n
/core/events
/pages/project-overview
/pages/model-workbench
/pages/calculation
/pages/solve
/pages/results
/components/native-fea
/components/validation
```

路由变化时统一 `AbortController.abort()`，禁止旧请求完成后覆盖新页面。

## 4. V0.26 — Persistent Motor-CAD Worker Pool（P0）

### 为什么要独立成一轮

V0.23 已证明当前“一 Case 一 child”架构不能可靠承载 `keep_instance_open` 的跨 Case 热复用。

真正的架构应是：

```text
Studio API
   ↓
Job Queue
   ↓
MotorCAD Worker-01 (persistent Python owner)
   └─ PyMotorCAD object / RPC instance
MotorCAD Worker-02
   └─ PyMotorCAD object / RPC instance
```

### Session 状态机

```text
STARTING
→ READY
→ LEASED
→ LOADING_MODEL
→ SOLVING
→ EXPORTING
→ READY
        ↓ jobs / RSS / RPC threshold
     RECYCLING
→ STOPPED
```

### 需要实现

- owner heartbeat；
- PID/RPC endpoint；
- license-aware concurrency；
- per-worker memory budget；
- max jobs before recycle；
- failed RPC quarantine；
- graceful quit + hard kill fallback；
- template warm-load 仅在证据证明安全时启用；
- Session API 与现有 V0.23 表直接衔接。

### 预期收益

- 减少频繁启动 Motor-CAD 的等待；
- 降低 residual process；
- 并行 DOE 时资源边界明确；
- 后续真正的 live FEA read-only client 有稳定 owner 可连接。

## 5. V0.27 — Native FEA Renderer / Results Decision Workspace（P1）

当前 V0.23 Canvas 采用点云表达，主要目的是先保证“证据是真的”。后续应增加：

- mesh connectivity；
- filled contour；
- vector arrows；
- equipotential；
- region mask；
- rotor-angle synchronized overlay；
- Torque / Air-gap B / FEA field synchronized cursor；
- Revision A/B 同步播放。

结果中心升级为工程决策空间：

```text
             Rev.5      Rev.6      Rev.7
Torque       12.2       12.8       -
Efficiency   94.8%      95.1%      -
Loss         182 W      171 W      -
Slot Fill    PASS       PASS       FAIL
Native FEA   PASS       PASS       BLOCKED
```

提供“设为基准 / 设为候选 / 创建下一 Revision / 加入 DOE / 加入 Dataset”。

## 6. V0.28 — Reliability & Migration（P0/P1）

### Browser E2E

用 Playwright 真正点击：

```text
Project → Template → Design → Revision → Scenario
→ Calculation → Gate → Submit → Solve → Native FEA
→ Result → Refresh → Back → Forward
```

### Windows Motor-CAD Contract

故障注入：

- Motor-CAD crash；
- RPC timeout；
- license unavailable；
- BrokenPipe；
- Worker kill；
- residual process；
- `save_fea_data` unavailable；
- FEA CSV schema variation；
- DB locked；
- disk full；
- stale route；
- output mapping missing。

### 数据库

把当前“启动时 CREATE/ensure_column”升级为正式 migration：

```text
backup
→ schema version detect
→ ordered migrations
→ integrity check
→ service ready
```

数据库升级失败时阻止工程服务进入 READY。

## 7. V0.29 — AI-ready Engineering Data（P2）

当运行时和原生证据稳定后，再强化 AI 数据层：

- Run Configuration hash；
- Motor-CAD / PyMotorCAD version；
- Automation Mapping hash；
- Material database / BH / loss curve hash；
- Validation Evidence；
- Native FEA manifest/hash；
- solver quality status；
- field feature extraction；
- feasibility-aware DOE；
- active learning；
- surrogate uncertainty；
- Pareto candidate → Design Revision Candidate 回写。

## 8. 建议顺序

```text
V0.24  Motor Model Workbench
   ↓
V0.25  Route-first Frontend Core
   ↓
V0.26  Persistent Motor-CAD Worker Pool
   ↓
V0.27  Native FEA Renderer + Decision Workspace
   ↓
V0.28  Browser/Windows Reliability + DB Migration
   ↓
V0.29  AI-ready Engineering Data
```

其中 V0.24 和 V0.25 可以部分并行设计，但实现上更建议先定义 Workbench 的页面契约，再用 V0.25 的 route-first core 承载它；避免先重构路由后再反复修改页面接口。
