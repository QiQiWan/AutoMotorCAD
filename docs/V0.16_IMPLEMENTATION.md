# V0.16 Implementation — Project-Centric Runtime & AFPM Geometry Hardening

## 1. 本轮目标

V0.16 不是新建另一批孤立功能，而是修复真实工作站暴露出的交互与求解一致性问题：Project 上下文重复选择、产品界面仍含 Mock、材料目录默认覆盖模板、e14 AFPM 槽数修改后几何失效、动态中文不完整、日志导出与本地诊断可用性不足。

## 2. Project-first 交互

全局 `activeProjectId` 作为工程上下文。Task、Monitor、Result Viewer、Data Factory 都从该状态继承 Project；这些页面在没有当前 Project 时退回 Engineering Workspace。Task Builder 不再提供独立 Project 下拉框，而显示只读“当前项目”。

后端 `/api/tasks?project_id=...` 和 dashboard Project filter 保证前端切换 Project 后只看到本项目任务。正式 Motor-CAD 请求还增加 `PROJECT_REQUIRED` 预检查。

## 3. Motor-CAD-only 产品模式

`Settings.enable_mock_solver` 默认 false，正式 HTML 不暴露 Mock，健康/预检查也不广告 Mock。测试环境通过 `MOTORCAD_STUDIO_ENABLE_MOCK=1` 保留内部 Mock，以继续验证任务编排而不改变产品行为。

## 4. e14 AFPM 槽数依赖

e14 的 MTT 基线包含：
- `Slot_Type=Yokeless`
- `Slot_Number=12`
- `Stator_Poles=12`
- `Stator_Pole_Angle=30`
- `Slot_Opening=3`

因此 `slot_count` 不能只映射 `Slot_Number`。当该参数属于本次用户显式设计意图时，MotorCADSolverAdapter 额外写入：

```text
Stator_Poles = slot_count
Stator_Pole_Angle = 360 / slot_count
```

之后调用绕组刷新和 Motor-CAD 几何验证。依赖写入进入 parameter audit，并影响 qualification/runtime roundtrip。

V0.16 不自行猜测 `Slot_Width` 等派生几何公式；未显式修改的耦合尺寸交由 Motor-CAD 自身约束/几何恢复处理。

## 5. 材料写入安全

材料快速选择器每次加载都以空选择开始，即“沿用模板”。只有用户主动选择目录材料才进入 Task `materials.component_materials`。

抽象 Studio 组件名在写入前解析成 Motor-CAD 实际组件候选。例如 `Stator Lamination` 优先探测 `Stator Lam (Back Iron)`、`Stator Lam (Tooth)`。只有能 read/get 的目标才执行材料覆盖，并记录 set/get audit。

## 6. 中文/双语和 UI

动态 Project Tree、DOE/constraint 字段、材料和参数状态中文优先；关键内部术语保留英文辅助核对。修复 native select 和 changed badge 对比度。

## 7. 日志与诊断

- `data/logs/studio.jsonl`
- `data/logs/studio.log`
- `data/logs/audit.jsonl`
- `data/runtime/diagnostics/BOOT-*/environment.json`
- `health_latest.json`
- `qualification_matrix.json`
- Case `solver_runtime.jsonl`

诊断包采用浏览器 Blob 下载，并同时落到当前 BOOT 诊断目录。

## 8. 已知边界

当前执行环境无 Motor-CAD，因此 e14 槽数依赖修复通过适配器单元测试和已有 MTT 结构验证，但仍必须在目标 2026R1 工作站执行真实 baseline/slot-count qualification。若 baseline 本身失败，不应把问题归咎于 slot_count，而应重新校准模板运行时几何和版本兼容性。
