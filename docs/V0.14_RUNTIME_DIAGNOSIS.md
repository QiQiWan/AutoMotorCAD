# V0.14 Runtime Diagnosis

## Evidence from the supplied diagnostic bundle

The supplied V0.13 logs contained three independent issue classes.

### Historical monitoring API failure

`GET /api/system/metrics` failed because an older runtime called `StructuredLogStore.log()` with an invalid positional argument. The current source already used keyword arguments; V0.14 adds deployment-version checks and static cache prevention so a stale browser/frontend cannot silently run against another backend build.

### Missing catalog endpoints

The bundle recorded HTTP 404 for `/api/materials/catalog` and `/api/result-viewer/catalog`, although both routes exist in the V0.13 source package. This is evidence of a mixed or partially updated deployment. V0.14 exposes a client contract and prominent compatibility warning.

### Motor-CAD geometry failure

The actual solver failure was not RPC or licensing. Motor-CAD reported:

```text
The current value of Slot Opening is not possible within the current machine constraints.
Regions "Stator" and "StatorAir" intersect.
Geometry check failed.
```

The strongest software-side root cause was that Studio treated MTT-derived defaults as authoritative task inputs and rewrote them into the live template. V0.14 stops doing this for untouched parameters and adds supported geometry auto-recovery plus an explicit-parameter safety gate.

## Operator troubleshooting artifacts

For future geometry failures inspect, in order: `model_validation.json`, `parameter_audit.json`, `runtime_defaults.json`, `solver_runtime.jsonl`, then the saved pre-solve `.mot`. Geometry errors are classified as `GEOMETRY_INVALID` instead of generic solver failure.
