# MotorCAD Studio V0.22.0 — Motor-CAD 流程对齐、求解可视化与诊断驱动修复

## 1. 本轮目标

V0.21 已经把 Design Revision、Scenario Revision、Solver Profile Revision、Output Profile Revision 和 Run Configuration 的工程对象边界拆清楚，但操作层仍然暴露过多“系统资产”概念。V0.22 的目标是保留 V0.21 的可追溯性，同时把普通操作流程收敛成接近 Motor-CAD 的连续模型工作流，并利用最新工作站诊断包修复真实的任务提交与结果提取问题。

项目级主流程统一为：

```text
概览 → 模型 → 计算 → 求解过程 → 结果 → 数据
```

Scenario / Solver Profile / Output Profile / Run Configuration 仍然是版本化工程资产，但在 Operator 模式下降级为计算流程内部的配置来源，不再与“模型、计算、结果”等主要动作平级竞争注意力。

## 2. 最新诊断包的事实结论

诊断窗口为 240 分钟，共 251 条结构化日志：INFO 91、WARNING 159、ERROR 1，健康分 67。日志组件以 API 为主（205 条），这已经说明本轮体验问题中有大量前端请求噪声，而非 159 个独立的 Motor-CAD 求解故障。

### 2.1 146 条 WARNING 来自一个已不存在的 Task

同一条日志反复出现 146 次：

```text
GET /api/tasks/TASK-A2D154252C/monitor -> 404
```

旧前端保存了过期监控 Task，并在任务已经不存在后继续轮询。V0.22 在第一次确认 404 后立即关闭流、清除当前 Task 选择并停止后续轮询；路由层同时增加过期 Project 深链接校验，避免对已删除/回收项目连续请求 `/project`、`/domain-integrity`、`/simulation-assets`。

### 2.2 32 次 geometry-precheck 说明前端存在重复请求

窗口内共有 31 次 i5 `geometry-precheck -> 200`，另有一次 e14 precheck。参数输入、多个监听器和异步刷新会重复发起同一配置的检查。

V0.22 增加：

- 420 ms debounce；
- 参数 payload key 去重；
- 共享 in-flight Promise；
- 新请求到来时通过 AbortController 取消已过期检查；
- Native model gate 共享 Promise，阻止重复深度 Motor-CAD 检查。

### 2.3 唯一一条 ERROR 是真实的 Revision 并发竞争

日志 seq 171：

```text
POST /api/solver-profiles/SLV-219AC66209/revisions
UNIQUE constraint failed:
solver_profile_revisions.solver_profile_id,
solver_profile_revisions.revision
```

这说明旧实现的“查询 MAX(revision) → Python 计算 +1 → INSERT”跨了两个独立事务。两次快速请求可能同时得到相同 revision number。

V0.22 将 Design、Scenario、Solver Profile、Output Profile 四类不可变 Revision 全部改为同一个数据库事务中的 `MAX(revision)+INSERT`，并给 Solver Profile、Output Profile 和 Task 提交按钮增加客户端提交锁。

### 2.4 16 槽和 18 槽失败属于真实模型约束

16 槽在 Studio 确定性预检中被阻断：

```text
16 / 3 / 1 = 5.33333
WINDING_SLOT_PHASE_PATH_NONINTEGER
```

18 槽通过整数关系，但 Motor-CAD 原生检查报告：

```text
Slot fill = 1.41 should not be > 1
The Slot Fill or Conductors/Slot must be reduced
```

因此 18 槽失败不能通过放宽 Studio Gate 解决。它需要调整 Conductors/Slot、导体尺寸、槽面积或绕组定义。

### 2.5 12 槽 / 4 极已经完成真实 EMag + 稳态热计算

诊断 seq 222 的 Motor-CAD Native Model Check 为 PASS，随后 `TASK-32C810232A` 创建 1 个 Case；solver worker 最终记录 `SOLVER_RUN_SUCCESS`，Task 状态为 COMPLETED。

该 Case 的质量状态是 WARNING，主要来自结果提取和映射，不代表有限元求解失败。当前有效计算结果包括轴转矩、效率、线电压、总损耗、磁钢损耗和绕组温度。

## 3. 为什么 Motor-CAD 的流程主观上更清晰

Motor-CAD 的核心优势来自“一个持续存在的当前模型”。Geometry、Winding、Input Data、Calculation、E-Magnetics/Temperatures、Output Data 等入口围绕同一个模型上下文切换，而且界面会根据当前模型类型减少无关选项。用户的心智模型始终是“我正在修改和计算这一台电机”。

V0.21 的 Studio 在可追溯性上更强，但用户需要同时理解 Project、Design Revision、Scenario Revision、Solver Profile、Output Profile、Run Configuration、Task、Case。对于日常操作员，这些工程资产不应该全部成为主要导航对象。

### 3.1 功能定位差异

| 能力 | Motor-CAD | V0.21 Studio | V0.22 处理 |
|---|---|---|---|
| 当前模型上下文 | 强，始终围绕当前 .mot | 被多个工程对象拆散 | 顶层连续流保持当前 Design/Scenario/Analysis 上下文 |
| 参数编辑 | 参数表与真实几何高度联动 | 参数表 + 近似示意图 | 当前值驱动示意、部件高亮、参数依赖提示 |
| 绕组 | 专门 Winding Editor / Pattern | 主要是参数与检查 | 保留绕组约束；下一步做独立绕组工作台 |
| 计算启动 | Calculation 中直接 Solve | Wizard + Gate + Task | 保留 Gate，但压缩为“配置 → 检查 → 提交 → 自动进入求解过程” |
| 求解反馈 | 状态栏 + FEA Display | 进度/日志为主 | 新增求解过程动画 + 完成后结果驱动回放 |
| FEA 可视化 | 真实网格、场云图、矢量/等势线 | 无原生 FEA 场展示 | V0.22 先实现过程可视化与真实结果曲线回放；V0.23 继续做原生 FEA 场帧 |
| 输出 | Output Data / Graph Viewer | 需要逐项勾选 | 常用输出按 analysis 自动勾选 |
| 自动化血缘 | .mot 和脚本为主 | Project/Revision/RunConfig/Task/Case | Studio 保持优势 |
| DOE/数据生产 | 软件内分析 + API | 原生工程数据管线 | Studio 保持优势 |

## 4. V0.22 操作架构

Operator 模式项目导航改为六个连续动作：

```text
1 概览
   ↓
2 模型
   ↓
3 计算
   ↓
4 求解过程
   ↓
5 结果
   ↓
6 数据
```

“仿真配置资产”只在 Engineering / Expert / Developer 模式下作为高级入口显示。

### 模型

用户主要完成：

```text
选择/创建 Design
→ 修改几何、槽极、磁钢、绕组
→ 实时查看参数示意与约束
→ 保存为不可变 Revision
```

### 计算

用户主要完成：

```text
Design Revision
→ Scenario
→ Analysis / Solver
→ Output
→ Native Gate
→ Submit
```

页面持续显示：

```text
当前 Design Rev → 当前 Scenario Rev/临时工况 → 当前 Analysis
```

Task 仍然冻结 Run Configuration，但普通用户不需要先进入 Run Configuration 管理页。

### 求解过程

Task 创建成功后直接进入求解过程页面，不需要再到任务列表中寻找刚提交的任务。

## 5. 参数编辑可视化升级

V0.21 的主要问题是示意图仍偏“模板图片”：用户修改 slot_count、pole_count、air_gap 等参数时，图形和参数之间的语义联系较弱。

V0.22 的 `motorSchematic()` 改为使用当前参数值生成几何：

- 槽数决定槽线数量；
- 极数决定永磁体数量；
- 定子外径、内径、气隙、磁钢厚度改变相对尺寸；
- 输入控件聚焦时，高亮对应几何部件；
- 显示参数依赖链与影响说明。

例如槽数：

```text
slot_count
  ↓
槽距
  ↓
齿宽 / 槽宽
  ↓
绕组周期
  ↓
Conductors/Slot
  ↓
Slot Fill
  ↓
Winding Factor
```

这仍然属于“工程快速示意”。它不会伪装成 Motor-CAD 原生 Geometry/FEA 几何。下一阶段应增加“快速示意 / Motor-CAD Native Geometry”双视图。

## 6. 求解动画：V0.22 已实现两种证据层级

### 6.1 实时过程模式

运行中的 Task/Case 会显示：

- 当前 Case 的真实极数、槽数和主要几何；
- 当前 Task stage；
- 当前进度；
- 转速；
- 转子运动；
- 与 EMag/Thermal/Validation 阶段匹配的动态视觉状态。

这里的动态场线只表达“求解正在推进以及模型正在旋转”，明确标注为过程示意，不作为物理场值证据。

### 6.2 Motor-CAD 结果驱动回放

V0.22 默认请求并提取：

- `TorqueVW` → 转矩-角度曲线；
- `B Gap (on load)` → 气隙磁密-机械角曲线。

Case 完成后，如果提取到这些序列，监控页面自动进入“结果回放”：

- 角度来自 Motor-CAD graph；
- 转矩来自 Motor-CAD TorqueVW；
- 气隙磁密来自 Motor-CAD FEA graph；
- 播放条可以暂停、拖动、逐帧查看。

### 6.3 当前仍没有伪造“真实 FEA 云图实时流”

Motor-CAD 本机 FEA Display 可以在求解时显示有限元 shading/contours，并支持打开历史结果和导出动画。PyMotorCAD 的公开 API 还提供 `save_fea_data()`、`get_fea_graph()`、`get_fea_graph_point()` 等结果接口。

当前 Studio 的 `do_magnetic_calculation()` 仍运行在独立阻塞 solver worker 中。V0.22 没有通过未经验证的并发 RPC 或屏幕抓取去伪造“实时节点场云图”。下一阶段应在 Windows 工作站上验证两条路线：

1. 求解后通过 `save_fea_data()` 批量导出真实 FEA step 数据，在浏览器构建高保真场回放；
2. 若 Motor-CAD 实例允许安全的第二只读 RPC 客户端，再验证求解中的增量 FEA frame 读取。未通过并发安全验证前，不启用该模式。

## 7. 默认输出与本次结果提取修复

V0.22 对适用 analysis 默认勾选常用项：

- 轴转矩；
- 转矩脉动；
- 效率；
- 峰值线电压；
- 输出功率；
- 总损耗；
- 磁钢损耗；
- 绕组最高温度；
- 绕组平均温度；
- 转矩-角度曲线；
- 气隙磁密-机械角曲线。

本次工作站成功 Case 表明当前 2026R1 i5 模板的 `TORQUE_RIPPLE`、`SHAFT_POWER/OUTPUT_POWER/MECHANICAL_POWER` 等直接变量名不能可靠读取。V0.22 因此：

```text
输出功率 = 轴转矩 × 角速度
```

并使用 Motor-CAD `TorqueVW` 曲线计算：

```text
Torque Ripple (%) = (Tmax - Tmin) / |Tavg| × 100
```

这样避免继续向已知不存在的变量发起重复探测。

当前 `copper_loss_w` 和 `stator_iron_loss_w` 暂不默认勾选，因为最新实际 Case 尚未校准出稳定的 2026R1 i5 直接映射。后续应通过 Output Data / Automation Parameter Names 或 CSV/Graph 数据完成工作站级结果校准后再恢复默认项。

## 8. 稳态热 `Initial_Temperature` 错误

最新 Case 明确记录：

```text
pymotorcad: set_variable: Error in SetVariable:
Could not find Initial_Temperature
```

但当前 recipe 是 `emag_thermal`，热阶段调用稳态热求解。稳态热并不需要把“初始温度”作为本次 recipe 的必写参数。

V0.22 把 Scenario 参数映射分为：

```text
steady state:
  ambient / cooling / operating point

transient thermal:
  ambient / cooling / operating point
  + initial_temperature
```

因此普通 EMag + Steady Thermal 不再探测 `Initial_Temperature`。

## 9. V0.21 Scenario 的执行语义漏洞

V0.21 已经把速度、电流、电压等归入 Scenario Revision，但 solver 的 explicit write whitelist 仍主要来自 Design 参数。这会产生“Run Configuration 中保存了 Scenario，却可能继续沿用模板运行点”的风险。

V0.22 将所有非 null 的 Scenario operating fields 加入真实 Motor-CAD 写入意图：

```text
shaft_speed_rpm
peak_current_a
rms_current_a
dc_bus_voltage_v
phase_advance_deg
```

同时继续做 write/readback audit。这样 Scenario Revision 的工程语义和求解器行为一致。

## 10. 空 Output Profile 的不可变语义

V0.21 的默认 Output Profile 用空列表表达“采用推荐输出”。但 Run Configuration 会把空列表直接 hash 进去，执行阶段又可能把空列表扩展成另一组输出，导致冻结快照和真实执行语义不一致。

V0.22 在 Run Configuration 创建之前将空选择显式解析成当前 analysis/template 的默认输出 ID 列表。历史 V0.21 Run Configuration 的空列表在重算时也按这一既有约定归一化，因此仍可重放。

## 11. 成功 Task 自动形成资格证据

最新诊断中 `emag_thermal` 已经完成真实 EMag 求解和稳态热求解，但 qualification matrix 仍为空，因此下一次提交依旧会出现 `ANALYSIS_NOT_VERIFIED`。

V0.22 在真实 Motor-CAD Case 完整成功后自动登记本机：

```text
Template + Analysis + Motor-CAD Version
→ Level 4 PASS evidence
```

结果字段缺失造成的 WARNING 不会把成功的求解能力重新标成“未验证”。本地 verified MOT 是否存在仍然是独立的 production provenance gate，不会被这条自动证据绕过。

## 12. V0.22 的边界

V0.22 重点解决当前诊断包已经证明的问题，并缩小与 Motor-CAD 的流程和交互差距。仍存在以下结构性差异：

- Studio 的几何仍是语义示意，不是 Motor-CAD Geometry Editor 的 region/entity 级模型；
- 绕组缺少类似 Motor-CAD Winding Editor 的专门可视化；
- 实时动画还没有节点/单元级真实 B/J/A 云图流；
- 材料编辑仍缺少真实材料曲线/BH/loss map 的联动视图；
- Result Workspace 还缺少 Motor-CAD Graph Viewer 式统一曲线浏览器；
- 需要 Windows + Motor-CAD 的 E2E/Contract Test，Linux 单元测试无法验证 GUI、RPC、许可证和 FEA 实例生命周期。

这些内容进入 V0.23/V0.24 路线图。
