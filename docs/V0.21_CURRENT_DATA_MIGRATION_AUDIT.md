## 4. V0.21 打开旧 Design 时的行为

当旧 Design Revision 被选为仿真基线，V0.21 会识别其中误存的运行点字段，并恢复到当前页面的临时 Scenario。系统会提示把这些运行条件保存为 Scenario Revision。这样可以避免升级后静默回退到模板默认转速、电流或母线电压。

旧 Design Revision 保持 immutable；正式迁移通过后续自然创建：

```text
旧 Design Revision
  ├─ 设计参数 -> 新 Design Revision
  └─ 运行点参数 -> Scenario Revision
```

Solver Profile 与 Output Profile 在第一次进入 V0.21 配置资产流程时按项目建立默认版本化资产。Scenario / Solver / Output 的“新建 + Rev.1”使用单事务原子 API，避免创建空容器后第二步失败留下半成品。

## 5. 当前数据建议操作

先不要删除旧 Revision 或旧 Task。进入 Active Project 后，按以下顺序自然迁移：

```text
选择旧 Design Revision
→ 检查自动恢复的临时 Scenario
→ 保存 Scenario Revision
→ 将需要长期保留的设计/材料修改保存为新的 Design Revision
→ 选择/保存 Solver Profile Revision
→ 选择/保存 Output Profile Revision
→ 提交一次新的 baseline Task
→ 核对 Run Configuration hash / traceability
→ Native Validation / Solve
```

完成后，新执行链路即可具有 V0.21 的完整四域版本和 Run Configuration 血缘，同时保留 V0.20 历史数据用于对照。
