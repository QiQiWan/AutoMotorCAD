# V0.88-D — Editor Transaction Convergence & Native State Reconciliation

Release: **MotorCAD Studio 0.88.4 / Schema 45**

## Objective

V0.88-D closes the remaining state ambiguity between the browser editor, persisted Design Draft, immutable Design Revision and the live Motor-CAD model. Geometry, winding and material editors now share one server-authoritative `EditorTransactionAuthorityV1` transaction. A native validation result is trusted for the editor only when it is attached to the exact persisted transaction and exact durable design-intent hash.

The authority chain is:

`Immutable Design Revision -> Design Draft Transaction -> persisted intent hash -> Motor-CAD native check -> NativeModelSnapshot -> Native reconciliation -> immutable Revision commit`

Changing the editor tab or subview does not change design intent. Changing geometry, winding, magnet/topology parameters or component material assignments does.

## 1. EditorTransactionAuthorityV1

Every persisted draft carries:

- `editor_transaction_id` — stable for the lifetime of the draft;
- `editor_intent_hash` — SHA-256 of base revision + durable parameters + materials + explicit parameter set;
- `editor_intent_version` — increments only when durable design intent changes;
- normal draft `version` — still increments for every persisted draft update, including view state;
- `native_reconciliation_json` — the latest native evidence retained for audit even after it becomes stale.

This separates optimistic-concurrency versioning from engineering-intent identity. Moving from Geometry to Winding may advance the draft persistence version, but it does not invalidate a valid native result. Editing air gap, turns per coil or magnet material does invalidate it.

## 2. Single transaction across Geometry / Winding / Materials

The editor no longer treats each surface as an independent state owner. The same Design Draft carries all three domains:

- geometry: topology + geometry + magnet parameters;
- winding: winding parameters and later structured winding intent;
- materials: component material assignment configuration.

`dirty_design_domains()` computes deterministic deltas relative to the frozen base Revision and returns dirty parameter IDs by engineering domain plus changed material components.

The source Motor-CAD `.mot/.mtt` template remains read-only. Product-facing **保存设计** commits a new immutable historical snapshot internally; the engineer is not required to manage a review/revision form for an ordinary edit.

## 3. Persist-before-native rule

Motor-CAD native validation no longer accepts the browser's in-memory parameter payload as the authority source for the editor workflow.

Before native validation:

1. pending browser changes are flushed to the Design Draft;
2. the server returns the current `transaction_hash` and `intent_hash`;
3. the browser submits only draft version + those hashes + repair policy;
4. the server reloads parameters/materials from the persisted draft;
5. the server verifies version/hash lineage before launching Motor-CAD.

This closes the historical race where the native check could validate values that were visible in one tab but had not yet become the canonical persisted draft.

## 4. Double-checked native attachment

Motor-CAD execution may take seconds or minutes. A second browser tab can therefore edit the same Draft while the native process is running.

V0.88-D performs a second atomic transaction/intention check after Motor-CAD returns. If the current Draft changed during the run, the result is **not attached** to the new editor state. The API returns `EDITOR_TRANSACTION_CHANGED_DURING_NATIVE_CHECK`.

The old runtime result may remain available in diagnostic evidence, but it cannot certify the newer design intent.

## 5. Native state reconciliation

`native_reconciliation_record()` reduces V0.88-A/B/C evidence into one editor-facing state:

| State | Meaning |
|---|---|
| `UNCHECKED` | No Motor-CAD evidence exists for the current transaction. |
| `CURRENT` | Native check passed and evidence is bound to the exact transaction/intent. |
| `STALE` | Design intent changed after the native result. |
| `DRIFT` | Motor-CAD readback contradicts current design intent. |
| `PARTIAL` | Native evidence exists but is incomplete. |
| `FAILED` | Native check failed. |

The reconciliation record anchors snapshot hash, native design-state hash, BindingPlan hash, RepairPlan hash/status, fault count, repair-attempt count, model fingerprint and its own evidence hash.

## 6. HMI convergence

The editor now exposes four persistent status cells:

1. **编辑事务** — stable transaction identity and intent version;
2. **设计状态** — 未修改 / 已修改未保存 / 草稿已保存;
3. **Motor-CAD 状态** — 待检查 / 已应用到 Motor-CAD / Native Evidence 已过期 / Native 已漂移 / 证据不完整 / 检查失败;
4. **起始模板** — permanently shown as read-only.

A prior native result is retained visibly as stale after an edit instead of disappearing. This makes the causal relationship between “I changed a value” and “the previous native evidence is no longer valid” explicit.

After **保存设计**, the read-only Design Viewer shows the immutable saved state and the native reconciliation status that was present at commit time.

## 7. Immutable Revision evidence

Schema 45 adds editor/native reconciliation fields to both `solution_drafts` and `motor_revisions`. On commit, the source editor transaction and native reconciliation are frozen into the new Revision before the Draft is deleted. This provides an audit trail from product-facing Save to the exact native evidence available at that moment.

## 8. API contract

New/extended endpoints:

- `GET /api/solutions/{solution_id}/editor-transaction`
- `GET /api/solutions/{solution_id}/draft` now returns `editor_transaction`
- `PUT /api/solutions/{solution_id}/draft` now returns `editor_transaction`
- `POST /api/solutions/{solution_id}/draft/native-check`
- compatibility alias: `POST /api/designs/{design_id}/draft/native-check`

The native-check request contains `expected_version`, `transaction_hash`, `intent_hash`, timeout and repair policy. Design parameters/materials are intentionally absent from this request because they are loaded from the canonical persisted Draft.

## 9. Production qualification

The Windows qualification contract advances to **0.88-D** and adds the release gate:

`editor_transaction_reconciliation_authority`

This is a release-level gate, not a claim that a browser Draft itself is the formal solver authority. Formal native scenarios still require the V0.88-A semantic authority, V0.88-B post-solve model readback and V0.88-C clean fault/repair evidence. V0.88-D proves that the product editing workflow cannot attach stale native evidence to a newer design intent.

The current environment cannot execute licensed Motor-CAD 2026R1 on the target Windows workstation. Formal live qualification therefore remains pending.

## 10. Acceptance criteria

V0.88-D is code-complete when all of the following hold:

- one draft transaction spans geometry/winding/material editing;
- view-only changes preserve intent identity;
- durable edits advance intent identity;
- native checks use persisted draft state;
- stale transaction requests fail closed;
- edits made during native execution cannot inherit the old result;
- previous native evidence becomes explicitly `STALE` after design changes;
- commit freezes editor/native reconciliation evidence into the immutable Revision;
- source templates remain read-only;
- current regression/HMI suites pass;
- live Windows Motor-CAD qualification remains explicitly pending until observed.
