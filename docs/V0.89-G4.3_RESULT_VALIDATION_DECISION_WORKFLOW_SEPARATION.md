# V0.89-G4.3 结果、验证与决策流程分离

## 修复结论

原三阶段导航把结果浏览和工程决策共同放在“决策”下，导致用户点击“查看结果”后先看到决策摘要，工况、曲线和有限元场被推到页面下方。验证页同时承担配置、运行和结果跳转，页面职责不清晰。

本轮将主流程调整为：

1. 设计：配置并冻结电机版本；
2. 验证：配置分析、执行检查、提交计算和查看进度；
3. 结果：选择任务与工况，查看指标、曲线、场数据和原始证据；
4. 决策：审查结论、工程要求、可信度、比较和优化。

## 具体修复

- 顶部导航增加独立“结果”阶段；结果入口路由到 `/results/tasks`，决策入口路由到 `/results`。
- 结果模式隐藏工程决策摘要、指标卡和高级证据，结果选择器成为首要操作区。
- 决策模式保留工程摘要、工程要求、比较、鲁棒性和优化入口。
- 结果工作台内部标签改为“结果查看”和“工程决策”，说明各自职责。
- 工作流门禁先开放结果，再开放决策；没有可用结果时两个入口均给出明确前置条件。
- 导航按钮采用四列两行网格：序号独立占两行，标题和状态分别占一行；移除容易遮挡文字的弹性挤压。
- 决策摘要语言以页面实际 `lang` 状态为权威，并在语言按钮切换后重新渲染；动态状态词补充中文映射。
- 工程焦点条根据当前结果模式显示“结果查看”或“工程决策”，下一步提示同步变化。
