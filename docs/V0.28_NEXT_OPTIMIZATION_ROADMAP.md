# V0.28 后续深层优化路线图

## 总体判断

V0.28 已经把 Design Revision 首帧水合和普通 Task 提交路径统一，但系统距离长期稳定的 Motor-CAD 工程工作台仍有四个结构性差距：数据库升级机制、真实浏览器端到端测试、Windows Motor-CAD 合同测试，以及 Native Geometry/Winding/FEA 的直接工程交互。

## P0 — V0.29 Formal Migration + Browser E2E

### 1. 正式数据库 Migration

当前仍保留 `CREATE TABLE IF NOT EXISTS`、`ensure_column()` 和个别 query-time recovery。建议改为启动阶段唯一迁移：

```text
Startup
→ migration lock
→ database backup
→ read schema version
→ ordered migrations
→ PRAGMA integrity_check
→ foreign_key_check
→ application READY
```

失败时阻断工程服务，页面只进入数据库恢复模式。

### 2. 真正的浏览器 E2E

现有大量前端测试属于源码/DOM 契约。必须加入 Playwright：

```text
Project
→ Template
→ Design Revision
→ 首帧几何核对
→ Scenario
→ 快速检查
→ Task Submit
→ Monitor
→ Result
→ Refresh
→ Back / Forward
```

专项覆盖：

- Revision 快速切换；
- 路由切换期间旧请求 abort；
- 双击提交；
- 网络响应丢失后的幂等重试；
- 删除 Project/Task 后旧 deep link；
- 浏览器刷新/返回；
- Dialog / Sheet 关闭；
- 断网恢复。

### 3. 清理 pytest 进程退出等待

当前完整测试的用例本体能够全部通过，但旧 TestClient / 后台 Task 组合在 suite teardown 偶发等待。需要建立统一 pytest app lifespan fixture，并确保每个 Task thread / worker pool / realtime resource 在 suite 结束前显式收口。

## P0 — Windows Motor-CAD End-to-End Contract

在目标 Windows + Motor-CAD 2026R1 工作站自动运行：

```text
20 Cases smoke
100 Cases reuse
500 Cases endurance
```

注入：

- Motor-CAD crash；
- RPC pipe close；
- worker kill；
- license unavailable / restored；
- EXE path switch；
- insufficient memory；
- cancel during validation；
- cancel during FEA；
- Studio graceful / abnormal shutdown。

输出 Worker generation、Session、RSS、resource wait、lease hash、native message、result quality 的统计分布，用真实证据决定默认 recycle job count 和 RSS 阈值。

## P1 — V0.30 Native Geometry + Structured Winding

Workbench 目前的快速几何仍是 Studio 参数示意。下一步使用 Motor-CAD Region / Entity 数据建立 Native Geometry Viewer：

```text
参数树 / Region Tree
↔ Native Geometry
↔ constraint evidence
```

真实绕组使用 `get_winding_coil()` 形成 Phase / Path / Coil / go-slot / return-slot / turns 的结构化视图。

目标是：点击 Motor-CAD 错误 → 原生 Region/Coil 高亮 → 关联参数 → 上一可行值 → 修复 → Native Validation。

## P1 — Output Mapping Calibration

真实 Case 已证明不同 Motor-CAD 版本/模板的直接变量名可能不同。建议把结果提取升级为工作站校准资产：

- Automation output registry by Motor-CAD version + template family；
- candidate probe evidence；
- direct / derived output authority；
- unit readback；
- mapping confidence；
- 必需输出缺失才阻断，常用可选输出进入 Quality Warning。

## P2 — AI-ready Engineering Provenance

Dataset 行最终冻结：

- Run Configuration hash；
- Validation Evidence hash；
- Runtime Contract/environment signature；
- Motor-CAD/PyMotorCAD version；
- canonical model hash；
- material DB / BH / loss curve hash；
- output mapping version；
- FEA evidence hash；
- result quality flags。

这样生成的 DOE / NSGA-II 数据才适合长期代理模型、PINN/ML 和跨版本复现实验。
