# V0.29 工程师中心流程与界面架构

## 1. 目标

V0.29 的目标是降低工程师在“理解软件对象”和“完成电机分析”之间的转换成本。底层继续保留 Design Revision、Scenario Revision、Solver/Output Profile、Run Configuration、Task、Case、Execution Lease 等不可变追溯对象；主界面只持续回答五个问题：

1. 当前在研究哪一台电机？
2. 当前运行点/边界条件是什么？
3. 准备做什么分析？
4. Motor-CAD 当前能否执行、正在执行什么？
5. 结果是否可信，下一步应修改哪里？

## 2. V0.28 工程师体验审查

### 2.1 主流程切得过细

V0.28 项目级主导航为“概览、模型、计算、求解过程、结果、数据”。“计算”和“求解过程”本质属于同一次仿真活动，却被拆成两个一级阶段。工程师提交任务后会产生一次额外的上下文切换。

V0.29 收敛为：

```text
概览 → 模型 → 仿真 → 结果 → 数据
              ├─ 配置仿真
              ├─ 计算记录
              └─ 实时求解
```

### 2.2 领域对象对操作层暴露偏多

版本化领域模型对追溯非常重要，但日常工程操作不应要求用户持续在 Design Revision、Scenario Revision、Solver Profile、Output Profile、Run Configuration、Task、Case 之间切换思维。V0.29 将这些对象继续作为证据和高级配置资产，而工程主线围绕“当前模型 + 当前工况 + 当前分析 + 当前任务”组织。

### 2.3 仿真配置缺少持续摘要

五步配置向导可以降低新用户认知负担，但工程师经常跨步骤检查参数。V0.29 在工程模式下增加右侧固定运行摘要，任何一步都能看到即将送入 Motor-CAD 的核心上下文，并可以直接跳转步骤。

### 2.4 重复原生检查打断参数迭代

独立 Motor-CAD Geometry/Winding 检查成本远高于 Studio 确定性预检查。同一个模型快照反复点击检查会重复启动 Motor-CAD。V0.29 将独立检查证据按模型指纹缓存 300 秒；模型参数、显式修改集合、材料、Motor-CAD 可执行文件或目标版本发生变化时指纹自动变化。工程师可显式“强制重新检查”。正式 Task 仍在 Execution Lease 内重新完成权威原生校验。

### 2.5 页面加载仍存在历史跨页面刷新

Route-first 已经解决大部分异步覆盖，但旧 `changeActiveProject()` 包装层仍会在 Router 已拥有加载权时额外刷新 Task context/readiness；项目概览拿到 readiness 后又再次请求一次。V0.29 删除这两个 waterfall，减少项目页面切换时的冗余网络/DOM 工作。

## 3. 新的信息架构

### 全局层

```text
项目管理 | 运行环境 | 问题与日志 | 系统诊断
```

### 项目层

```text
概览 | 模型 | 仿真 | 结果 | 数据
```

### 仿真二级层

```text
配置仿真 | 计算记录 | 实时求解 | 高级配置资产（工程/专家模式）
```

“实时求解”不再占据一级流程位置。Task/Case/Run Configuration 继续支持 deep link 和追溯。

## 4. 持续工程上下文条

项目页面顶部新增持续上下文：

```text
当前模型        工况             分析          Motor-CAD        当前任务
Rev.N       Scenario/临时     EMag/Therm       就绪/阻断        TASK-...
```

这些信息可直接跳转到对应工作区。工程师在结果、任务记录、模型和仿真之间切换时，不需要重新确认“当前到底是哪台模型”。

## 5. 工程模式运行摘要

仿真配置页右侧固定显示：

- 模型版本；
- 工况；
- 分析类型；
- 计算方式；
- Case 数；
- 临时覆盖数量；
- 输出数量；
- 当前 Gate；
- 五步直接跳转；
- 返回模型工作台 / 检查提交 / 定位问题。

引导模式仍维持单列、逐步向导，适合首次使用；工程模式允许非线性导航。

## 6. 输出偏好

Output Registry 继续决定哪些输出可用和哪些是 required。V0.29 在此基础上保存：

```text
(project_id, analysis) -> selected output ids
```

因此同一项目重复进行 EMag 或 EMag+Thermal 分析时，会恢复工程师上次使用的输出集合。点击“选择推荐项”会重新建立推荐集合并覆盖当前偏好。

## 7. Motor-CAD 原生检查证据缓存

缓存键绑定：

```text
template
+ normalized effective parameters
+ explicit_parameter_ids
+ material configuration
+ effective Motor-CAD.exe
+ target Motor-CAD version
+ model policy
```

普通独立检查：相同指纹 300 秒内复用。

强制检查：`force=true`，绕过缓存。

缓存仅用于“独立诊断检查”；正式计算继续执行：

```text
Runtime Resource Lease
→ Persistent Worker
→ canonical model reload
→ parameter/material write + readback
→ native geometry/winding validation
→ same-session full solve
```

因此缓存不会降低正式计算的验证强度。

## 8. 页面性能优化

V0.29 两处关键调整：

```text
Router owns project load
→ changeActiveProject 只更新 project context
→ 不再额外 refreshProjectTaskContext/readiness
```

以及：

```text
Project Overview Promise.all 已取得 readiness
→ 直接用于 readiness UI
→ 不再发第二次 readiness API
```

下一阶段建议增加 route performance budget：项目切换 P95 < 800 ms（本地数据库环境），超过预算的 endpoint 进入诊断包 waterfall。

## 9. 设计原则

1. 工程对象可追溯，但不占用不必要的主导航位置。
2. “当前模型”始终可见。
3. 模型错误优先定位到 Region/参数，日志作为证据层。
4. Studio 快速检查用于即时反馈；Motor-CAD Native Evidence 用于权威判断。
5. 不重复执行没有新信息增益的昂贵操作。
6. Engineer mode 允许直接跳转；Guided mode 保留线性防错流程。

## 10. 下一阶段验收重点

V0.30 应优先继续解决：Native Geometry/Structured Winding、结果决策工作台、正式浏览器 E2E、Windows Motor-CAD contract test、数据库正式 migration，以及页面级性能预算和 API waterfall 观测。
