# MotorCAD Studio V0.7 实施说明

## 1. 版本目标

V0.7 将 V0.6 的“交互式仿真驾驶舱”推进到“工程 DOE 与多目标候选筛选平台”。本轮不尝试在未实机验证前实现黑盒式 NSGA-II 闭环，而是先把可靠的试验设计、资源调度、阶段恢复和多目标结果分析做成稳定底座。

核心链路：

```text
Template + Canonical Parameters
            ↓
Experiment Definition
            ↓
Full Factorial / LHS / Random / Pareto Search
            ↓
Case Queue
            ↓
Licence Pool → Solver Worker → Motor-CAD
            ↓
Checkpoint / Result / Quality
            ↓
Analytics Dataset
            ↓
Pareto / Parallel Coordinates / Curve Overlay
```

## 2. DOE 与优化候选生成

新增 `ExperimentDefinition`：

- `single`
- `full_factorial`
- `latin_hypercube`
- `random`
- `pareto_search`

每个 DOE 变量定义：

```yaml
parameter: air_gap
low: 0.8
high: 1.2
levels: 5
```

LHS 和随机采样使用 `samples` 与 `seed`，可以重复生成同一设计空间样本。Full Factorial 会在提交前限制最大 Case 数，避免组合爆炸。

Pareto Search 当前定义为“基于 LHS 的多目标候选搜索 + 任务结束后的非支配排序”。它不是自适应 NSGA-II；这样可以在真实 Motor-CAD 批量运行可靠性尚未完成 100+ Case 实机验收前避免引入闭环优化状态复杂度。

## 3. Pareto 与候选排序

任务可以定义多个目标：

```yaml
objectives:
  - result_id: shaft_torque_nm
    direction: max
  - result_id: magnet_loss_w
    direction: min
```

系统计算：

- dominance；
- Pareto rank；
- Pareto front；
- front 内 crowding distance；
- 标准化平行坐标数据。

任务结束自动生成：

```text
optimization_summary.json
```

该文件作为 Task 级 Artifact 归档。

## 4. Licence Pool

新增本地许可证资源调度器：

```text
EMAG
THERMAL
LAB
MECHANICAL
```

Case 在创建 Motor-CAD Worker 之前先申请分析所需模块容量。例如：

```text
emag_thermal → EMAG + THERMAL
lab_operating_point → LAB
```

容量由环境变量明确配置。该机制不声称能够查询许可证服务器的总 license count；它是平台侧的并发保护层。实际容量应根据单位购买的并发许可进行设置。

## 5. 阶段检查点恢复

新增 `checkpoint_manifest.json`，使用输入签名保护检查点：

```text
Template + Parameters + Scenario + Analysis + Materials + Solver Settings
                          ↓
                       SHA-256
```

输入改变时旧检查点自动失效。

对 `emag_thermal`：

```text
EMag完成
→ 保存 emag_completed.mot
→ 保存 checkpoint_emag_results.json
→ 写 checkpoint manifest
```

如果 Worker 或 Studio 重启，同一 Case 再次运行时检测到签名一致的 `EMAG` 检查点：

```text
启动 Motor-CAD
→ 加载电磁检查点 MOT
→ 恢复电磁标准结果
→ 跳过 do_magnetic_calculation()
→ 从稳态热分析继续
```

当前恢复粒度首先覆盖耗时价值最高且状态边界清晰的 EMag→Thermal 顺序分析。Lab、Mechanical、原生 coupled 的阶段恢复需要在真实 Motor-CAD 上验证软件状态可移植性后再扩展。

## 6. 多 Case 结果可视化

结果分析工作台新增：

- Pareto 前沿；
- 平行坐标；
- 多 Case 曲线叠加；
- 原有参数—结果散点/趋势；
- Pearson 快速敏感性；
- 质量状态筛选表。

多 Case 曲线通过 `/api/tasks/{task_id}/series-overlay` 从服务端读取标准化 series，不在浏览器中重新解析 Motor-CAD 原始文件。

## 7. API

新增：

```text
GET /api/system/resources
GET /api/tasks/{task_id}/optimization
GET /api/tasks/{task_id}/series-overlay?series_id=...
```

原 `/analytics` 数据集增加 `series_keys`。

## 8. GUI

“自动化任务”现在支持：

- 单次；
- 一维扫描；
- CSV；
- Full Factorial；
- Latin Hypercube；
- Random DOE；
- Pareto Search。

DOE 参数使用动态行编辑器定义参数、上下限与 levels；Pareto Search 使用动态目标编辑器定义结果指标与最小化/最大化方向。

系统驾驶舱同时显示 EMag/Thermal/Lab/Mechanical 的许可证容量、占用和等待状态。

## 9. V0.7 明确保留的边界

### 未宣称实现完整 Motor-CAD License Server 查询

PyMotorCAD 可以对当前实例执行 licence 检查，但 stable API 没有提供跨所有模块的通用“服务器总许可证数”查询。因此 V0.7 的 LicensePool 使用显式配置容量。

### 未实现真正 NSGA-II / Bayesian closed-loop

V0.7 已具备 closed-loop 所需的 Case、质量、资源、Pareto 和数据基础，但自适应优化会让任务变成“运行中继续生成新 Case”的动态 DAG。建议在完成真实 Motor-CAD 100 Case 稳定性验证后作为 V0.8 实现。

### Session Pool 仍使用 PyMotorCAD 官方复用机制

平台支持 `reuse_parallel_instances` / `set_free()`，但还没有自己维护 Motor-CAD port 到 PID 的长期持久 Session Pool。需要先验证多模板、多上下文连续复用是否存在状态残留。

## 10. V0.8 建议

1. 真实 Motor-CAD Session Pool；
2. 许可证等待队列与模块级公平调度；
3. NSGA-II / Bayesian Optimization 动态 Case 生成；
4. Stage checkpoint 扩展到 Lab / Thermal transient；
5. Lab 效率图、Torque-Speed Envelope 和 Loss Map 结构化解析；
6. 结果约束与可行域显示；
7. Maxwell 高保真候选自动触发。
