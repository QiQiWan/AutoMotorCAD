# V0.26 Persistent Motor-CAD Worker Pool + Validate-and-Run Execution Lease

## 1. 本轮目标

V0.25 已解决前端 Route 生命周期与重复 Task 提交，但仍存在一个运行时语义风险：提交前 Motor-CAD Qualification 属于独立进程/独立实例，而正式 Task 会再次加载模型。如果把提交前 PASS 理解成正式求解实例已经通过校验，会产生“检查通过，Task 仍失败”的认知落差。

V0.26 将正式 Case 的权威链路收敛为同一执行租约：

```text
Run Configuration
      ↓
Case input hash
      ↓
Persistent Python Worker
      ↓
Motor-CAD Session
      ↓
每 Case 重载 canonical MOT / registered template
      ↓
参数写入 + readback
      ↓
材料写入
      ↓
Geometry / Winding native validation
      ↓
Validation Evidence Hash
      ↓
不换 Worker / 不换 Session
      ↓
Full Solve
      ↓
FEA Evidence / Result Extraction
      ↓
set_free()
      ↓
Worker 继续服务下一 Case
```

提交前完整检查仍保留，用于快速阻断明显错误；正式 Task 中的 Validate-and-Run Lease 才是该 Case 的权威执行证据。

## 2. Persistent Worker Pool

新增 `motorcad_studio/runtime/persistent_solver_pool.py`。

每个 Worker 是长期存活的 Python 进程，一个 Worker 同时只执行一个 Case。Motor-CAD 只在该 Worker 第一次接到真实 Case 时按需启动。后续 Case 通过 PyMotorCAD 的 instance reuse/free 机制复用可释放实例。

### 2.1 Worker 状态

```text
未启动
  ↓ 首个真实 Case
READY
  ↓ acquire
BUSY
  ↓ Case success
READY
  ↓ 达到回收条件
RECYCLE → 新 generation
```

Worker 记录：

- `worker_id`
- PID / create time
- generation
- current Task / Case / lease
- jobs completed
- RSS（包含子进程）
- restart count
- last error
- last recycle reason
- pending recycle reason

### 2.2 硬回收边界

以下状态不会继续复用当前 Worker：

- Case cancellation；
- Solver timeout；
- Worker process unexpected exit；
- solver exception / RPC unknown state；
- 配置的 Case 数阈值；
- RSS 内存阈值；
- Motor-CAD 安装路径/版本变更；
- 操作员请求回收。

取消、超时、异常会终止整个 Worker process tree 并重建，避免继续使用内部状态未知的 Motor-CAD。

### 2.3 每 Case canonical reset

持久进程不代表沿用上一 Case 的模型状态。每个 Case 都执行：

```text
clear_message_log
→ load canonical local MOT / registered template
→ capture runtime defaults
→ apply this Case explicit intent
→ parameter readback
→ material application
→ native model validation
```

`execution_lease.json` 中记录：

```json
{
  "model_reset_strategy": "reload_canonical_model_each_case"
}
```

因此 Worker 复用只复用进程/RPC实例生命周期，不复用上一 Case 的工程模型状态。

## 3. Validate-and-Run Execution Lease

每个真实 Case 新增：

`execution_lease.json`

关键字段包括：

- lease id；
- Task / Case；
- persistent worker id + generation；
- Python worker PID；
- Motor-CAD session id；
- Run Configuration ID / hash；
- Case input hash；
- model source；
- model reset strategy；
- validation evidence hash；
- validated / solve started / solve finished timestamps；
- `same_session_validation_and_solve`；
- session release state。

状态链：

```text
ALLOCATING
→ MODEL_LOADED
→ MODEL_VALIDATED
→ VALIDATED_FOR_RUN
→ SOLVING
→ COMPLETED / FAILED
```

## 4. Validation Evidence Hash

V0.26 的 Validation Evidence Hash 不只绑定 Run Configuration，还绑定实际运行证据：

```text
Template ID / version
Run Configuration hash
Case input hash
actual model_load
runtime defaults
model_validation
parameter readback audit
material audit
analysis recipe
```

这可以区分“工程输入相同，但实际加载的本机 registered template / runtime defaults 已变化”的情况。

`.env.example` 增加/更新：


```text

```

隔离模式继续保留，用于确认持久实例复用是否参与某个异常。

## 9. 与提交前 Gate 的职责边界

### 提交前 Gate

用途：

- 快速发现确定性几何/绕组问题；
- 检查 Motor-CAD / RPC 可用性；
- 防止明显无效任务进入队列。

它运行在独立 Qualification process，因此 UI 改称“提交前检查”。

### 正式 Validate-and-Run Lease

用途：

- 对正式 Task 的实际输入重新写入；
- readback；
- native validation；
- 在完全相同的 Worker / Motor-CAD Session 中直接进入 Full Solve；
- 形成权威证据哈希。

因此 Case 成功/失败判断以后应优先依据执行租约，而不是依据提交前 Gate。

## 11. 实机验收边界

当前非 Windows 环境无法代替目标 Motor-CAD 2026R1 工作站验证以下项目：

1. `reuse_parallel_instances=True + set_free()` 在连续 100 / 500 Case 下的长期稳定性；
2. 每 Case 重载 MOT 后 Motor-CAD 内部隐藏状态是否完全恢复；
3. Worker process tree 回收后是否存在特殊情况下的独立 Motor-CAD 残留进程；
4. 多 license / 多 Worker 并行；
5. Motor-CAD GUI visible 模式与无界面模式的差异。

这些应作为 V0.27 Windows Runtime Contract Test 的核心验收项。
