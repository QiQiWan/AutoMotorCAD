# MotorCAD Studio V0.64.0：Design Renderer Modularization 深度迭代报告

## 1. 本轮目标

V0.63 已经建立统一 Design Store、Navigation 和 Draft 深链接，但读模式 Design Viewer 的几何、绕组、材料、验证、参数 Inspector 仍集中在历史 `v031.js`，Draft 编辑器的显示逻辑仍大量集中于 `v024.js`。这会造成三个持续风险：历史版本脚本仍拥有新页面 DOM；路由、异步请求和页面重绘之间容易形成隐性竞争；响应式布局继续依赖浏览器 viewport，无法准确反映项目树和 Inspector 占用后的真实工作区宽度。

V0.64 将这一层从“逻辑收敛”推进到“物理模块迁移”。本轮不新增 Motor-CAD 求解能力，重点降低前端回归面并为后续真实几何/材料/结果扩展建立稳定所有权。

## 2. Design Renderer 物理拆分

新增并正式加载以下模块：

- `design/render-utils.js`：安全转义、数值格式、几何极坐标/环段、视图上下文等纯渲染工具。
- `design/geometry.js`：径向截面、径向磁通纵向装配剖面、轴向磁通盘式堆叠剖面。
- `design/winding.js`：绕组连接、槽/相排布、槽内布置视图。
- `design/materials.js`：Design Revision 部件材料绑定视图。
- `design/validation.js`：Motor-CAD 模型检查/计算依据与 Revision 比较。
- `design/parameter-inspector.js`：读模式参数 Inspector、Draft 分组/参数列表/关联参数卡片。
- `design/renderer.js`：统一 renderer facade。
- `design/viewer.js`：只读 Design Viewer 的状态、生命周期、路由和异步取消。

与原 `store.js`、`navigation.js`、`workbench.js` 合计形成 11 个稳定 Design 模块。`v031.js` 从 412 行收敛至约 110 行，只保留工程四阶段状态条以及 FEA/热结果增强。径向/轴向/绕组/材料/Design Viewer controller 已从该文件物理移除。

## 3. Design Viewer 异步状态竞争修复

新的 Viewer 使用独立 `AbortController`。每次切换 Design/Revision 或重新加载 Viewer 时会取消上一笔 workbench 请求，同时保留 request token 与 revision identity 双重检查：

1. 发起请求前记录当前 Revision ID 与 token；
2. 新请求发起时主动 abort 旧请求；
3. 返回后检查 abort 状态；
4. 检查 request token；
5. 再检查当前 `state.workspaceRevision.id`；
6. 路由调用场景继续验证 PageRuntime route context。

因此旧 Revision 的晚返回结果不能覆盖新 Revision。

视图优先级固定为：显式请求视图 → Router/Store 当前视图 → 同一 Design/Revision 已保持视图 → 模板 preferred view。模板默认值已经降为最后兜底，避免刷新或异步恢复后重新跳回径向截面。

`mcs:route-ready` 也不再无条件重新 fetch Design workbench。只有当前 Viewer 尚未装载或 Revision identity 发生变化时才再次装饰，降低一次路由进入 Design 时的重复读取。

## 4. 结果跳转取消 timeout 驱动

旧逻辑从 Design Validation 点击“查看工程结果”后：切换 tab → 等待 500 ms → 尝试修改 Case `<select>` → 模拟按钮点击。页面加载速度变化时容易失败。

V0.64 优先直接导航到：

`/app/projects/<project>/results/tasks/<task>/cases/<case>`

由 Router 和 Result Route Controller 完成 Task/Case hydration。只有 Router 不可用时才使用兼容分支，并显式 `await loadViewerCases(..., {autoOpen:false})` 后再打开指定 Case。`design/viewer.js` 中没有 `setTimeout`。

## 5. Draft autosave 串行化

V0.62 的 Draft 已后端持久化，但连续输入可能同时触发多次 PUT。网络延迟反转时，旧 payload 可能晚于新 payload 到达/完成；直接删除 Draft 也可能与正在进行的 PUT 竞争。

V0.64 增加：

- `draftSavePromise`
- `draftPending`
- `draftPayloadVersion`
- `draftPersistedVersion`
- `draftSession`
- immutable payload clone
- 单一 `drainDraftQueue()`

每次 autosave 只保留队列中最新快照，一次只允许一个写请求执行。显式“放弃草稿”和“替换旧草稿”也进入同一队列。这样 DELETE 一定排在已经开始的 PUT 之后，不会出现“用户已经删除，旧 PUT 随后把 Draft 又写回来”的竞态。

Session/version 还用于防止前一个编辑会话的请求完成后修改当前 UI 的 `draftSavedAt`、Draft 对象或 persisted version。

## 6. Draft Editor 显示所有权继续下沉

`v024.js` 已移除本地 `geometryHtml()`、`windingHtml()` 等重复 renderer。Draft 中央模型由 `MCSDesignRenderer` 生成，参数分组、区域、参数行和选中参数信息由 `MCSDesignParameterInspector` 生成。

`v024.js` 当前保留的职责已经更清晰：

- Draft 生命周期和后端持久化；
- 编辑事件；
- 本地 dirty tracking；
- Studio precheck / Motor-CAD native check；
- Revision commit；
- 草稿冲突处理。

这为 V0.65 将 Draft controller 本身迁出历史脚本提供了直接边界。

## 7. 组件宽度响应式布局

项目页面真实可用宽度会受到项目树、右侧 Inspector、系统缩放和浏览器窗口共同影响，因此只使用 `@media(max-width:...)` 无法稳定判断 Design 组件是否应该换行。

V0.64 引入两个命名容器：

- `design-workspace`：`#workspaceCanvas`
- `design-viewer`：`.design-viewer-v031`

Read-only Viewer：

- 宽于 980 px：模型 + 280–360 px 参数 Inspector 两栏；
- 小于等于 980 px：Inspector 下移；
- 小于等于 680 px：标题/参数列表/下一步卡片进一步单列化。

Draft Workbench：

- 大于 1320 px：参数树 + 中央模型 + 参数编辑器三栏；
- 861–1320 px：参数树 + 模型两栏，参数编辑器下移；
- 小于等于 860 px：单列。

绕组/材料表设置局部 `overflow:auto` 与 620 px 表格内部最小宽度，宽度不足时只滚动表格，不再扩张根页面。

## 8. 路由和兼容层所有权

Router、V0.46 context navigation 与 Design Workbench 均优先读取 `MCSDesignViewer.state`。`MCSVisualV031` 仍保留为兼容 fallback，避免历史脚本和既有测试在当前阶段一次性断裂。

Router 的 `apply()` 优先调用 `MCSDesignViewer.applyRouteView()`；只有新 Viewer 不存在时才调用旧兼容接口，避免同一路由被两个 controller 重复处理。

- Batch 2：117 passed

同时验证：

6. 真实 Case 从 Design Validation 深链到指定 Result Case。

## 11. V0.65 建议边界

下一轮不建议继续新增 `v065.js` 覆盖现有 DOM。建议直接推进：

1. 将 Draft controller 从 `v024.js` 迁移为 `design/editor.js`、`design/draft-service.js`、`design/precheck.js`；
2. 对 23 个仍加载的历史 `v0xx.js` 建立依赖/ownership 图，删除已经完全被稳定模块接管的脚本；
3. 将 Design 主要 DOM 更新从大块 `innerHTML` 向局部 keyed patch/组件 render 收敛；
4. 降低 `window` 全局 API 数量，统一通过 `MCSDesign*` namespace 暴露兼容入口；
5. 加入完整浏览器路由级 visual regression 与交互回归；
6. 在 Windows Motor-CAD 工作站完成真实几何/材料/Result 深链验收后，再进入求解与结果工作台的同类模块迁移。
