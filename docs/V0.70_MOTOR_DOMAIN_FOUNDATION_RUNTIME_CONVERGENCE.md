# MotorCAD Studio V0.70.0 — Motor Domain Foundation + Runtime Convergence

## 1. 版本定位

V0.70 是 V0.69 结果/优化闭环之后的领域架构收敛版本。本版本不继续增加求解算法或优化策略，核心目标有两个：

1. 建立统一、求解器无关的电机领域对象，逐步结束 Geometry、Winding、Material、Motor-CAD Adapter、Results、Optimization 各自解释同一组裸 `dict` 参数的状态。
2. 继续物理迁移历史前端运行层，关闭 Single Case Result Viewer 的 legacy renderer fallback，并将活动 `v0xx.js` 降到 10 以下。

V0.70 采用渐进迁移。V0.69 的数据库字段、HTTP payload 和 dict 调用仍保持兼容，新的 Motor Domain 通过 Legacy Adapter 与旧边界双向转换。因此本版本没有进行 Big Bang rewrite。

## 2. V0.70 最终架构边界

```text
Project
  │
  └─ Design
       │
       └─ immutable Design Revision
              │
              ├─ legacy parameters/materials       [compatibility]
              │
              └─ MotorSnapshot v2                  [new authority contract]
                    │
                    ├─ MotorIdentity
                    │    ├─ native_motor_type
                    │    ├─ family_id
                    │    ├─ topology_id
                    │    └─ template_id
                    │
                    ├─ ParameterSet
                    │    ├─ values
                    │    ├─ unknown_values
                    │    └─ explicit_ids
                    │
                    ├─ MotorAssemblySnapshot
                    ├─ WindingModel
                    ├─ MaterialAssignmentSet
                    ├─ MotorCapabilitySet
                    └─ source/compatibility evidence
                              │
                              ↓
                         MotorModel
                              │
                   immutable parameter patch
                              │
                              ↓
                       MotorChangeSet
                    ├─ affected owners
                    ├─ affected views
                    ├─ invalidated analyses
                    └─ native readback requirement
```

`MotorModel` 是纯领域对象：不持有数据库连接，不启动 Motor-CAD，不依赖 FastAPI，也不依赖浏览器。后续 V0.71 的可视化 Provider、V0.72 的 Motor-CAD Native Binding、V0.73 的 Analysis/Result 对象会消费这个稳定边界。

## 3. 电机身份体系重构

V0.69 及更早版本中，`motor_family`、`motor_type_id`、template family 在不同代码路径中存在语义复用。V0.70 新增 `config/motor_topologies.yaml`，将四种身份分开：

| 层级 | 示例 | 语义 |
|---|---|---|
| `native_motor_type` | `BPM`, `BPMOR`, `IM` | Motor-CAD 原生模型类别 |
| `family_id` | `rfpm`, `afpm`, `induction` | Studio 物理电机族 |
| `topology_id` | `rfpm_spm`, `rfpm_ipm`, `outer_rotor_pm` | 具体电机拓扑 |
| `template_id` | `e9_eMobility_IPM` | 模板/预设/初始实例来源 |

已登记 topology：RFPM-SPM、RFPM-IPM、RFPM-Spoke、AFPM、Outer-Rotor PM、三相/单相感应、绕线同步、同步磁阻、SRM、PMDC、Claw thermal、Coreless cup。

模板继续作为 preset，不作为类层级。这样未来同一个 `rfpm_ipm` 可以具有多个 Motor-CAD 模板、用户模板或 `.mot` 来源，不需要生成模板专属 Python 类。

## 4. Motor Domain 包

新增目录：

```text
motorcad_studio/motor_domain/
  __init__.py
  identity.py
  parameters.py
  components.py
  winding.py
  materials.py
  capabilities.py
  snapshot.py
  model.py
  registry.py
```

### 4.1 `MotorIdentity`

持有 native type / family / topology / template origin，阻止模板 ID 继续承担领域类型职责。

### 4.2 `ParameterDescriptor`

把参数的工程语义集中到单一描述符：

- owner：motor / stator / rotor / magnets / shaft / housing / winding / cooling hardware / scenario / advanced；
- 类型、单位、范围、默认值和 UI level；
- Motor-CAD candidate automation names、context、solver unit 和 conversion；
- 是否属于 topology parameter；
- 是否可作为 Design optimization variable；
- `affects`：参数变化会使哪些 Geometry/Winding view、Validation 和 Analysis domain 失效。

当前 descriptor 由原 `parameter_registry.yaml` 的 35 个 canonical 参数生成。V0.70 没有复制第二份参数表。

### 4.3 `MotorSnapshot`

Snapshot schema version = **2**。Snapshot 是 Design Revision 的不可变领域投影，包含：

- identity；
- canonical parameter values；
- 未识别/native-extension parameters；
- component assembly；
- winding；
- material assignments/provenance；
- capabilities；
- source snapshot；
- compatibility evidence。

内容采用稳定 JSON 排序计算 SHA-256，因此一个 Design Revision 可以稳定引用对应的领域快照。

### 4.4 `MotorModel`

`MotorModel` 提供纯领域操作：

- `parameter()`；
- `parameter_values()`；
- `component_parameters()`；
- `with_parameter_patch()`；
- `optimization_space()`。

`with_parameter_patch()` 不修改原 snapshot，返回新 `MotorModel + MotorChangeSet`。例如 `air_gap` 或 `magnet_thickness` 变化后，会明确返回 `geometry.radial / geometry.longitudinal` 失效，以及 `analysis.emag / analysis.thermal` 需要重新建立证据。

`optimization_space()` 只返回 Design-owned 且可优化参数；Scenario-owned 转速、电流、环境/冷却工况不会进入 Design optimization space。

## 5. Legacy Adapter 与渐进迁移

V0.70 保留 V0.69 现有接口：

```text
parameters: dict
materials: dict
explicit_parameter_ids: list
```

`MotorDomainRegistry.build_snapshot()` 将旧结构转为 `MotorSnapshot`；`to_legacy()` 将 Snapshot 无损回写到旧结构。

兼容策略重点：

1. 未登记参数进入 `unknown_values`，不会在对象化过程中丢失 Motor-CAD 扩展字段。
2. 原始材料 raw payload 与 `material_provenance` 保留。
3. `component_materials` 可以转换为 `MaterialReference` 后再无损返回旧 payload。
4. V0.69 现有 Task、Analysis、Optimization 暂时继续消费旧 dict；后续版本逐模块切换到 Snapshot。

因此 V0.70 可以作为之后多个版本的迁移底座，同时维持现有工程流程稳定。

## 6. 数据库 Schema 23

`design_revisions` 与 `design_drafts` 新增：

```text
motor_snapshot_json
motor_snapshot_schema_version
motor_snapshot_hash
```

新建 Design Rev.1、新建 Revision、保存 Draft 时自动写入 typed snapshot。

对于旧数据库，新增：

```http
POST /api/projects/{project_id}/motor-domain/backfill
```

Backfill 特性：

- project-scoped；
- idempotent；
- 已经是 v2 且具有 hash 的 Revision 自动跳过；
- Draft 同步生成 snapshot；
- 不修改旧 `parameters_json/materials_json`；
- 不改变 Design Revision 编号和工程血缘。

读取旧 Revision 时，即使尚未执行持久 backfill，Workspace 也会产生只读的即时 MotorSnapshot，使 UI/API 能立即消费 typed contract；`persisted` 字段区分“已落库”和“即时派生”。

## 7. Motor Domain API

新增四个稳定接口：

### 7.1 Domain catalog

```http
GET /api/motor-domain/catalog
```

返回 topology registry 与 ParameterDescriptor catalog。

### 7.2 Project snapshot backfill

```http
POST /api/projects/{project_id}/motor-domain/backfill
```

用于历史工程迁移。

### 7.3 Immutable motor snapshot

```http
GET /api/design-revisions/{revision_id}/motor-snapshot
```

返回：

- typed MotorSnapshot；
- snapshot hash；
- persisted 状态；
- legacy parameters/materials compatibility payload。

### 7.4 Change impact

```http
POST /api/design-revisions/{revision_id}/motor-snapshot/change-impact
```

输入一组参数候选修改，不创建 Draft 或 Revision，只计算：

- before / after snapshot hash；
- 参数变化列表；
- affected owners；
- affected Geometry/Winding views；
- invalidated Analysis domains；
- 是否需要 Motor-CAD native readback。

该接口是 V0.71 实时 Visualization invalidation 和 V0.72 Native Binding update plan 的基础。

## 9. Single Case Result Viewer 收敛

V0.69 的 `results/workbench.js` 已拥有 Results 主路由，但 Single Case 仍回落到 `app.js` 的旧 Result Viewer owner。V0.70 完成该迁移：

```text
static/results/case-viewer.js
```

现在负责：

- Task / Case hydration；
- usable Case 自动选择；
- result module navigation；
- overview / performance / loss / inputs；
- waveform / spectrum；
- FEA/thermal/Lab/mechanical/artifact 结果；
- exact result route restoration。

`results/workbench.js` 直接 mount `MCSCaseViewerV070`。`routing/page-controllers.js` 不再调用 `loadResultViewerLanding/openCaseViewer`。`app.js` 只保留窄 compatibility delegate，供尚未迁移的 result decorator 调用。

因此 Results 路由现在具有一个稳定 Workbench owner，Single Case 不再拥有 legacy route fallback。

## 12. 与 V0.68 Native Parity 的关系

V0.70 没有修改 Native Qualification 的可信度边界。当前构建环境仍没有 Windows Motor-CAD 2026R1 + 有效许可证，因此：

```text
Studio V0.70 implementation scope      = completed
Motor-CAD workstation qualification    = pending
native qualification percentage        = 0%
```

Motor Domain 的 `NativeParameterBinding` 只保存语义映射元数据，不把 Linux 测试结果包装成 Motor-CAD native evidence。

V0.72 才会把现有 V0.68 qualification framework 升级为 `MotorSnapshot -> MotorCADBindingPlan -> Apply -> Readback -> NativeSnapshot` 的正式对象化绑定层。

## 13. V0.71 迁移入口

V0.71 应继续严格沿既定路线推进 **PM Motor Object Migration**，重点不再扩建 V0.70 的基础对象数量，而是让现有设计工作台开始真正消费 MotorSnapshot：

1. RFPM-SPM、RFPM-IPM、Outer-Rotor PM、AFPM 建立 topology-specific Geometry Provider；
2. `design/geometry.js` 从直接读取裸 parameters 切换为 Geometry Projection；
3. `design/winding.js` 使用同一个 WindingModel 同时驱动绕组 SVG、槽号和 coil table；
4. Material Assignment 使用 Component → MaterialReference；
5. Parameter Inspector 读取 ParameterDescriptor owner/unit/range/affects；
6. 删除 Design renderer 中主要的 template-ID / motor-type ad-hoc 判断；
7. 每种 topology 建立固定视觉基线和 snapshot-to-scene runtime contract。

V0.71 完成以后，前端应该逐渐形成：

```text
MotorSnapshot
  ├─ RFPM Geometry Projection
  ├─ AFPM Geometry Projection
  ├─ Winding Projection
  ├─ Slot Projection
  └─ Material Projection
        ↓
      renderer
```

而不是 SVG/DOM 自己判断电机对象语义。
