# V0.88-B — Native Geometry & Winding Readback Authority

Release: **MotorCAD Studio 0.88.2 / Schema 44**  

> Layer note: V0.88-B remains the active readback authority inside the current **0.89.3** architecture. Formal workstation qualification has advanced to **0.88-F**, which consumes `NativeModelSnapshot` drift/unresolved evidence as a typed validation fault tree and RepairPlan.

Target: **Motor-CAD 2026R1 / ansys-motorcad-core 0.8.8**  
Authority: **NativeGeometryWindingReadbackAuthorityV1**

## 1. Objective

V0.88-A freezes the exact Motor-CAD names that Studio is allowed to use. V0.88-B adds the next authority layer: after a design is applied to a live Motor-CAD model, Studio must read the actual geometry, topology, winding and material state back into one immutable, comparison-ready `NativeModelSnapshot`.

The production authority chain is now:

`Design Draft -> V0.88-A exact semantic names -> frozen BindingPlan -> live Motor-CAD model -> NativeModelSnapshot -> validation/result/qualification evidence`

This closes the gap where a Studio draft, preview and parameter write audit can all look internally consistent while Motor-CAD has regenerated a winding, adjusted a linked dimension, retained a different material, or exposes only partial native evidence.

## 2. NativeModelSnapshot contract

`NativeModelSnapshot` schema version is `1`. The enclosing legacy-compatible `MotorCADNativeSnapshot` schema is bumped to `3`.

A snapshot freezes:

- design/binding lineage: template/topology/native motor type, `design_snapshot_hash`, `binding_plan_hash`, semantic profile hash and model-source fingerprint;
- topology: pole count, slot count, phase count and parallel paths;
- geometry: canonical parameter readback, native variable name, units/conversion, delta/tolerance, geometry API validity, optional geometry-tree digest and region/material observations;
- winding: high-level winding variables, structured `get_winding_coil` topology, phase/path coverage, slot-index domain, turn consistency and winding signature;
- materials: fresh `get_component_material` observations for the exact components resolved by the binding plan;
- trust state: `QUALIFIED`, `DRIFT`, `PARTIAL` or `UNAVAILABLE`;
- actionable fault tree;
- lineage-bound `preview_projection` for downstream result/case visualization.

Each canonical readback value retains both the expected Design value and the live native value. Required semantics with no native candidate remain explicit unresolved rows; they are never dropped from the qualification contract.

## 3. Three-phase readback

V0.88-B captures the same authority at three lifecycle points.

| Phase | Purpose | Production meaning |
| --- | --- | --- |
| `post_binding` | confirm the frozen BindingPlan produced the intended native state | early diagnosis; can expose write/material/winding drift before validation |
| `post_native_validation` | re-read after Motor-CAD geometry/winding validation/regeneration | primary pre-solve model qualification |
| `post_solve` | re-read after the actual Motor-CAD calculation | final scenario evidence; proves the solved model still represents the qualified design |

Formal Windows scenario evidence uses the **post-solve** snapshot as the primary `NativeModelSnapshot`.

## 4. Geometry authority

The geometry readback contract is generated independently from the explicit edit list. Untouched template defaults that carry native engineering meaning are read back as well, so a model cannot qualify merely because the latest edited parameter round-tripped.

For every mapped topology/geometry/magnet semantic, the authority records:

- canonical semantic ID;
- exact/fallback Motor-CAD variable candidates resolved through V0.88-A;
- expected canonical value;
- raw Motor-CAD value;
- canonicalized Motor-CAD value;
- absolute/relative tolerance and delta;
- required/optional status;
- semantic-authority provenance.

`check_if_geometry_is_valid(0)` is treated as an explicit native gate. A returned boolean `False` is a blocking geometry failure even when no Python exception is raised. If the API is unavailable or produces no validity evidence, the snapshot is `PARTIAL` and formal qualification fails closed with `geometry:validity`; missing evidence cannot be promoted to a geometry pass.

When available, `get_geometry_tree()` is captured as supplementary structural evidence. Region names and `get_region(...).material` observations support diagnosis and future renderer convergence. Geometry-tree content does not replace canonical parameter readback.

## 5. Winding authority

Winding qualification combines scalar semantics with structured coil topology.

High-level readback includes phase count, parallel paths, layer count, turns per coil, slot fill factor and path convention where the template exposes them. Required high-level semantics are tracked as matched, mismatched or unresolved. Contradictory evidence is classified as `DRIFT`; unreadable/missing required winding evidence remains `PARTIAL`, so the fault tree does not mislabel an evidence gap as a model change.

When `get_winding_coil` is available, the snapshot captures each observed coil's phase, path, coil index, go/return slot, go/return position and turns. The authority then verifies:

- expected phase coverage;
- expected parallel-path coverage;
- slot-number domain and zero/one-based validity;
- uniform/expected turns;
- custom path convention where required;
- deterministic winding signature.

A model with no structured winding evidence cannot receive a V0.88-B `QUALIFIED` state when winding readback is required.

## 6. Fresh material readback

Material rows from the initial binding step are treated only as prior component-resolution evidence. Every `NativeModelSnapshot` phase re-reads live component assignments through `get_component_material`.

This prevents a stale post-binding material row from being copied into post-validation/post-solve evidence after Motor-CAD or an external action has changed a component assignment.

For a V0.88-A exact one-to-many component mapping, every qualified native component must still be readable and carry the requested material. Candidate-only diagnostic mappings accept at least one live resolved component but do not weaken the formal V0.88-A semantic gate.

## 7. Stable design-state fingerprint

`NativeModelSnapshot.content_hash()` hashes the full evidence object, including timestamp and phase. V0.88-B also adds `design_state_hash()`, which intentionally excludes timestamp/phase and hashes the stable native design state:

- identity and lineage;
- native topology values;
- canonical geometry/magnet readbacks;
- high-level winding values and structured winding signature;
- live material assignments.

After native validation, the design-state hash is frozen. After solve, Studio captures a new snapshot and compares the two hashes. A difference creates the blocking fault:

`NATIVE_POST_SOLVE_DESIGN_STATE_DRIFT`

and forces the final snapshot to `DRIFT`.

This distinguishes “new evidence captured later” from “the actual solved design state changed”.

## 8. Status model and fault tree

`QUALIFIED` means all required canonical readbacks resolve and match, geometry is valid, required structured winding evidence is complete, required materials match, and the post-solve state fingerprint remains stable.

`DRIFT` indicates at least one resolved required value/topology/material differs from the Design contract, geometry is invalid, or post-solve state changed.

`PARTIAL` indicates required native evidence is missing or unreadable. `UNAVAILABLE` is used when the native APIs provide no usable evidence.

Current blocking fault codes include:

- `NATIVE_GEOMETRY_INVALID`
- `NATIVE_GEOMETRY_VALIDATION_UNAVAILABLE`
- `NATIVE_GEOMETRY_READBACK_DRIFT`
- `NATIVE_GEOMETRY_READBACK_UNRESOLVED`
- `NATIVE_WINDING_PARAMETER_DRIFT`
- `NATIVE_WINDING_PARAMETER_UNRESOLVED`
- `NATIVE_WINDING_TOPOLOGY_DRIFT`
- `NATIVE_WINDING_READBACK_INCOMPLETE`
- `NATIVE_MATERIAL_READBACK_DRIFT`
- `NATIVE_MATERIAL_READBACK_UNRESOLVED`
- `NATIVE_POST_SOLVE_DESIGN_STATE_DRIFT`

Each row contains domain, severity, semantic ID where applicable, a concise Chinese engineering explanation, repair guidance and detailed readback evidence.

## 9. Preview projection and lineage rule

A qualified snapshot exposes `preview_projection` with native parameters, winding topology and material observations plus:

- `binding_plan_hash`;
- `design_snapshot_hash`;
- `model_source_fingerprint`;
- `design_state_hash`.

This projection is safe for result/case/native-closure views tied to the same Design lineage. The readback contract always computes a model-source fingerprint even when no cached V0.88-A profile exists, and `qualified_for_native_preview` requires both `QUALIFIED` readback status and complete Design/model-source lineage. The active Design editor must not silently consume an arbitrary “latest native snapshot”. A renderer may switch from Draft values to native projection only after it proves the snapshot belongs to the same Design snapshot/revision lineage.

This rule prevents a previous native run from contaminating the geometry preview of a newly edited draft.

## 10. Solver and Native Closure integration

Normal Motor-CAD execution now performs:

`apply BindingPlan -> post_binding snapshot -> native validation -> post_native_validation snapshot -> solve -> post_solve snapshot -> result extraction`

For `validation` and `production` model policies, any non-`QUALIFIED` required snapshot fails closed. Development mode may continue for diagnosis, but the output is explicitly unqualified.

Native Closure stores both post-validation and post-solve snapshot artifacts. The final post-solve object is promoted to the primary `native_model_snapshot` evidence, while the pre-solve object remains available for phase comparison.

The API exposes:

`GET /api/native-closure/runs/{run_id}/native-model-snapshot`

and returns final snapshot status, evidence hash, stable design-state hash, phase and full readback/fault-tree payload.

## 11. Windows production qualification contract

The formal Windows contract is **`0.88-B`**. Each representative SPM/IPM/AFPM/IM scenario must provide:

- `native_semantic_binding_qualified = true` and a semantic-profile hash;
- `native_model_readback_qualified = true`;
- a non-empty final `native_model_snapshot_hash`;
- a non-empty `native_model_design_state_hash`;
- `native_model_snapshot_phase = post_solve`;
- existing native binding, precheck, solve, result, restart, runtime, license and process-exit gates;
- immutable packaged scenario evidence whose fields match the imported qualification row.

The release gate `native_model_readback_authority` remains fail-closed when any representative scenario lacks final readback authority evidence.

## 12. Acceptance criteria

V0.88-B code closure requires:

1. exact-name readback contract generated from the current Design and V0.88-A profile;
2. required unmapped semantics preserved as unresolved rather than omitted;
3. geometry boolean failure and unavailable validity API handled fail-closed;
4. structured winding topology and high-level winding state verified together, with `PARTIAL` kept distinct from `DRIFT`;
5. material assignment freshly re-read at every phase;
6. post-validation and post-solve design-state hashes compared;
7. Native Closure primary evidence promoted to final post-solve snapshot;
8. API/HMI expose readback status, fault tree, evidence hash and state hash;
9. Windows 0.88-B qualification rejects missing/partial/stale readback evidence;
10. current source, browser and packaging regression gates pass.

## 13. Qualification boundary

The current build environment cannot launch the user's licensed Windows Motor-CAD 2026R1 workstation. Local tests can verify contracts, planner/executor behavior, simulated API readback, fail-closed policy, API/HMI wiring and release packaging. They cannot establish real SPM/IPM/AFPM/IM `QUALIFIED` native snapshots.

The production claim remains pending until the 0.88-B Windows matrix is executed against the target workstation and its immutable evidence package is imported successfully.

## 14. V0.88-C direction

The next iteration should converge the readback fault tree into **Validation Fault Tree & Native Repair Orchestration**. It should map every native fault to the exact editor section/parameter/component, distinguish safe automatic repair from engineer-required decisions, provide a “定位问题 -> 修复 -> 重新原生验证” loop, and keep all repair actions lineage-audited.
