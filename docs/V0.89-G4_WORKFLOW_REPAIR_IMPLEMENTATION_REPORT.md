# V0.89-G4 主流程稳定性与界面收敛修复报告

## 1. 结论

本轮没有继续在单个页面上叠加临时样式，而是把问题拆成五个可独立测试的模块：**界面壳层与密度、动态国际化、分析工作区数据入口、可观测后台作业、设计物理预检**。用户反馈的 10 类问题均已落到明确的代码所有者和回归测试中。

本地能够证明的是：Python/JavaScript 编译通过、G4 专项回归通过、标准验证重复物化保持幂等、分析工作区不再逐方案/逐历史版本请求、辐射关闭后相关值不进入求解投影、无效槽极/绕组关系会在启动 Motor-CAD 前阻断。正式的 Windows + licensed Motor-CAD 2026R1 实机 Golden Journey 仍需在目标工作站执行，本报告不以 Linux/Mock 测试替代该证据。

## 2. 模块边界

| 模块 | 单一职责 | 主要实现 |
| --- | --- | --- |
| UI Convergence | 主流程页头密度、空白、项目导航样式作用域 | `ui-convergence-g4.css`、`compact-flow-header.js`、`global-shell-convergence.js` |
| Dynamic i18n | 动态节点、异步状态、属性和语言切换的一致翻译 | `i18n.js`、`analysis/labels.js` |
| Analysis Workspace Gateway | 一次请求读取项目、方案/电机版本和轻量分析索引 | `/api/projects/{id}/analysis-workspace`、`SolutionRepository.list_for_project_with_revisions` |
| Observable Jobs | 后台执行、真实阶段、单飞合并、截止时间、晚到结果保护 | `observable_jobs.py`、标准验证/完整预检 jobs API、`operation-progress.js` |
| Engineering Guards | 物理输入启停依赖、槽极/相数/并联支路/绕组重建资格 | `engineering_precheck.py`、`winding_guard.py`、模板约束配置 |

模块之间只通过稳定合同协作：UI 不推测数据库重复项，列表 API 不执行 Motor-CAD，后台作业注册表不包含领域逻辑，绕组守卫不启动原生求解器。

## 3. 十项问题的根因与修复

### 3.1 进度呈现仍有大量英文

根因不是缺少若干字符串，而是旧国际化逻辑只记录文本节点第一次出现的内容，且只监听新增节点。异步渲染器复用同一个节点、直接修改 `textContent` 时，旧源文本会覆盖新状态；`characterData` 变化也不会被翻译。进度组件自身又保存了创建时语言，切换语言后不会重绘。

修复后，文本和属性都保存 `{source, rendered}`：只有节点仍等于上次译文时才沿用旧源；应用真正写入新状态时，该状态成为新的翻译源。MutationObserver 同时监听 `childList` 和 `characterData`，活动进度卡在语言变化时重绘。完成、失败、超时、取消、运行中和秒数都有中英文标签。

### 3.2 页面顶部说明占用过高

根因是方案、电机、分析、监控、结果等页面各自复制了“眉题 + 标题 + 长说明 + 操作”的大卡片。说明属于低频帮助，却永久参与布局。

新增 `compact-flow-header.js` 统一识别主流程页头，将说明移动到“说明 / Help”折叠项中；桌面端作为浮层展开，不再把操作面板向下推，移动端回到正常文档流。标题、操作和当前状态仍保留在首屏。

### 3.3 中英文混搭

根因有三类：后端/配方枚举直接显示原始值（`Lab`、`emag_thermal`）、动态模板硬编码 `Analysis Rev.` / `Revision` / `False`、以及国际化观察器的旧源问题。

分析模块、配方、求解模式、布尔值和版本标签现由 `MCSAnalysisLabels` 统一输出；中文引导模式还会清理 `Rev.`、`Analysis`、`Design`、`Solver`、`Lab`、`True/False` 等残留界面词。技术品牌和不可翻译标识（如 Motor-CAD、SPM、记录 ID、单位）继续保持原值。语言按钮触发所有活动主流程模块重绘，不再依赖刷新页面。

### 3.4 辐射关闭后参数仍可编辑

根因是输入域只有字段列表，没有字段启用条件；求解投影也不区分“保存值”和“当前有效值”。

`radiation_temperature_c` 与 `emissivity` 新增 `enabled_when: radiation_enabled == true`。前端按依赖实时禁用并显示原因；后端保留用户已填写值，便于再次开启，但从 `physical_inputs`、场景投影和校验输入中移除。这样关闭辐射时，隐藏值既不会改变求解，也不会产生错误阻断。

### 3.5 设计验证页顶部导航样式损坏

根因是 G3.1 结果页专用四列壳层样式由脚本无条件给 `body` 添加 `studio-v089g3`，因此设计、分析和验证页也被结果页网格覆盖。

现在 `studio-v089g3` 仅在 `body.dataset.canonicalStage === 'results'` 时存在，并监听规范页面 enter/leave 生命周期。G4 通用样式使用独立 `studio-v089g4` 类，不再借用结果页作用域。

### 3.6 进度条永久卡住

根因是标准验证同步串行执行多个原生预检，HTTP 请求可能等待数分钟；前端进度只是动画，没有后台任务 ID、阶段状态、截止时间或解锁路径。分析工作区加载也可能让 `loadPromise` 永久占用。

标准验证现在 POST 后立即返回 202 作业快照，通过 GET 轮询真实的物化、Motor-CAD 检查和提交阶段。重复点击通过 single-flight key 合并到同一作业。完整预检有 4 分 30 秒界面截止时间，标准验证有 17 分钟截止时间，普通分析请求有 60 秒网络截止时间。超时会恢复按钮并清除锁；后台晚到结果不能把 `TIMED_OUT` 状态改回成功。

### 3.7 已保存分析配置加载慢且显示大量重复项

加载慢由两个 N+1 共同造成：前端先读项目，再为每个方案请求 `/api/solutions/{id}`；后端列分析定义时再为每条定义读取全部历史版本。项目越老，打开时间越长。

新 `/analysis-workspace` 入口一次返回项目、两次有界 SQL 查询得到的方案/电机版本，以及一次 latest-revision 查询得到的轻量分析索引。只有用户真正打开某条分析时才读取完整不可变历史。

重复项来自标准验证“检查后创建”不是原子过程，以及旧版本记录缺少新 `standard_validation_package` 元数据，导致复用检查识别不到。物化现受进程内重入锁保护，并以 `analysis_guidance.template_id` 兼容识别旧定义。列表层对同一电机版本、名称、模块、配方和内容哈希完全一致的旧重复记录只显示一条，同时保留 `duplicate_ids` 供审计，不删除历史数据。

### 3.8 深入分析与迭代方案

本轮把故障从截图症状还原到状态所有权：语言属于 i18n 状态机，页头属于 UI Convergence，加载属于 Workspace Gateway，长任务属于 Observable Jobs，工程可行性属于 Engineering Guards。后续修改应落到对应模块，而不是在页面模板中增加另一套条件分支。

### 3.9 操作模块出现奇怪空白

分析页在外层 `<main>` 中又嵌套了一个 `<main>`，全局 `main` 的宽度、边距和 50px 底部内边距因此被重复应用；分析编辑器另有 640/520px 固定最小高度。标准验证隐藏区也有遗留高度规则。

内层语义元素已改为 `<section>`，编辑器最小高度改由内容决定，空状态保留 220px 的可读高度，三栏布局顶部对齐。标准验证空/隐藏状态不参与布局，折叠摘要只显示一条紧凑状态带。

### 3.10 修改绕组、极数、槽数后 Motor-CAD 验算失败

根因有两个：界面字段“极数”容易被理解为极对数；旧本地检查只覆盖 `槽数 / 相数 / 并联支路` 是否为整数，没有校验总极数必须为偶数、槽极周期是否能按相数均分，也没有声明模板是否具备绕组重建资格。因此不兼容配置直到 Motor-CAD 生成绕组时才失败。

参数标签现明确为“极数（总极数）”，并提示 `总极数 = 2 × 极对数`。守卫按模板能力依次校验：

1. 槽数、总极数、并联支路和相数必须为正整数；
2. 已登记模板要求偶数总极数；
3. `槽数 / 相数 / 并联支路` 必须满足模板整数约束，并给出邻近可行槽数；
4. `Q / gcd(Q, 极对数)` 必须能按相数均分；
5. 槽数或极数偏离模板基线时，模板必须明确登记绕组重建能力，否则本地阻断。

通过本地守卫只表示确定性关系可行，正式求解前仍执行 Motor-CAD 原生几何和绕组诊断。

## 4. 状态与数据流

### 分析工作区加载

`route mount → analysis-workspace bootstrap → 选择轻量分析 → 按需读取该分析完整历史/输入 → 渲染`

任何请求超过截止时间都会退出本次 mount，显示可恢复错误卡；旧请求由 AbortSignal 终止或因路由 token 失效而不能覆盖新页面。

### 标准验证

`POST jobs → QUEUED → materialize → motorcad → submit → SUCCEEDED/FAILED/TIMED_OUT`

同一个项目、电机版本、包哈希和执行策略只允许一个活动作业。提交密钥不参与 single-flight 身份，避免用户双击制造两条相同后台链路；各分析任务仍使用派生的幂等提交键。

## 6. 后续迭代方案

### G4.1：目标工作站验收（优先级 P0）

- 用 12 槽/10 极基线、非法 13 槽、误填 5“极对”、合法新槽极组合各跑一次完整预检；
- 记录 Motor-CAD MessageLog、绕组图、geometry validity 和模型回读；
- 校准不同 SPM/IPM/AFPM 模板的 `supports_winding_regeneration`，只有实机证据通过后才放开。

### G4.2：历史重复数据治理（P1）

- 当前仅展示折叠，不删除历史；
- 增加只读重复审计页和显式合并工具；
- 数据库增加标准验证身份唯一索引前，先生成冲突报告并处理旧记录，避免迁移失败。

### G4.3：性能证据（P1）

- 以 1/20/100 个方案、1/20/100 条分析、每条 1/20/100 个历史版本建立基准；
- 记录 bootstrap SQL 数、响应字节、P50/P95 和首个可操作时间；
- 对输入目录和模板目录增加 ETag/版本缓存，但不可缓存活动分析详情。

### G4.4：国际化闭环（P2）

- 将所有 Operator/Engineering 动态模板迁移到 key-based locale catalog；
- CI 分别在中文和英文模式扫描纯英文主操作、纯中文主操作及混搭短语；
- 专家/开发者界面保留技术标识，但说明文案仍需完整随语言切换。

## 7. 验收边界

本轮可以作为合并门禁的条件是：G4 专项全部通过、标准验证连续物化两次第二次 `created_count == 0`、辐射关闭不进入 `physical_inputs`、非法槽极组合不调用 Motor-CAD、分析页只存在一个 `<main>`、结果页样式类不会出现在设计/分析阶段、任何进度等待都有终态和截止时间。

正式生产发布仍必须补齐 licensed Windows 工作站证据；特别是“本地绕组守卫通过”不能替代 Motor-CAD 原生绕组生成和求解成功。
