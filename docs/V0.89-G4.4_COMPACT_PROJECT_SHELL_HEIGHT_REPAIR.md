# V0.89-G4.4 Compact Project Shell Height Repair

## Root cause

Three generations of desktop shell rules competed for the same elements. An
older rule fixed the shell to one 52 px row, while G4.2 changed it back to a
two-column grid with visible overflow. The context breadcrumb, focus bar and
journey cue therefore had no authoritative rows and could either overlap the
stage labels or expand the shell unpredictably.

## Repair

- The default operator/engineering shell is now exactly two rows: a 54 px
  project/stage row and a 46 px focus row.
- The project identity and four stages have explicit grid ownership in row 1.
- Current status and next action have explicit ownership in row 2.
- The diagnostic breadcrumb and duplicate journey cue are hidden in the
  default experience. Expert and developer modes may still expose them.
- Stage text is clipped with an ellipsis inside its own cell instead of
  escaping beneath neighbouring layers.
- The compact rules also apply when a legacy session has no `data-user-mode`,
  preventing startup timing from selecting the wrong geometry.

## Acceptance

At desktop widths the shell is 100 px high, does not overflow, all four stages
remain readable, and page content starts at a stable vertical position.
