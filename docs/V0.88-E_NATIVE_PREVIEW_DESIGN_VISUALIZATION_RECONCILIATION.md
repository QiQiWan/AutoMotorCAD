# V0.88-E — Native Preview & Design Visualization Reconciliation

Release: **MotorCAD Studio 0.88.5 / Schema 45**  
Windows qualification contract: **0.88-E**

## 1. Scope

V0.88-E closes the remaining visualization ambiguity after V0.88-A through V0.88-D. The product already knew which Motor-CAD names were writable, what the loaded native model contained, why validation failed, and which editor transaction a native result belonged to. The remaining problem was that the engineer-facing geometry/winding/material figures could still look like an independent Studio sketch even after a native model had been verified.

V0.88-E introduces one visualization authority:

`NativePreviewReconciliationAuthorityV1`

Its job is to decide whether a Motor-CAD readback projection is allowed to describe the exact immutable Design Revision currently shown, then produce one Design ↔ Native reconciliation object consumed by geometry, longitudinal-section, winding, slot and material renderers.

## 2. Authority chain

The read-only visualization chain is:

`Design Revision -> motor_snapshot_hash`

`Native Case / saved editor reconciliation -> NativeModelSnapshot.preview_projection`

`design_snapshot_hash + lineage_complete gate`

`NativePreviewReconciliationAuthorityV1`

`Design Intent | Motor-CAD Native | Difference Compare`

A native projection is rejected when its `design_snapshot_hash` does not equal the Revision's immutable `motor_snapshot_hash`, or when V0.88-B marked its lineage incomplete. No "latest native run" fallback is allowed.

## 3. Source policy

Three explicit visualization sources are available:

- **设计意图** — current canonical Design Revision/Draft values;
- **Motor-CAD 原生** — canonical values read back from the lineage-compatible live Motor-CAD model;
- **差异对比** — side-by-side Design and Native render plus semantic differences.

For saved read-only Revisions, a `QUALIFIED` projection with `qualified_for_native_preview=true` becomes the default. A `DRIFT` or `PARTIAL` projection may still be inspected because it is useful diagnostic evidence, but it remains compare-only/defaults to Design. Stale/mismatched lineage disables Native and Compare completely.

Draft editing remains Design-first. Any new edit immediately switches the canvas back to Design Intent and V0.88-D marks older native evidence stale. A fresh transaction-bound native check can then supply a new projection for explicit Native/Compare inspection.

## 4. Geometry reconciliation

V0.88-E deliberately reuses the V0.88-B canonical readback instead of creating another geometry extractor. `native_effective_parameters` overlays Motor-CAD readback values on the exact Design parameter set, and the existing topology-specific MotorObject/renderer reconstructs the radial/axial/longitudinal engineering view from those values.

The V0.88-B preview projection is extended with bounded geometry evidence when available:

- native geometry validity;
- `get_geometry_tree()` support flag;
- geometry-tree digest;
- native region names;
- region material readbacks.

This evidence proves which live Motor-CAD geometry tree supplied the readback. The Studio SVG remains an engineering reconstruction. It is not represented as a pixel-identical Motor-CAD viewport, mesh or CAD-region export.

Unreturned canonical fields are retained as explicit Design fallback values. They are not guessed from screenshots or fabricated.

## 5. Winding reconciliation

The Native winding projection carries high-level phase/path/turn/layer/fill information plus the structured coil table and V0.88-B winding signature. The winding and slot views therefore use the same native source contract as geometry.

When Motor-CAD provides structured coils, the rendered winding topology uses those coils. The slot conductor legend continues to state that yellow circles are equivalent conductor cross-section markers unless actual native wire diameter/strands-in-hand evidence exists.

## 6. Material reconciliation

Native material visualization is populated from live component material readbacks. Material rows explicitly show `Native 回读` / `Motor-CAD NativeModelSnapshot` provenance and are read-only. Viewing native materials never updates the material database or changes Design assignments.

One logical Studio component may still map to multiple Motor-CAD native components; identical native materials collapse to one display value, while divergent values remain visible as a joined readback and therefore cannot be mistaken for one Design assignment.

## 7. Difference model

Differences are generated by canonical semantic ID. Each comparable row contains:

- semantic ID and engineering label;
- category/unit;
- Design value;
- Native value;
- numeric delta when meaningful;
- `MATCH / DELTA / NATIVE_ONLY` state.

The compare view filters the summary to the active geometry/winding view where possible. Material comparison uses component IDs. This avoids comparing unrelated raw Motor-CAD variable names in the UI.

## 8. Evidence reuse and persistence

V0.88-D reconciliation schema advances internally from 1 to 2 and stores only the bounded `native_preview_projection`, snapshot hash and phase. It does not persist a second full geometry model. The immutable post-solve Case remains preferred over an editor-native-check projection for the same Revision.

Priority is:

`post_solve Case > post_native_validation Case > current editor native check > post_binding Case`

Only lineage-compatible candidates participate.

## 9. Failure policy

Native visualization is fail-closed for:

- Design Snapshot hash mismatch;
- incomplete native lineage;
- a native Case not bound to the exact Revision;
- stale Draft evidence after a new edit.

`DRIFT/PARTIAL` is not hidden. It remains visible through an explicit Native/Compare selection so the engineer can see exactly how Motor-CAD differs while Design Intent stays the default authority.

## 10. Windows production contract

The Windows contract advances to **0.88-E** and adds the release gate:

`native_preview_visualization_reconciliation_authority`

The gate proves that the shipped frontend/backend use the fail-closed reconciliation contract. It does not duplicate the workstation scenario evidence already required by V0.88-B. Formal SPM/IPM/AFPM/IM scenarios still require a QUALIFIED post-solve NativeModelSnapshot, CLEAN V0.88-C RepairPlan, zero hidden repair attempts, and all runtime/result/restart evidence.

## 11. Acceptance criteria

V0.88-E is code-complete when:

1. exact Revision lineage is required before a native projection can render;
2. QUALIFIED native evidence can be the saved read-only default;
3. DRIFT/PARTIAL evidence is compare-only by default;
4. stale/mismatched evidence cannot render;
5. geometry, longitudinal section, winding, slot and materials consume one reconciliation object;
6. the UI exposes Design / Native / Compare explicitly;
7. Design↔Native parameter/material differences are visible;
8. editor changes automatically return visualization to Design Intent;
9. current Windows qualification fails closed when the V0.88-E release gate is absent;
10. local tests do not claim licensed Motor-CAD 2026R1 workstation qualification.

## 12. Next boundary

The next useful iteration should focus on **visual geometry fidelity and native-result spatial correlation**: where supported by Motor-CAD/PyMotorCAD, add region-boundary or exported native geometry/field overlays tied to the same region IDs and Design-state hash. That work should remain a separate authority from V0.88-E so a richer visualization cannot weaken the current lineage and provenance rules.
