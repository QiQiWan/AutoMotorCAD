# V0.5 深度迭代说明

## 1. 设计原则：API 与 Automation 参数分层

PyMotorCAD API 负责“动作”：启动实例、加载模型、切换上下文、执行计算、处理材料/热网络、读取图表和结果。

Automation Parameter Registry 负责“数据变量”：几何、绕组、工况、冷却、网格、Lab 设置、Mechanical 设置等随 Motor-CAD 版本/机型/上下文变化的变量。

```text
Canonical engineering schema
        │
        ├─ Versioned parameter mapping → 标准高频参数
        │
        └─ Automation registry → 目标版本长尾专家参数
                               │
                        PyMotorCAD set/get
```

平台不再把“PyMotorCAD API 文档很完整”等同于“所有 Motor-CAD Automation 参数都已硬编码”。

## 2. 安装识别和自动启动

`MotorCADInstallationManager` 支持：

- 环境变量显式 EXE；
- Windows Uninstall Registry；
- Motor-CAD 常见安装目录；
- 运行时人工选择并持久化；
- 根据 `2026R1` 等目标版本自动优选；
- `set_motorcad_exe()` 配置 PyMotorCAD 启动目标。

真实 Case 启动时会再次解析所选安装，因此用户不需要先手工启动 Motor-CAD。

## 3. API Capability Catalog

`config/pymotorcad_api_catalog.yaml` 按官方 stable 文档登记 13 个方法域。当前目录包含 193 个 `MotorCAD` 方法和 3 个 utility functions。`/api/system/api-capabilities` 不再只做静态展示，而是通过运行时反射审计当前安装的 `MotorCAD` 类，输出：文档登记且可用、登记但缺失、运行时新增但尚未分类的方法，用于识别 PyMotorCAD 升级后的 API 漂移。

## 4. Automation Registry

导入键：

```text
Motor-CAD version × Motor Type × Context
```

例如：

```text
2026R1 / BPM / EMag
2026R1 / BPM / Therm
2026R1 / BPM / Lab
```

存储：

```text
data/runtime/automation_registry/<version>/<machine_type>/<context>.json
```

每个条目保存：

- automation_name
- current_value
- value_type
- unit
- description
- category
- io
- raw row

任务中的 `automation_overrides` 不绕过校验：validation/production 模式下，如果已经有目标注册表，未登记变量可被阻断。

## 5. 动态 GUI

新建任务页分为两层：

### Canonical 参数

平台长期稳定的工程语义参数，包含单位转换、约束和版本映射。

### Motor-CAD 专家参数

从实际 Automation Registry 中按上下文加载，可搜索、选择、赋值。适合网格、特殊槽型、Lab、Mechanical、冷却细节等暂未标准化的参数。

这种设计避免把数千内部参数同时暴露给普通用户，同时保证专家仍能使用目标版本提供的完整 Automation 能力。


## 5.1 官方示例高频 Solver Controls

新增 `config/solver_controls.yaml`，将 stable 文档基础示例中已经明确给出名称和使用方式的高频求解参数单独治理：

- EMag：`CurrentDefinition`、`TorquePointsPerCycle`、`TorqueNumberCycles`、Torque/Back-EMF/Cogging/Torque-Speed/Demag/Inductance/Short-Circuit/Force 等 12 项；
- Therm：`Transient_Calculation_Type`、`Transient_Time_Period`；
- Lab：模型构建、最大电流/转速、工作点需求和磁/热耦合等 12 项；
- Mechanical：不根据名称猜测，优先通过目标版本 Automation Registry 导入。

这些控件默认不强行覆盖模板值，用户显式启用后才写入。所有写入仍按 EMag/Therm/Lab/Mechanical 上下文执行。

## 6. 材料层

V0.5 连接官方材料 API：

```text
select_material_database
set_component_material
get_component_material
set_fluid
```

任务可以配置材料数据库路径、组件材料映射和冷却介质映射，输出 `material_audit.json`。

## 7. 分析配方

### EMag
`show_magnetic_context → parameters → validation → do_magnetic_calculation → extract`

### Thermal steady/transient
`show_thermal_context → thermal parameters → do_steady_state_analysis / do_transient_analysis → extract`

### Native coupled
`do_magnetic_thermal_calculation`

### Mechanical
`show_mechanical_context → expert settings → do_mechanical_calculation`

### Lab
`set_motorlab_context → build_model_lab（需要时）→ calculate_magnetic_lab / calculate_operating_point_lab`

Lab 工作点登记输出包括 `LabOpPoint_ShaftTorque` 和 `LabOpPoint_Efficiency`。


## 7.1 结果提取与原生归档

V0.5 对 Graph API 做了批量优先改造：

```text
get_magnetic_graph / get_temperature_graph
        ↓ 不可用时
get_*_graph_point 逐点兼容回退
```

同时支持：

- `get_fea_graph("B Gap (on load)", 1, 0)`：气隙磁密；
- `get_magnetic_graph_harmonics("TorqueVW")`：转矩谐波；
- `get_heatflow_graph()`：热流曲线接口预留；
- `export_results()`：阶段结束后保存 Motor-CAD 原生 CSV。

当前注册的结构化结果为 19 项；即便尚未把某个 Motor-CAD 输出标准化为 canonical result，原生 CSV 仍可随 Case 归档。

## 8. 电机家族覆盖

原始 33 套模板资产被归入主要电机家族，当前已有 15 套 curated profile 用于系统化配置与验证：

- RFPM SPM
- RFPM IPM
- RFPM Spoke
- AFPM
- Outer Rotor PM
- IM
- IM1PH
- Wound Synchronous
- SynRel
- SRM

系统明确记录 PMDC 和 CLAW-Therm 当前缺少用户提供的模板；Coreless Cup 需要 Adaptive Geometry 或后续 Maxwell 高保真路径。

## 9. 零人工运行边界

完成一次 Motor-CAD Automation registration 后，正常任务可由 Studio 完成：

```text
安装识别/EXE选择
→ PyMotorCAD启动实例
→ GUI隐藏
→ 加载MOT/模板
→ 设置参数/材料/求解器设置
→ 上下文切换
→ 求解
→ 结果/日志/审计提取
→ 保存MOT
→ quit / set_free
```

不要求用户在每个 Case 中打开或操作 Motor-CAD GUI。

## 10. 尚未声称完成的内容

- 未实机确认所有 Automation Parameter Names 的实际导出格式；导入器提供多种表格/空白格式兼容，但仍需用目标版本样本验证。
- 未在本容器运行真实 EMag/Therm/Lab/Mechanical。
- 未提供 PMDC、CLAW-Therm、真正空心杯正式模板。
- 未将所有 Automation 参数提升为 Canonical 工程参数；长尾参数通过 Expert Registry 使用。
