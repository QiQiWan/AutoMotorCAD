# MotorCAD Studio V0.66.0 深度迭代报告

## Engineering Parity Closure & Roadmap Recovery

日期：2026-08-17

## 1. 本轮结论

V0.62～V0.65 的架构主线总体沿着此前确定的方向推进：状态所有权、深链接、Design Draft、Design Renderer、并发一致性和路由生命周期都在持续收敛。功能里程碑存在两处明显延期：原计划 V0.64 完成的材料体系没有在当时形成完整工程交互；原计划 V0.65 完成的“分析设置 → 计算 → 结果”流程收敛仍未达到预期。V0.65 把大量精力投入到 Draft 并发和历史 Design 层物理迁移，这些工作有必要，但造成用户可见的材料、设计验证、几何/绕组参数联动继续滞后。

本轮 V0.66 采用“路线纠偏 + 工程设计闭环”的定位：

1. 完成 V0.65 已明确安排给 V0.66 的历史 Runtime Layer Removal 第一阶段，物理移除 `v020.js`、`v025.js` 和 `v061.js`；
2. 补齐延期的材料库/材料赋值工程交互；
3. 修复 Design Viewer 迁移后暴露的 `decorateDesignViewer is not defined` 兼容边界；
4. 重做纵向装配剖面、绕组槽号/支路显示和槽内参数化预览；
5. 扩展高频几何参数面，并保留完整 Motor-CAD Automation Parameter Names 入口；
6. 将空的“设计验证”改成真正的设计就绪与原生证据入口；
7. 用组件宽度控制设计阶段导航，继续消除 1366/1440 等工程工作站宽度下的遮挡问题。

因此，V0.66 已重新回到既定路线。下一阶段不再继续扩展 Design 工作台，V0.67 应直接回到此前延期的 Analysis / Calculate Convergence。

## 3. 问题 1：`decorateDesignViewer is not defined`

### 根因

V0.64 / V0.65 将 Design Viewer 从历史脚本中迁出后，`decorateDesignViewer()` 已成为 `design/viewer.js` 的模块内函数。旧版本缓存、历史 wrapper 或加载顺序中的兼容调用仍可能按旧方式访问全局名称，从而在页面加载时抛出：

`decorateDesignViewer is not defined`

这属于模块物理迁移后的兼容边界缺失。

### 本轮修复

- `design/viewer.js` 继续保持 `MCSDesignViewer.decorate` 为正式实现入口；
- 增加临时兼容：`window.decorateDesignViewer = decorateDesignViewer`；
- 调整 `index.html` 加载顺序：稳定 `materials/library.js → design/editor.js → design/viewer.js → design/workbench.js` 在历史 compatibility layers 之前初始化；
- 当前代码中没有其他未限定的 `decorateDesignViewer()` 所有者；
- 物理移除 V0.20 老 Design editor 路径，避免旧控制器继续复活。

### 验证

新增 `scripts/verify_v066_shell_runtime.py`，按应用相同稳定模块顺序在 Chromium 中加载 Design boundary，检查：

- `window.decorateDesignViewer` 为 function；
- `MCSDesignViewer`、`MCSDesignEditor`、`MCSMaterialLibrary`、`MCSDesignRenderer`、`MCSDesignStore` 正常初始化；
- 无 page error；
- 无上下文直接调用 compatibility boundary 不抛异常。

## 4. 问题 2 / 3：纵向装配剖面准确性与参数联动

### 原图问题

此前剖面主要表达“上下对称装配关系”，没有严格沿轴中心线建立机械剖面语义。绕组、槽内有效导体、端部绕组、转子/定子叠长关系表达不充分，用户容易把示意理解成 Motor-CAD 原生装配截面。

### 新的剖面定义

径向磁通 BPM/SPM 采用沿转轴中心线的纵向剖面，显示：

- 机壳；
- 轴承；
- 转轴及轴孔；
- 上/下定子铁心；
- 定子槽窗口；
- 槽内有效导体侧；
- 黄色端部绕组回路；
- 上/下永磁体；
- 套筒 / banding（存在时）；
- 径向气隙；
- 上/下转子叠片；
- 定子/转子/磁体轴向长度关系。

AFPM 仍使用独立轴向 stack 视图，不与径向磁通纵剖面共用拓扑。

### 参数驱动

新图直接读取当前 Draft `values`，以下参数会即时影响 SVG 坐标或尺寸：

- `stator_lamination_length`
- `rotor_lamination_length`
- `magnet_length`
- `stator_outer_diameter`
- `stator_inner_diameter`
- `housing_diameter`
- `shaft_diameter`
- `shaft_hole_diameter`
- `air_gap`
- `magnet_thickness`
- `sleeve_thickness`
- `banding_thickness`
- `turns_per_coil`

Editor 的参数输入使用 `requestAnimationFrame()` 重绘当前视觉区域，因此无需等待保存 Revision，也不会依赖页面刷新。

### 权威边界

该图仍属于 Studio 的快速工程预览。其目标是正确表达拓扑、参数关系和变化方向；最终几何有效性及真实 Motor-CAD 绘制仍以目标 Motor-CAD 版本为权威。

## 5. 问题 4：绕组槽号、支路同步和槽内定义联动

### 槽号与表格对齐

绕组径向图现在按 `1...slot_count` 标注槽号，18 槽模型会显示 1～18。槽下方表格使用相同 slot ID，因此用户可以从图形直接对应到表格的：

- 槽号；
- 相；
- 电流方向；
- 并联支路。

槽数很大时采用降采样标签，避免全部文字互相覆盖。

### 并联支路同步

`parallel_paths` 已进入图形渲染输入。修改右侧 1 → 2 → 3 支路后，绕组图中的支路分组和 `P1 / P2 / P3` 会立即改变，下方表格“支路”列同步。

当后续 Motor-CAD native winding evidence 返回真实 coil table 且包含 path/branch 字段时，优先使用原生支路数据；当前未取得原生 coil table 时显示 Studio 参数化预览，并明确标注其权威等级。

### 槽内定义同步

槽内图现在读取：

- `slot_opening`
- `slot_width`
- `slot_depth`
- `slot_corner_radius`
- `tooth_width`
- `tooth_tip_depth`
- `tooth_tip_angle`
- `turns_per_coil`
- `slot_fill_factor`

槽口、槽腔、齿顶、圆角标识、槽深、导体点数量/占用都会随当前 Draft 值变化。

新增 Node runtime contract 直接比较两组参数生成的 SVG 字符串，验证气隙、定子叠长、转轴、并联支路、槽宽、槽深、槽满率和匝数均会改变输出。

## 6. 问题 5：为什么当前几何参数比 Motor-CAD 少，以及本轮策略

### 原因

Motor-CAD 参数规模远大于当前 Studio 的高频设计表面，原因包括：

1. 参数随 Motor Type 改变；
2. 参数随 Geometry / EMag / Thermal / Lab / Mechanical context 改变；
3. Slot Type、Rotor Type、Cooling、Mounting、Custom Geometry 等配置会激活不同字段；
4. Motor-CAD 版本升级会新增或调整 Automation Parameter Names；
5. 一部分参数属于 topology-specific 或 adaptive geometry，不适合作为所有模板的固定字段。

因此将 Motor-CAD 全部参数永久平铺到默认设计编辑器，会显著增加认知负担，也容易形成版本脆弱的参数映射。

### V0.66 的三级参数策略

#### Level A：结构化高频参数

用于默认 Design Workbench、即时几何/绕组预览和静态检查。

当前 canonical registry 已扩展到 35 个核心 ID。本轮新增/强化：

- `housing_diameter`
- `shaft_diameter`
- `shaft_hole_diameter`
- `rotor_lamination_length`
- `slot_width`
- `slot_corner_radius`
- `tooth_tip_depth`
- `tooth_tip_angle`
- `magnet_length`
- `sleeve_thickness`
- `banding_thickness`

以 `i5_Industrial_SPM_Servo_Tooth_Wound` 为例，workbench 当前得到 25 个结构化设计参数；radial view 19 个、axial view 10 个、slot view 9 个、winding 核心 5 个。

#### Level B：目标版本完整 Automation Parameter Names

Design Editor 左侧增加：

`高级：全部 Motor-CAD 参数`

入口使用已有 Parameter Catalog API。该目录组合 versioned registry 与导入的目标 Motor-CAD Automation Parameter Names，允许搜索、按 context 筛选和保存新 Revision。

#### Level C：Motor-CAD 原生模型

对 IPM、AFPM、复杂自适应槽形、Custom Geometry 等，最终以真实 Motor-CAD 模型、Geometry Check、Winding Pattern 和原生求解证据为准。

### 本轮判断

需要“能力对齐”，不建议默认 UI 做 1:1 字段平铺。默认工作台覆盖高频工程参数；高级目录覆盖全部自动化字段；原生模型负责拓扑相关的最终几何语义。这样更符合工程软件的层级设计。

## 7. 问题 6：材料库浏览、详情、曲线、应用和默认赋值

### 原 UI 问题

截图中存在四个独立问题：

1. 左侧材料条目很多但列表无法稳定滚动；
2. 中间详情区域只看到材料名称，核心物性与曲线不明显；
3. 原始字段很多时下部内容不可达；
4. 选择材料之后没有明确的“应用到当前部件”动作。

此外，材料管理和电机部件材料绑定被放在相近视觉层级，用户难以区分“维护数据库”和“修改当前 Design Revision”。

### 本轮结构

#### Material Library（系统级）

负责：

- 扫描本机 Motor-CAD 数据库；
- 导入 `.mdb`；
- 搜索/筛选；
- 查看关键属性；
- B-H 曲线；
- 磁体退磁曲线；
- 铁损点；
- 温度物性；
- Motor-CAD 原始字段；
- Studio 管理副本 CRUD；
- managed `.mdb` 导出。

桌面布局中材料列表和详情是两个独立滚动区。120 条模拟材料的 Playwright 测试确认左侧 `scrollHeight > clientHeight` 且 `overflow-y:auto`；右侧详情同样独立滚动，根 dialog 不产生额外纵向滚动。

选择材料后自动加载第一条详情，避免“左边有条目，中间空白”。

#### Material Assignment（Design 级）

负责：

- 定子铁心；
- 转子铁心；
- 永磁体；
- 绕组导体；
- 转轴；
- 机壳；
- 套筒；

等部件到具体材料记录的绑定。

编辑模式下操作链固定为：

`部件 → 选择其他材料 → 材料库检查属性/曲线 → 用于当前部件 → 返回 Design Draft`

Picker 顶部明确显示当前正在为哪个部件选择材料，详情右上角显示一级 CTA：`用于当前部件`。

### 模板默认材料

本轮从 `.mtt` 的 `[Material]` section 提取真实模板部件材料。以 i5 SPM 为例：

- Stator Lamination → `M350-50A`
- Rotor Lamination → `M350-50A`
- Magnet → `N30UH`
- Conductor → `Copper (Annealed)`
- Housing → `Aluminium (Alloy 195 Cast)`

模板没有填写的材料字段保持未赋值，不进行猜测。通过 `source_kind=mot_import` 创建的原生导入模型也不会强行套用其他模板材料。

新建 Design Rev.1 会把模板已有材料基线冻结到 Revision；旧 Revision 没有显式材料时，Workbench 显示模板 inherited material，并在用户生成新 Revision 时完成冻结。

这使普通使用场景下材料配置以“确认默认值”为主，用户只在需要时更换少数部件。

### 材料追溯

继续记录：

- material record ID；
- source database path；
- database SHA-256；
- material section SHA-256；
- Motor-CAD version；
- source kind。

这样能区分“整个数据库文件变化”和“具体材料 section 变化”。

## 8. 问题 7：几何 / 绕组 / 材料 / 验证导航遮挡

原布局在 Design Viewer 可用宽度减小时仍尝试把四个 stage + `版本比较` 放在同一横排，右侧 Parameter Inspector 进一步挤压可用宽度，导致 `设计验证` / `版本比较` 文本换行或被遮住。

V0.66 调整为：

- `design-stage-nav-v062`：主流程使用 `minmax(0,1fr)`；
- `版本比较` 作为独立 utility，不再参与四阶段等宽分配；
- Design Viewer container ≤ 1100 px 时 utility 自动换到下一行；
- 小宽度进一步切为两列阶段按钮；
- 所有按钮 `min-width:0`，长文本可以在自身边界内换行；
- 以 Design Viewer / Design Workspace 实际宽度触发，不依赖浏览器 viewport。

Playwright 验证 1200 px 时两列 stage/utility 布局、900 px 时自动换行，根 workspace 无横向溢出。

## 9. 问题 8：设计验证空白

### 新的 Design Validation

只读 Revision 页面始终展示四个 readiness card：

1. 几何参数：结构化参数载入数量；
2. 绕组定义：相数、匝数、并联支路；
3. 部件材料：已配置/模板继承数量；
4. Motor-CAD 原生证据：当前 Revision 是否已经取得 native validation / solve evidence。

同时展示：

- Studio precheck 阻断项；
- Studio warning；
- 当前静态检查 PASS；
- `进入设计验证`；
- `配置分析工况` 或最近结果入口；
- L0～L4 evidence ladder。

Draft 编辑模式中的 validation view 显示：

`Studio 设计检查 → Motor-CAD 原生模型检查`

两阶段操作，旧结果在参数再次变化后自动变成 stale，避免拿旧检查证据代表当前 Draft。

因此设计验证在“尚未计算”的情况下也有明确内容。求解后的 native evidence 会追加到同一页面。

## 10. 材料数据库与公开资料边界

V0.66 继续坚持本机 Motor-CAD 数据库为实际工程事实源。

Motor-CAD 标准 solids/fluids `.mdb` 使用可读文本格式；steel 可包含 B-H 与铁损点，magnet 可包含退磁曲线及温度参数。V0.66 的材料库按这些字段解析并展示曲线，同时保留未知原始 Key/Value，避免在 Studio parser 尚未认识某个新字段时丢失数据。

对于 Granta `.gdb` 等加密来源，应先通过 Motor-CAD 的 Material Import 进入可工作的材料数据库，再由 Studio 同步标准材料记录。

## 15. 当前版本判断

V0.66 后，Design 工作台的下一阶段重点已经不应继续增加新的几何或材料入口。当前 Design 侧已经具备：

`几何 → 绕组 → 材料 → 设计验证 → 分析设置`

的完整用户路径，同时具备 Draft、Revision、材料 provenance、参数高级目录和原生验证边界。

目前最明显的系统级短板转移到了“分析设置 → 计算 → 结果”这一段。继续在 Design 页面叠加功能会再次偏离原路线，因此 V0.67 应强制聚焦 Analysis / Calculate Convergence，等这一链真正跑顺后再进入 Windows 原生一致性验收。
