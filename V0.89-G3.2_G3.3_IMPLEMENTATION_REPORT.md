# V0.89-G3.2 + G3.3 Implementation Report

Date: 2026-08-30  
Base package: MotorCAD Studio 0.89.9 / V0.89-G3.1  
Iteration scope: ResultBundle coverage, Native FEA engineering viewer, analysis/precheck responsiveness, loading/progress convergence, analysis layout cleanup.

## 1. Root-cause findings

### 1.1 Large blank/dead area above Analysis Configuration

The dominant source was `standardValidationPackageV087D`. The Standard Validation package was rendered before the three-column Analysis editor and expanded every validation step inline. On projects with a populated validation plan this block consumed a large vertical region, while hidden/empty hosts could still retain layout influence through surrounding styles. The screenshot's isolated “刷新验证计划” control at the top is consistent with this ownership boundary.

Repair:
- Standard Validation now renders as a compact status strip with details collapsed by default.
- Empty/hidden validation and analysis-context hosts are forced out of layout.
- Validation steps remain available on demand without pushing the main editor below the fold.

### 1.2 “运行完整计算前检查” appeared to do nothing

The previous button called the synchronous `/calculation-check` endpoint. That request can enter `template_geometry_runtime_check(... timeout_s=180)` while Motor-CAD starts, loads the model, applies inputs and performs native checks. During that blocking interval there was no stage feedback. The submit button remained disabled because the contract requires both an executable plan and a valid current full-check result, so the UI looked stalled even when the backend was still working.

Repair:
- Added an immediately acknowledged asynchronous precheck job API (`HTTP 202`).
- The worker reports `queued -> capture -> studio -> motorcad -> identity -> evidence -> done`.
- The Motor-CAD stage is explicitly indeterminate while the native call is blocking.
- The browser polls the job and updates both an inline progress surface and the global progress dock.
- Submission stays fail-closed, but its reason is now visible: waiting for check, check blocked, stale revision, or ready.

### 1.3 Save/refresh/load actions lacked immediate feedback

Several operations awaited network/backend work without binding a busy state to the action. In addition, route/background loads such as project/design/analysis/summary retrieval had no shared latency indicator.

Repair:
- Added `MCSOperationProgress` with determinate/indeterminate progress cards, elapsed time, finish/fail states and button busy binding.
- Added explicit progress to high-impact Analysis, Standard Validation and Result Viewer operations.
- Added a shared API latency fallback for legacy controls and background loads. Fast background GETs avoid flicker; button-triggered refreshes and writes show feedback immediately.
- All enabled button clicks receive a short acknowledgement pulse, so the first interaction frame is visible even before a longer operation is detected.

## 2. V0.89-G3.2 — ResultBundle module authority

### 2.1 Explicit coverage of all canonical outputs

Added `motorcad_studio/result_domain/module_contract.py` as the authoritative mapping from each registered result ID to:
- physical domain;
- one or more Result Viewer modules;
- mandatory `output_data` exposure.

Coverage is checked against `config/output_registry.yaml`: 44/44 canonical outputs have explicit mappings.

### 2.2 Typed ResultBundle projection

`EngineeringResultBase` now carries `physical_domain` and `viewer_modules`. `ResultBundle.module_projection()` builds a deterministic module inventory containing result IDs, result types, extracted/missing/invalid counts and availability. Solver artifacts are also emitted as typed `ArtifactResult` rows while preserving the legacy artifact-name projection.

The Result Viewer consumes this projection first and uses legacy name heuristics only as a compatibility fallback. Heavy-data hydration also follows the declared viewer-module contract.

Result: the ResultBundle can drive overview, performance, FEA, thermal, mechanical, stress, graph/output-data and artifact surfaces from one typed contract instead of a small scalar subset.

## 3. V0.89-G3.3 — Native FEA full-mesh 2.5D viewer

### 3.1 Native mesh archive

The FEA normalizer now preserves the complete available native triangle set rather than limiting the viewer to sampled centroids. For every archived frame it writes:
- frame mesh manifest;
- bounded triangle chunks (maximum 1,800 elements per chunk);
- referenced native node coordinates;
- source/data bounds;
- region/field inventory;
- element/node counts and mesh-completeness state;
- immutable file size and SHA-256 evidence.

New verified endpoints expose per-frame mesh manifests and chunks with ETag/cache support.

### 3.2 Motor-CAD NodesTable parsing repair

A native export can contain a semantic header followed by a units row. The previous preamble selector could choose `[-],[mm],[mm]` as the node header because it was the last alphabetic-containing row, so node coordinates were never indexed and triangle connectivity appeared incomplete. The parser now prefers structural headers such as `NodeIndex/X/Y` (and equivalent region structures) before considering generic preamble rows.

This repair is required for `full_region_mesh=true` on normal Motor-CAD exports.

### 3.3 Engineering viewer

`static/results/field-viewer.js` was rebuilt around the native triangle contract. When full connectivity is available it provides:
- triangle-element filled contours using native element values;
- optional mesh edges, enabled by default;
- full archived model bounds;
- progressive chunk loading/rendering;
- up to 30 recorded native frames;
- play/pause and frame progress;
- automatic focus/fit;
- wheel zoom;
- drag pan;
- Shift-drag or right-drag rotation;
- tilt slider and rotate-left/right controls;
- reset/autofocus controls;
- nearest-element click probe;
- global or per-frame value range;
- four-frame browser LRU cache;
- bounded concurrent chunk loading.

Evidence boundary: this is a rotatable/tiltable 2.5D engineering plane based on native 2D FEA triangles. Missing connectivity is not fabricated and no synthetic volumetric geometry is generated. If full connectivity is unavailable the viewer falls back to the existing sampled evidence view and states that limitation.

## 4. Analysis calculation gate and responsiveness

The full-check frontend now preserves the current Design/Analysis revision identity throughout the job. The check result is invalidated when revisions change. The submit action remains disabled until:
1. the execution plan is current and submit-capable; and
2. the current full precheck is valid.

The difference is observability: the gate now displays the active stage, percentage/indeterminate state, status message and the reason submission remains unavailable.

Progress was added to:
- Analysis workspace initial load;
- project/design/revision graph hydration;
- Analysis input refresh;
- operating-case save;
- physical-input save;
- solver-setting save;
- execution-plan refresh;
- full precheck;
- calculation submission;
- Analysis template/catalog creation flow;
- Standard Validation refresh/execute;
- Case/ResultBundle open;
- aggregate result open;
- heavy result hydration;
- FEA mesh/frame load and playback;
- shared API-backed background loads/legacy buttons.
